## Storage and shutdown lifecycle

Server 0.18 contains the explicit Core storage lifecycle correction:

- transaction commit never closes physical storage;
- root checkpoint is durable and leaves storage open;
- `use` requires CLOSED and rejects before target validation;
- `close` rejects active transaction levels without implicit commit or rollback;
- ordinary Core `User` owns `use`, `checkpoint` and `close`.

3.5.2.13 closes the remaining interactive Console JVM shutdown adapter:

```text
active Console Mind
-> rollback unfinished child transaction levels
-> root Mind
-> ordinary closeStorage()
-> checkpoint + physical close
```

The obsolete `flush -> close(null)` path is removed. Permanent qualification proves rollback of uncommitted child state, durability of committed root state, clean reopen and idempotent shutdown of an already closed root.
