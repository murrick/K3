## Storage lifecycle

The integrated Core/Console contract includes:

- transaction commit never implicitly closes physical storage;
- root checkpoint is durable and leaves storage open;
- close rejects active transaction state;
- Console JVM shutdown retains the active `IMind`, rolls unfinished child levels back to root and delegates physical shutdown to ordinary `closeStorage()`;
- storage lifecycle quiescence requires visible transaction level zero and no pending root child reservations;
- opening a database under an ordinary L1+ transaction stack is rejected before storage acquisition or factory rebinding;
- offline L0 workspace insertion is supported as `DB L0 + workspace L1`;
- imported workspace is recompiled in the database context and remains provisional until explicit commit;
- rollback leaves the database unchanged;
- generalized multi-level transaction-stack rebase is deliberately out of scope.
