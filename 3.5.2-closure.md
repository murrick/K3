## Corrected storage lifecycle

Server 0.18 contains the integrated explicit-storage-lifecycle correction:

- transaction commit never closes physical storage;
- root checkpoint is durable and leaves storage open;
- `use` requires CLOSED and rejects before target validation;
- `close` rejects active transaction levels without implicit commit or rollback;
- ordinary Core `User` owns `use`, `checkpoint` and `close`;
- typed lifecycle failures are shared by Core, Console and Server.

The Server 0.17 soak failure remains historical evidence. Its exact causal chain
was not proven. The Server 0.17 JAR, operations package and damaged database are
frozen and must not be reused or modified.
