# Stage524: native replay and complete frozen receiving qualification

`ContextDependentRuntimeBarrierInspection` bridges a freshly checked runtime execution plan into the existing physical-source proof history. It appends a complete producing round and a complete empty receiving round, checks the new outputs against native replay, and audits native originals plus every actual final common/private occurrence under supplied receiving interpretations. RECEIVED_PENDING is a bounded explicit receiving result, not automatic saturation or ordinary default/query/write admission.

## Exact runtime occurrence manifest

Preparation always starts from the actual parent/child and complete independent/TRUST cuts. The caller supplies an execution request and receiving interpretations, not a frame, output receipt or prior round result. The bridge takes the internally fresh proposed history and verifies its complete original ticket inventory against the final frozen barrier.

Every COMMON runtime occurrence maps in ordinal order to its actual common ticket. Every VISIBLE occurrence maps to the historical ticket visible at the producing cut, including its own last-round products and earlier common products. Common/visible duplicates remain separate raw occurrence slots pointing to the same proof ticket. No Source alternative or support superset is minimized. Each slot is compared with both its receiving row and original proof row: producer, whole Sources, depth, retained literal, polarity, predicate and typed alpha-equivalent graph with bijective variable correlation and exact function Source/binder/ordered dependencies.

Runtime references become carried old tickets; original native unit references remain physical originals. Global earlier-output indices become the correct per-cut local indices, even when the execution plan interleaves cuts. No same-round sibling output is made common early. Native replay reconstructs the entire prefix independently; its original basis/scopes/common sets and audit digests must match, and every newly created row must match the executed output's exact head, ancestry and depth. Typed graph comparisons do not use hash/text equality or model guesses.

## Producing and receiving passes

All cuts produce from the same frozen previous barrier. Only outputs whose complete supporting Source set contains local-X ancestry export as common. Foreign-only results stay private to their originating cut; all physical TRUST members share that cut. The appended empty receiving pass lets every exact cut qualify the full new common pool plus its own private history. It does not perform automatic new tuple discovery or declare a fixed point.

Actual native refutations are checked before receiving model success, first in the producing result and then in the receiving result. ROUND_REFUTED contains whole native proof Sources, explicit translation to original parent/candidate/foreign Sources and the exact incoming Source subset. Incoming causality is recorded rather than assumed; a candidate-free proof does not automatically blame the incoming batch. Failed interpretations remain INCOMPLETE, never semantic refutations. Preparation's existing sourced BASE_REFUTED/CANDIDATE_REFUTED and recipe NO_MATCH outcomes stay separate.

Receiving function keys use parent-original Sources for preserved X declarations and exact actual Sources for incoming/foreign declarations. Only the internally fresh one-to-one append map rebinds them. Receiving models may choose different witness values than the input interpretations: both phases check their own original formulas and product graphs; neither choice becomes a fact or native Cvar assignment.

The receiving model auditor consumes the actual checked round result directly. A package-private constructor supports this exact history without fabricating a FIXED_POINT iteration receipt. It checks every cut's native originals and every actual raw common/visible final occurrence. Native/model preflight-original work and final-truth work remain separate. Bridge mapping/replay comparison and bounded Source/refutation/model-rebase metadata passes use the bridge allowance; native proof reconstruction has the existing per-operation policy bounds. These are not a process-wide CPU/heap guarantee.

Any late bound, missing/false model, inconsistent manifest or replay mismatch returns INCOMPLETE with no execution, round, epoch, ticket manifest or successful count prefix. Native sourced refusal keeps only refusal evidence. No ordinary factory row, witness value, revision or durable packet is written.

## Provider ownership

`prepareDependentRuntimeBarrier` constructs the complete physical cuts under the existing provider lock and parent/child/retained/topology guards. Only a successful post-check retains the receiving result under a distinct epoch. The input runtime's model/execution getters are cleared rather than representing that input stamp as the new receiving state. `dependentRuntimeBarrier(UUID)` requires the exact current receiving epoch, owning thread, lease and unchanged actual views.

Structural/model/execution-only reprepare invalidates the old receiving epoch. Legitimate refusal clears all prior retained state; wrong-thread preparation cannot clear the owner's result. Closing clears it. Detached results remain historical data. The receiving bundle contains checked proof history, not a newly projected runtime frame for further execution or a family saturation checkpoint.
