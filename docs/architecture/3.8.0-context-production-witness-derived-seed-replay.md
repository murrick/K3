# Stage2z: observed native steps from transported witness proof seeds

## Why the imported ledger must remain derived evidence

X's exists(p(w,1)) and A's p->q give q(w,1) with depth1 and sources {X,A}.
If its restored logical carrier were labelled as new primary X knowledge, a B
rule q->r would incorrectly obtain depth1 and omit A. The new runner requires
r at depth2 with {X,A,B}, then a C step at depth3 with {X,A,B,C}. It explicitly
refuses the reset/merged alternatives. No alleged primary source is attached to
the restored carrier.

## Owning fresh pass

ContextWitnessSeedReplay.open restores a sealed stage2y Packet into a fresh
private Mind, immediately opens an owning witness observation capture, and binds
each canonical source/binder Origin to that replay's checked native root. The
raw conjunction is not replayed through a sourced-primary capture entrypoint.
Only separately supplied new producer declarations receive primary producer
labels. The original immutable Item proof groups seed the verifier at their
carried depths, including depth>0.

Once native settlement begins, rule input is sealed. Successful settlement is
observed once; repeating verification with a different proof budget/depth bound
does not execute native inference again. A native/input failure marks the pass
unusable for later verification, so an interrupted observation cannot expose a
prefix through retry. Closing releases the owner-thread capture boundary.

Source-cut checks recover X's context/revision/view from all carried proof groups
and require consistency. Every group must use X. Newly supplied local-X producers
must match that cut; a foreign label cannot reuse X's context. The shared producer
scope additionally permits only one new foreign context/revision/view, checks
exact supplied source/native-rule bindings and the existing producer shape bound.
Historical foreign authorities in a carried X-dependent proof remain provenance;
they do not become raw sibling knowledge in the new pass.

## Shared proof closure, not a second inference engine

The existing ContextWitnessUnaryChainVerifier closure is extracted into a shared
internal entrypoint. Original primary seeding still uses depth0 and retains its
unary/shared-origin scopes. New replay seeds use the immutable transported proof
groups without changing depth or sources. Every seed belongs to the fresh replay
namespace. The same producer-instance, sign/fixed argument, common-root donor,
materialization occurrence, whole-source union, minimum-depth and budget checks
then apply to actual observed native applications.

A rule application has depth max(all donor groups, producer)+1. Two-premise joins
require one original witness; source alternatives remain separate. Physical
materialization still has no rule-depth cost. Every observed application must be
reconstructed, and work/depth failure publishes no verified route prefix.

ContextWitnessResultTransport.exportNext re-verifies the owning pass; it does not
accept a caller-supplied proof result. A successful result is repacked using the
sealed imported Origin binding table. Old seeds and their alternatives remain in
the packet; actual new products retain all historical and current authorities.
The new packet can be used by another fresh pass. Canonical origins are not
rewritten to local rule/term numbers or given false X ownership.

## Controls and limits

The 34-check runner covers a native two-premise application after q import, two
old producer alternatives carried through three fresh Minds, depth1->2->3, exact
source groups, no primary/source reset or alternative union, preserved original
packet seeds, depth/work stops, sealed input, sticky observation failure, current
foreign-cut separation, X context/revision/view/role refusals, foreign-origin
X-dependent products without resurrection of foreign facts, independent imported
roots in a common raw carrier, signed/fixed values, and refusal of an unproved
new existential input.

Only imported one-root witness literals and observed one/two-premise preserving
applications are reconstructed. Witness-free/mixed premises, new/generated
witnesses and other producer cases retain the existing refusal boundaries.
General source snapshot authentication remains a trusted-caller assumption.

A pass without the required observed productive application/materialization
returns INCOMPLETE, not SATURATED. This is not yet a coverage certificate, family
fixed point, native consistency/model check or authoring decision. Even a valid
proof packet must still pass collision/admission qualification before publication.
No ordinary producer rules or scalar seeds are silently transported as witness
primary knowledge. Runtime authoring-gate integration and question3 remain open.
