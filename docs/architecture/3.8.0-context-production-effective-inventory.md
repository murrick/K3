# Stage3h: provider-owned effective production inventories

## Native counterexamples to revision-only and text-only snapshots

In real DUMB2, applying `!private(4);` to an existing connection changes its
private effective knowledge while both X's published revision and the foreign
exact pin remain unchanged. The old lease is invalidated and a fresh inventory
contains the private assertion plus the same physical revision identity.
Repeating the assertion as a native no-op still changes initialization intent;
the ordered command vector belongs to the view fingerprint.

Advancing the external Context's HEAD is the converse control: its old immutable
pin remains valid, and the new assertion must not enter the acquired view.
Direct snapshot inspection confirms that neither private initialization nor
newer HEAD content changed the originally pinned revision.

Native witness storage also separates a whole primary existential conjunction
from generated materialized rows. The fixture has two primary declarations
(existential p&&flag and p->warm) plus generated p, flag and warm rows. Replaying
generated origin strings as independent primary assertions would lose source
and witness ownership. A complete inventory must retain this distinction.

## Detached inventory, deliberately not replay evidence

ContextProductionInventory.inspect walks the complete bounded effective Rule
factory without filtering by Horn shape, arity, stored-fact status or executable
origin text. All enumerated rows are retained, sorted by native ID, including
available tombstones. Each Row records native ID, generated/deleted/query flags,
raw origin (possibly absent), native formatted text and a digest of Rule.pack.
Visible non-generated rows and generated caches have separate immutable indexes;
generated rows remain in the overall inventory and row budget. An active query
row refuses acquisition. Exceeding the row bound produces no partial artifact.

The fingerprint includes exact context/revision/role metadata, length-prefixed
ordered initialization commands, every row's flags/origin/native text and native
packed-rule digest. It is a conservative diagnostic guard for this acquired
runtime view, not a durable canonical semantic identity, proof certificate or
portable serialization of the entire native object graph. There is no text-only
roundtrip assumption and no implicit reconstruction of referenced factories.

The DTO is immutable and contains no Mind, mutable native Rule/Term or storage
handle. Its public inspect helper requires provider-acquired metadata; it does
not authenticate arbitrary caller-supplied labels. The provider-owned lease is
the authority boundary. No executable Declaration list, witness Packet or
positive authoring verdict can be produced from the DTO through this API.

## Real provider acquisition and freshness lease

The qualification-only DUMB2 ContextProductionSnapshotSession acquires metadata
from the active owning DB under its monitor. X must be the active settled root,
without pending children. The session captures X's actual context/revision and
the complete direct working connection vector. Each foreign view is read from
that connection's existing exact-pinned initialized layer, not from a locator's
current HEAD. Dependency connections of foreign targets are not traversed.
TRUST members are explicitly refused rather than flattened into independent
sources. Repeated source context identities are refused.

The total1..10000 row limit covers X and all direct foreign inventories together.
Acquisition rechecks the captured state before releasing a lease. Every guarded
read verifies owner thread, active X, current root settlement, X revision, exact
working topology and all effective inventory fingerprints. Source publication,
connection edits/removal, or native inventory changes revoke the lease. A newer
external HEAD alone does not change a stable pin. All checks use bounded fresh
reads of the existing provider views.

close revokes lease authority but does not close borrowed provider Minds/layers
or publish knowledge/topology. Old detached DTOs may remain as historical audit
artifacts, never live permissions. Acquisition may lazily open an existing
connection runtime through the provider's standard accessor, with no persistent
context or initialization changes.

## Limits and next work

This supplies complete rule-row acquisition/freshness for physical X and direct
non-TRUST effective views. It does not yet translate native graph/primary witness
bundles into authenticated replay objects or bind those objects to the Stage3g
qualification Plan. That next step must validate source text against native
structure and preserve whole existential bundles, original rule IDs, generated
cache exclusions and scalar facts explicitly. Unsupported content must cause
INCOMPLETE rather than disappear from a claimed full plan.

The current rule-row fingerprint is not a claim that every referenced native
factory/value graph has been independently snapshotted for portable replay.
Leases are thread-confined operation-local guards, not cross-process locks or
remote publication capabilities. Main/Core, DB provider source and runtime
authoring gate are unchanged; the adapter lives in kanger-qualification.
Question3 remains open.

The34 new controls run against actual DUMB2 contexts and cover exact source/pin
identity, primary vs generated witness rows, aggregate budgets, read preservation,
owner thread, remote HEAD advancement, changed and no-op initialization, immutable
original pins/artifacts, closed leases, X publication, TRUST refusal and removal
of a direct source. No tests use or mutate the user's project contexts.
