# KANGER 3.5.0.3 — invariant audit and hardening

## Governing rule

`3.5.0.3` changes executable behavior only where an invariant violation is
proven and the correction can be isolated behind a directed regression gate.
It is not a general refactoring stage.

## Initial queue

```text
I1 IndexOne.compareTo long-ordering violation
I2 Index.firstKey empty-index contract mismatch
I3 Index iterator null-on-empty collection contract
```

### I2

Status: unresolved observable contract.

Current empty behavior throws before the apparent `-1` fallback. Caller and
compatibility evidence is required before choosing sentinel or exception.

### I3

Status: unresolved collection contract.

Current iterator factories can return `null` after construction failure. Empty
iteration behavior must be characterized before correction.

## Execution gate

No item advances from documented proof to a green production commit without:

1. a regression that fails under the historical implementation;
2. a minimal correction;
3. successful focused execution;
4. active baseline regression where available;
5. explicit confirmation that persistence format and unrelated semantics are
   unchanged.
