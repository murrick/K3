## Pair rationale

The pair establishes the boundary between a logical variable and the canonical values that may be associated with it.

```text
TVariableFactory
    logical-variable allocation and per-Mind overlay

TValueFactory
    canonical variable/value identities
    + active runtime bindings
    + transaction-layered acceleration index
    + mutation signal
    + nested rollback deltas
```

They are related but intentionally asymmetric. The documentation does not flatten them into two interchangeable sides of one map.

## Shared lifecycle review

Both introductions correctly establish:

- one concrete factory instance per exact `Mind` level;
- child initialization through `transaction(parentFactory)` and an `Escalera` overlay;
- child-created units remaining owned by the child until typed parent commit;
- parent `Mind` authority over acceptance, release, sequencing, and transaction reservation;
- root-only borrowed schema `IBase` attachment;
- child factories remaining memory overlays without storage close authority;
- typed `commit(childFactory)` remaining distinct from no-argument checkpoint `commit()`.

Neither introduction claims that a factory-local synchronized method makes the complete transaction protocol thread-safe.

## TVariableFactory review

### Identity and creation

The class contract correctly states that `createTVar(rule, name)` creates a new logical variable and records several different identifiers and relationships:

```text
schema ID
variable index
owning Rule
name Term
owning Mind ID
```

It does not invent canonical lookup or semantic deduplication by name or Rule. This is an important distinction from `TValueFactory.add/find`.

The Javadoc also prevents a false identity equivalence: variable index is not described as the persistent schema ID.

### Transaction and persistence

The class is accurately described as a comparatively direct per-Mind `Escalera` overlay. Typed commit promotes and rebinds child-created variables. No-argument mark/commit/release delegate to the cache because this class currently owns no separate auxiliary checkpoint journal.

Root-only storage hydration/update and child lack of connection ownership are explicit.

### Cross-factory cleanup

The class contract records the non-local cleanup obligation in `pack()`:

```text
physically remove logically deleted TVariable
    -> remove the same TVariable key from TValueFactory.current
```

This statement is bounded correctly. `pack()` is not presented as general reachability analysis, and the documentation does not imply that canonical TValue storage and the transient current-binding map are the same structure.

## TValueFactory review

### Independent state dimensions

The introduction correctly separates:

```text
Escalera cache
    canonical TValue identities and transaction visibility

current
    transient active TVariable -> TValue binding projection

parentIndex / localByVariable
    layered acceleration metadata storing TValue IDs

action
    mutation/effect signal

additionsStack / actionStack
    nested checkpoint rollback journal
```

This preserves the lifecycle audit conclusion that `top` and `current` belong to different axes and must not be described as symmetrical current/root state.

### Canonical identity and resurrection

The documented canonical key is the semantic pair:

```text
(TVariable identity, ITerm value identity)
```

The Javadoc accurately explains the deliberate transition:

```text
canonical TValue exists
    -> logically deleted in transaction state
    -> same pair added again before pack
    -> find returns the same canonical object
    -> add clears the deletion mark
```

Logical deletion remains reversible visibility state. Physical removal belongs to `pack()`. The documentation therefore does not reinterpret the absent deleted filter in `find()` as a defect.

### Active binding projection

`current` is correctly described as transient runtime state used by `get(TVariable)`, `set`, and `isEmpty`, not as the canonical registry, persistent record set, or durable child-to-parent publication map.

The two cleanup directions remain explicit:

```text
TValueFactory.pack
    removes bindings whose TValue was physically removed

TVariableFactory.pack
    removes bindings keyed by a physically removed TVariable
```

### Layered index and observable order

The documentation correctly states that the acceleration index stores IDs only and that values remain owned/hydrated through cache and storage.

It preserves the source-proven ordering model:

```text
Escalera raw iteration        newest first
root index initialization     reverse to oldest first
layer collection              parent layers before local IDs
forEach substitution order    historical oldest first
```

This order is not conflated with either canonical identity or `TValue.compareTo` ordering.

### Checkpoint deltas and action rollback

The no-argument checkpoint protocol is accurately documented as delta-based:

```text
mark
    push empty additions delta
    save action
    mark cache

add
    add to cache and index
    record in current delta

nested commit
    merge inner delta into enclosing delta
    discard saved action

release
    release cache
    unindex additions in reverse order
    restore action
```

The wording explains why this auxiliary journal is required without claiming that a complete index snapshot is taken.

### Packing, persistence, and ordering

The pack contract is bounded to logically deleted values and values whose underlying Term is not referenced by an active Rule. Physical removal synchronizes the index and transient binding projection and re-establishes the generation-local chain anchor.

The unit-level ordering contract is stated separately:

```text
TValue.compareTo -> lexicographic (tVarId, TValue id), full long range
```

The class comment does not confuse Comparable order with oldest-first substitution traversal.

## Review conclusion

J4 establishes a precise variable/value vocabulary:

> A TVariable is a separately allocated logical variable owned by a Rule and Mind level; a TValue is a canonical variable/value association whose persistent identity, transient active binding, acceleration metadata, and checkpoint lifecycle are related but separate state dimensions.
