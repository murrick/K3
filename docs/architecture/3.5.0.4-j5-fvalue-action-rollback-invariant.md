# KANGER 3.5.0.4 — J5 FValue action rollback invariant

## Status

A focused J5 regression proved and isolated an `FValueFactory` checkpoint rollback defect.

Red checkpoint:

```text
7c6ab082af9498742b6c50d5387a835214ece6a4
Gate FValue action rollback
```

Minimal correction:

```text
3a749b7ca08f8ada4a1f67c3b745c58034ae5ad5
Restore FValue action on checkpoint release
```

Permanent runner:

```text
kanger-console/src/org/kanger/KangerFValueActionRollbackSafetyRunner.java
```

## Architectural context

`FValueFactory` owns several related but independent state dimensions:

```text
Escalera cache
    canonical FValue records and checkpoint visibility

invalidated
    transaction-visible IDs excluded from canonical lookup

action
    mutation/effect signal consumed by inference continuation
```

Before the correction, no-argument checkpoint handling was asymmetric:

```text
mark
    cache mark
    invalidated snapshot

release
    cache release
    invalidated restore
    action retained from speculative mutation
```

A released speculative `FValue` therefore disappeared from the canonical cache and lookup path while the factory still reported an action that no longer existed.

## Proven failure

The focused runner performs one baseline and one speculative result lifecycle:

1. create a complete Function and a baseline FValue;
2. clear the baseline action signal;
3. change the Function result state so a different FValue is required;
4. mark the FValue factory checkpoint;
5. create the speculative FValue and verify that action becomes true;
6. release the checkpoint;
7. verify that the speculative FValue no longer exists in cache or canonical lookup;
8. require the pre-mark action state to be restored.

On the red checkpoint, all pre-existing KANGER CI gates succeeded and only the new `FValue action rollback invariant` step failed. The cache and lookup assertions precede the final action assertion, isolating the remaining violation to the stale continuation signal.

## Root cause

`FValueFactory.action` is checkpoint-semantic state but was not included in the factory's nested checkpoint journal.

The existing `invalidatedStack` restored invalidation visibility correctly. It did not restore action state, and no higher layer could reconstruct whether the signal had existed before the local mark.

This is analogous in invariant shape to action rollback in `TValueFactory`, but the implementation remains category-specific:

```text
TValueFactory
    additions delta stack
    + action stack

FValueFactory
    complete invalidation snapshots
    + action stack
```

No universal factory journal is introduced.

## Minimal correction

The correction adds:

```text
Stack<Boolean> actionStack
```

and makes it generation/checkpoint symmetric:

```text
transaction / clear
    clear action snapshots

mark
    mark cache
    snapshot invalidated IDs
    snapshot action

commit
    commit cache
    discard invalidation snapshot
    discard action snapshot

release
    release cache
    restore invalidated IDs
    restore action
```

Nested behavior is preserved:

- inner commit retains the current action and discards only the inner saved state;
- enclosing release can still restore the action value that existed before its own mark;
- generation changes cannot retain snapshots from a previous cache/storage lifecycle.

## Change boundary

The correction does not change:

- FValue canonical lookup or equality;
- Function completeness or substitution stamp construction;
- UDF invalidation selection;
- `FunctionBinding` behavior;
- persistent FValue record layout;
- cache promotion or typed child commit;
- storage attachment or close authority;
- public signatures;
- Linker continuation policy.

It only prevents a released mutation from leaving a false positive in the existing continuation signal.

## Acceptance

The invariant is accepted when the permanent runner succeeds and the complete qualification contour remains green on a correction checkpoint.

J5 source documentation must thereafter describe `actionStack` as a dedicated auxiliary checkpoint journal alongside, but distinct from, complete invalidation snapshots.
