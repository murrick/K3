# Stage3bb — explicit writer language boundary before default integration

Historical scope at stage3bb. Stage3bc extends the flat whole-declaration variable
limit to three and moves the executable refusal to four variables; see
3.8.0-context-production-three-variable-scope.md. The controls below describe the
original stage3bb boundary.

The opt-in `ctx candidate write` path is narrower than native KANGER authoring.
These limits are a conservative supported scope, not evidence that the rejected
native assertions are contradictory. Default authoring is still unchanged.

## Executable boundary controls

The actual shared-command/provider publication driver now checks the following
native-valid assertions in disposable physical stores. Each unsupported candidate
must return INCOMPLETE with a reason, no publication audit and unchanged physical
revision, rule count and presentation stores. Reopen must retain the exact original
inventory fingerprint and one anchor primary. Thus an unsupported candidate cannot
fall through to the ordinary native writer.

| Native assertion | Current explicit writer boundary |
| --- | --- |
| `!@x @y a(x,y)&&b(x,y)->c(x,y);` | Supported two-variable, three-literal control: audited publication |
| `!@x @y @z tri(x,y,z);` | Whole-declaration variable count exceeds two |
| `!@x a(x)&&b(x)&&c(x)->d(x);` | Clause width exceeds three |
| `!@x p(x)->q(x+1);` | Variable-containing function argument outside flat ordinary arguments |
| `!$w witness(w);` | Native witness bundle is not a flat universal proof declaration |

Each unsupported case first compiles successfully with the ordinary native engine.
This distinguishes supported-scope refusal from syntax rejection. These controls
are boundary evidence, not an exhaustive grammar characterization.

Two additional actual-provider controls place the three-variable assertion in
existing X or a pinned foreign context, then request the simple candidate
`!safe(1);`. Binding must abort the whole request with the native binding reason;
it must not skip that primary row and authorize a supported prefix. The Console
reports an operational binding failure, not PUBLISHED. Existing-inventory binding
failure is currently an exception, whereas unsupported candidate staging/inspection
returns a typed INCOMPLETE result. This distinction is preserved and documented.

## Requirements before changing ordinary authoring

A default-authoring handoff must preserve the current explicit writer's fresh
owning lease, complete inventories, exact initialized cuts, synchronous common
barriers, all whole-Source alternatives, independent final audit and consumed
settlement authority. Neither a historical diagnostic nor an incomplete supported
subset can grant publication. Independently contradictory sibling contexts remain
permitted; foreign facts must not become communal X facts.

Native syntax acceptance alone cannot grant flat proof/model coverage. Expanding
variable/width limits requires checking the later inference, factoring, provenance,
model and independent-audit bounds together; changing a binding constant alone is
not an established extension. Witness/residual/function semantics require explicit
scope and source-sharing evidence before they can join this path. Resource stops
remain incomplete, never inferred consistency or a fabricated collision.

These controls do not redirect default `!` input or resolve its last RED contract
(stage3r, 56 checks / two failures). Question3 remains open. No new semantic defect
or architectural fix is claimed by this stage: it records and tests the current
publication boundary so subsequent language work has a concrete baseline.
