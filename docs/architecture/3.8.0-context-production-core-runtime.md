# Stage3q: production Core boundary for the round engine

## Extraction

Nineteen runtime classes moved, with their package names and behavior retained,
from kanger-qualification/src/org/kanger to kanger/src/org/kanger:

- native inventory, binding, family assembly and detached candidate;
- witness bundle, primary-step/materialization checks and proof closure;
- seed replay, transport, source-cut/empty-target handling;
- ordinary application authentication, Horn obligations, family qualification
  and synchronous fixed-point execution;
- disjoint/dormant coverage helpers used by transport.

The only qualification dependency was the immutable Declaration DTO nested in
ContextProductionRoundsReference. It now lives in production
ContextProductionInputs.Declaration. Both the reference implementation and
runtime callers use that independent DTO; reference runners stay in the
qualification plane. The former qualification-only nested type is not retained
as a parallel source/proof representation. No stable runtime API used it.

No Core dependency on qualification, DUMB2, command/bootstrap or delivery modules
is added. The Core artifact contains the engine and DTO, with no Runner or
RoundsReference class. Existing public facades expose the same scoped diagnostic
semantics; placement in Core does not turn FIXED_POINT into unrestricted
admission or enable a default authoring hook.

## Standalone artifact check

ContextProductionCoreJarRunner uses only public Core APIs. Beyond the focused
suite it is explicitly compiled and executed with kanger-core.jar as its only
runtime dependency:

```
javac -cp kanger-core/target/kanger-core-3.3-SNAPSHOT.jar \
  -d /tmp/k3-stage3q-core-only \
  kanger-qualification/src/org/kanger/ContextProductionCoreJarRunner.java
java -cp /tmp/k3-stage3q-core-only:kanger-core/target/kanger-core-3.3-SNAPSHOT.jar \
  org.kanger.ContextProductionCoreJarRunner
```

Seven checks cover native input/binding, detached candidate fixed point, source
mapping, seed accounting, candidate authority, base nonmutation and the shared
DTO. Evidence: `/tmp/k3-stage3q-core-only.log`. ZIP inspection independently
confirms runtime classes are present and qualification runners/reference absent.

## Remaining production integration

DUMB2 ContextProductionSnapshotSession and the explicit writeCandidate bridge
still reside in qualification. Next: move the owning provider bridge into DUMB2
with an intentional supported-scope interface; then extend the required signed/
foreign-fact qualification and wire actual default write/commit/topology gates.
Ordinary default behavior is unchanged in this extraction. The original authoring
contract remains last RED56/2. Question3 and general language/source coverage stay
open. Full DMZ gate equivalence is not inferred from class relocation.

Validation reconciliation: the first full offline Maven verify ran 821 tests,
with zero assertion failures and11 socket-permission errors in the sandbox.
The three affected HTTP/admin classes were rerun with local sockets permitted:
13/13 tests passed, covering all11 errors (two already-green tests repeated).
All qualification JUnit classes were then built/tested with the reactor:
28/28 passed; exec-based parser/corpus runs are tracked separately. This is a
reconciled set of runs, not a claim that the initial full reactor invocation was
green. Logs: `/tmp/k3-stage3q-maven.log`, `...-sockets.log`,
`...-qualification-maven.log` and `...-exec.log`.
