# Stage2u: observed single-premise witness chain proofs

ContextWitnessUnaryChainVerifier reconstructs a finite captured journal of
single-premise applications, with exactly one distinct witness root in each
premise and conclusion. That root must be preserved within the observed
application. Repeated argument positions and fixed semantic arguments are
allowed; multiple simultaneous roots, dominating witnesses, new witness
introduction and multi-premise applications are refused. Ordinary producer
shape/source checks retain the previous two-native-variable bound.

The owning Session must describe one X-plus-one-external cut with consistent
supplied revision/view labels. Primary source/native bindings and producer
instances use the shared checks from the primary-step verifier. Materialization
correspondences use the same previously tested verifier and the same work budget.
No live effective-pin authentication or native coverage certificate is added.

## Separate physical carriers and proof origins

A Route holds the actual physical literal pattern, an original primary witness
root, the complete source support/minimum depth, and an immutable predecessor
recipe. IDs belong to Session.replay only. A physical root is not rewritten into
a global equivalence class. Instead:

1. A primary bundle atom seeds a route at depth0 with its whole source support.
2. A checked observed application consumes a matching physical premise route.
   Its conclusion inherits that route's original witness, unions its producer
   sources with the whole donor group, and has depth max(donor, producer)+1.
3. A verified materialization occurrence moves that application's route to the
   actual stored literal. Original witness, source group and depth are unchanged;
   the recipe retains the specific application/occurrence rather than an alias
   between every root sharing the stored representative.

Producer support alternatives and donor routes are handled separately. Equal
physical pattern/origin/whole-source-group entries retain their minimum depth;
other origins or source groups never collapse. Iteration repeats until no such
entry changes. Captured patterns, primary origins and source subsets are finite;
minimum-depth replacement prevents redundant cyclic paths from growing forever.
The work/depth limits still stop with no verified route prefix. This is a fact
about closure of the captured journal, not termination or completeness of native
inference on arbitrary inputs.

## Why the restricted chain is sound

Each seed refers to the witness of its complete primary conjunction. Each native
application is independently matched to its producer clause, preserving signs,
constants and variable correspondence. Within this scope the application has
one witness value, so replacing that physical representative uniformly by one
route's primary witness preserves the producer instance. Applying it to the
route's proved premise yields the conclusion for that same witness. A stored
alpha representative is then a carrier of this specific proof; it does not add
a source, a rule step, a new witness or a global equality. Induction over the
immutable predecessor recipe establishes each returned route.

For independent left(w,1) and right(v,1) producing the same stored q, downstream
q->r gives separate stored-r routes: origin w with the left proof sources, and
origin v with the right proof sources. One physical stored root can carry both
routes. Neither exchanged source/origin pairs nor the union of the alternatives
is inferred. Foreign-only routes remain private; no export into X is implemented.

## Validation and limits

The 23-check runner covers p->q->r with carried depth2, source/depth reset
refusals, zero-cost storage crossings, depth/work stops, independent origins
through one alpha-reused representative, direct versus chained proof depths,
minimum depth for an identical source group, producer aliases, signed intermediate
facts, fixed-value mismatch, cycles, invalid sibling cuts and refused multi-root/
multi-premise inputs. Earlier primary-step and materialization controls remain
active after sharing their scope/instance/correspondence checks.

All observed applications must obtain a route; unresolved applications refuse
the result. Existing nonordinary capture gaps remain present. The result is not
SATURATED, a model/coverage certificate, cross-round identity or a runtime write
decision. Base consistency still needs qualification. Whole witness result
transport is not enabled.

Next: prove route coherence for several premises before admitting witness joins,
then whole-bundle result transport and stable round identity. Mixed prefixes,
generated witness dependencies, effective views/pins, atomic runtime gates and
question3 remain open.
