# 3.5.0.7 — parser terminal-boundary release polish

## Trigger

After an in-memory source was loaded and exercised successfully, `use <database>` attempted to recompile that source while switching to persistent storage. When the source ended with delimiters after its final semicolon, tokenization advanced to `line.length()` and then called `String.charAt(line.length())`.

Observed path:

```text
Parser.nextToken
  -> Tools.extractLine
  -> Mind.compile
  -> Console.useDatabase
```

## Correction

- `Tools.extractLine()` now treats `tokenEnd >= line.length()` as source exhaustion;
- `Parser.nextToken()` returns `null` when delimiter skipping reaches the terminal boundary;
- `KangerParserTerminalDelimiterSafetyRunner` permanently covers exact-end, trailing-delimiter and delimiter-only buffers;
- the qualification-isolation workflow executes the new gate from the test-only qualification source tree.

## Compatibility

The correction does not change language grammar, semantic identity, public API, persistence format or storage lifecycle. It only replaces an unchecked terminal-boundary exception with normal end-of-source behaviour. The release version remains `3.5.0.7`.
