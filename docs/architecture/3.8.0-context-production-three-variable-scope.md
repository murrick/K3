# Stage3bc — three-variable flat native binding

The whole-primary native binding limit increases from two to three universal
variables per declaration. Clause width remains three, arity eight, declaration
branch count eight. Witnesses and variable-containing functions do not acquire
flat universal proof/model support. Ordinary default authoring is unchanged.

This supersedes the three-variable refusal recorded in stage3bb. The executable
boundary now refuses four-variable declarations, including existing X and pinned
foreign declarations: no unsupported primary is silently omitted. Stage3bb remains
an append-only historical checkpoint, not the current variable limit.

## Evidence across the full handoff

The binding change uses the existing variable-set representation, bijective clause
comparison, flat unifier/factoring kernels and all-value quotient construction;
none enumerates a hardcoded two-variable tuple in this explicit flat path. The quotient checker already caps
rank at sixteen and checks every projected valuation; native rotation audit has a
separate rank-three ceiling. This stage does not change those mechanisms or budgets. The older residual
eigenparameter path retains its separate rank-two limit; no wider residual
coverage is claimed.

The extended candidate driver checks:

* `seed(x,y,z) -> ready(z,y,x)` with foreign seed(1,2,3) and opposite
  ready(3,2,1): collision at common barrier2 in both sibling orders, exact three
  Sources/depth2 and independently audited candidate attribution;
* a three-variable binary join with nonmatching negative endpoints: complete
  all-value models for all three cuts, independently audited consistency;
* the same rule with instance budget one: INCOMPLETE, no certificate/collision;
* a fully universal three-variable seed and reversed consequence: consistency
  with an independently checked certificate over all admissible values;
* preservation of every original caller inventory.

The real Console/provider driver publishes
`!@x @y @z edge(x,y)&&edge(y,z)->path(x,z);` over edge(1,1), edge(1,2).
Ordinary native queries see path(1,2), do not see path(2,1), and retain the rule
and consequence after reopen. Only the two original facts and candidate are
primary; the generated consequence is not promoted to another primary. The
three-variable/three-literal empty-source control also publishes after audit.

## Practical model-search boundary remains explicit

The first exploratory tests used three distinct constants and ternary relations.
They exhausted the existing model assignment budget rather than receiving a
consistency certificate. The counterexample is retained: the above reversed rule,
seed(1,2,3), and negative ready(3,1,2) stop with model assignment limit. This is
bounded incompleteness, not evidence of a logical contradiction. No resource cap
or model search algorithm is changed here. Supporting three variables therefore
does not promise completion for every three-variable database.

Four variables, four literals, variable functions and witnesses still refuse
explicit publication. Default last contract remains stage3r RED56/2; general
native residual/witness/function scope and question3 remain open. Later work can
address model-search cost or clause width as separate bounded steps, with the full
independent audit and settlement guarantees retained.
