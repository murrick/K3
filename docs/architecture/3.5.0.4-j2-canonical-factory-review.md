## Stronger lifecycle finding

J2 disproved an over-broad initial factory abstraction.

Standard child `Mind` construction does not create child instances for these categories:

```java
terms = (DictionaryFactory) root.getTerms();
predicates = (PredicateFactory) root.getPredicates();
```

Therefore:

```text
DictionaryFactory / PredicateFactory
    exact canonical instances shared through the Mind chain

remaining principal factories
    child-specific factory instances initialized through transaction(parent)
```

The correction is recorded in:

```text
docs/architecture/3.5.0.4-j2-type-map-correction.md
```

This distinction is now part of the accepted architectural vocabulary and must govern later Javadoc.

## Paired role model

| Dimension | `DictionaryFactory` | `PredicateFactory` | Shared boundary |
| --- | --- | --- | --- |
| Representation | Canonical registry of Terms and internal variable descriptors | Canonical registry of predicate name/range descriptors | Semantic canonicalization, not mere construction |
| Owner | Root `Mind` that constructs the instance | Root `Mind` that constructs the instance | Child Minds observe the same instance |
| Child lifecycle | Exact-instance sharing; chain-shared Term cache and C-variable index | Exact-instance sharing; chain-shared Predicate cache | Not normal transaction overlays or parent-promotion participants |
| Identity | Equivalent value/descriptor maps to one active Term | Equivalent name Term plus range maps to one active Predicate | Restoring a deleted canonical unit does not allocate a duplicate identity |
| Persistence | Borrowed dictionary `IBase`; cache-miss hydration and update | Borrowed predicates `IBase`; cache-miss hydration and update | `User` / `IData` own storage generation and close authority |
| Runtime metadata | C-variable allocator, transient adjacency publication, incremental pack frontier | No separate allocator/frontier | Runtime metadata is not automatically durable semantic state |
| Packing | Incremental candidates after first full pass; Rule snapshots plus transient projection roots | Full canonical scan; Rules plus solution/hypothesis roots | Packing occurs at root quiescence, not child rollback |
| Concurrency | Synchronized add/index/pack boundaries | Synchronized add boundary | Local synchronization is not blanket thread safety |

## Contract consistency findings

The class-level contracts agree on the following invariants:

1. Canonical identity is shared throughout one active Mind chain.
2. Neither factory is the owner of `IData` or storage termination.
3. A schema `IBase` is a borrowed current-generation attachment.
4. Standard child publication occurs by reference reuse, not factory promotion.
5. `transaction`, typed `commit`, and cache-checkpoint methods must not be confused with the normal child-Mind lifecycle for these categories.
6. Packing is category-specific reachability cleanup performed through the owning/root context.
7. Query-result stores may temporarily retain canonical units but do not become factory-owned persistent repositories.
8. `closeConnection()` is not the authoritative storage lifecycle path.

No contradiction remains between the paired comments, `Mind` construction, `User` storage ownership, or the final `3.5.0.3` connection audit.

## Category-specific findings

### DictionaryFactory

The documentation correctly separates:

```text
canonical Term identity
chain-shared C-variable index allocation
transient Mind-owned C-variable adjacency
incremental reachability metadata
persistent schema attachment
```

The first complete pack pass establishes the Rule-term baseline. Later passes inspect the candidate frontier and reintroduce Terms whose active Rule references disappear. Terms retained only by solutions, hypotheses, or values remain watched because those roots are transient.

### PredicateFactory

The documentation correctly identifies predicate identity as the combination of name Term and range. Packing performs a full scan and consults active Rules plus current solution/hypothesis projections. The factory neither owns the name Term nor the projection stores used as temporary reachability roots.

## Compatibility surfaces

Both classes retain methods whose presence is broader than the standard current lifecycle:

```text
transaction(otherFactory)
commit(otherFactory)

release()
closeConnection()
```

J2 does not remove, narrow, reinterpret, or newly endorse these public surfaces. Their exact caller-visible contract belongs to `3.5.0.5`.

Implementation Javadoc describes the active architecture and explicitly prevents these methods from being mistaken for proof of child overlay or storage ownership.
