# KANGER 3.5.0.4 — J8 Linker opening

## Scope

J8 documents the existing `Linker` execution boundary without redesigning the inference kernel.

```text
kanger/src/org/kanger/Linker.java
```

The checkpoint is isolated because Linker coordinates the convergence loop across canonical factories, transient solve state, function evaluation, system predicates, hypothesis accumulation, produced-domain classification, and Rule materialization.

## Governing invariant

> Linker may continue saturation only when an observable transaction/query-local semantic effect survives the completed operation or pass.

A continuation signal is not independent state. It is evidence that a surviving mutation requires another pass. Any signal produced only by rolled-back speculative work must be restored with the same checkpoint frame.

## Evidence-first boundary

J8 must establish from production source and regressions:

1. ownership and lifetime of the Mind-owned Linker instance;
2. reset boundary of query-local statistics, `ruleSolves`, and solve-index acceleration;
3. construction of the active Rule set for full and rule-scoped execution;
4. the deliberate descending-then-ascending Rule traversal invariant;
5. pass-local reset and final consumption of Rule, TValue, FValue, temporary-hypothesis, and hypothesis action signals;
6. variable rotation and transient TSolve compatibility filtering;
7. local TValue/FValue mark, commit, and release boundaries during domain unification;
8. separation between branch classification in `linkDatabase()` and delayed Rule materialization in `updateDatabase()`;
9. publication of TValue, FValue, TSolve, hypothesis, produced Domain, Cause, and stored Rule effects;
10. flood-limit failure semantics and cleanup obligations;
11. concurrency assumptions and caller obligations;
12. the exact frozen boundaries around `isValidFor()` and `linkDatabase()`.

## Existing proven constraints

J8 inherits these already-qualified invariants:

- `solveIndex`, `indexedSolveCounts`, `unarySolveKeys`, and `indexedSolves` are query-local acceleration over `Mind.ruleSolves`, not semantic authority;
- each `link()` clears both canonical transient solve storage and its acceleration structures;
- the first Rule rotation is strict full-range descending ID order and the second is strict full-range ascending ID order;
- candidate metadata locks protect coherent ID snapshots and memo publication only; Rule hydration and Mind-dependent work remain outside those locks;
- `linkDatabase()` is a retained legacy branch-closure/deferred-materialization kernel and is not an authorized local refactoring target;
- `isValidFor()` is a hidden compatibility join over transient TSolve state; a rename or rewrite requires equivalence proof, not aesthetic preference.

## Change discipline

The default J8 production change is class-level architectural Javadoc only.

An executable change is permitted only if source inspection and a focused red gate prove a concrete invariant violation. Any correction must remain minimal and must not alter:

```text

Rule traversal order;
unification direction;
branch classification;
materialization timing;
hypothesis policy;

```
