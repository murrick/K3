# Stage3az — explicit read-only candidate command

The shared canonical command language now accepts:

```
ctx candidate "!@x left(x)&&right(x)->p(x);"
ctx candidate "!@x left(x)&&right(x)->q(x);" rounds=8 work=64000000
```

This checks a newly staged assertion against the current exact pinned initialized
family. It does not write the assertion, redirect ordinary `!` input, call the
stage3ay writer or produce a reusable publication capability.

## Shared boundary and limits

A new CTX_CANDIDATE intent is parsed/formatted/documented by the shared command
registry and dispatched by CanonicalCommandProcessor. ContextUniversalCandidateRequest
is immutable and preserves exact statement text plus normalized ordered limits.
There is no second Console parser. IContextFederation has an optional read-only
provider method with an unsupported default; DUMB2 implements it through a fresh
owning snapshot session. Console presentation does not depend on a DUMB2 cast.

Defaults: rows1000, rounds16, local16, depth16, instances20000, models1000000,
preparation64000000, events500000, work64000000, audit64000000. All limits are
positive except depth may be0; rows is capped at10000. Unknown/repeated/negative/
overflowing malformed options refuse at the command boundary. Request maps cannot
be changed by caller mutation. Canonical round trips preserve every limit.

Native binding/staging retain their existing per-operation preparation/event
allowances. work spans the complete synchronous family inspection; audit spans
the independent final candidate check. These are explicitly separate scopes.
The requested row limit must match the owning snapshot's captured row bound.
Each fresh invocation restarts qualification; no historical cached result is
accepted as proof for another trial.

## Result meaning

Console prints CONSISTENT or COLLISION only for a verified final audit. An
unfinished inference OR final audit prints INCOMPLETE, even if a prior inference
stage found a model. It prints the actual reason, completed-barrier count, exact
source context/revision, cut count and the all-admissible-value flat ordinary
universal scope. This is the previously proved quotient interpretation, not a
domain restricted to known values.

Every collision alternative shows exact candidate dependence, cumulative depth
and whole original Source identities. Rebuilt original X Sources are translated
back; foreign pins/views and the candidate's private Source retain their identity.
Candidate dependence is per proof, not unique blame or standalone assertion
falsity. A visible read-only footer explicitly states no assertion was written.
A transport Result.isSuccess means command execution succeeded, not write approval;
clients must inspect the typed audit/evaluation and verification flag.

The command neither overwrites saved DMZ queries/families nor source logs,
Solutions or Hypotheses. Preparation failures/unsupported native declarations,
including variable functions, remain incomplete. Scripts are not single-assertion
candidates. Missing/unavailable physical provider authority refuses without falling
back to ordinary Core authoring. Existing DMZ and normal assertion syntax remain.

## Controls and continuation

The new driver covers grammar, all-limit round trips, malformed input, immutable
requests, row-bound mismatch, shared typed dispatch, real Console output for all
three outcomes, exact proof attribution, incomplete final audits, native function/
script refusal, saved DMZ history, source presentation stores and physical reopen
with only the original primary assertion. All fixtures are disposable. The full
existing parser conformance suite is also rerun. Main checkpoint records totals
and final report; registration counts do not imply a full DMZ run.

Next: review explicit Console publication versus read-only diagnostic usage and
broader supported-language coverage before any default-authoring migration.
Native residual/witness/function scope and question3 stay open. Default last
contract remains stage3r RED56/2; the default path is unchanged.

Server scope: the server runtime retains its existing explicit intent allowlist;
CTX_CANDIDATE has no server transport binding in this stage and falls through to
the existing canonical_intent_not_bound response. No server file was changed.
The shared processor result is available to adapters that explicitly bind it;
this stage supplies Console presentation only, as with existing Console-bound DMZ
operations. No silent blank-success server projection was introduced.
