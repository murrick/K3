## Meaning of the refusal

The limit is an internal count of calls to a `work.run()` callback, not money,
model tokens, elapsed time or CPU instructions. The retained workload is:

- X: `!anchor(1); !@u p(u);`
- A: ONE physical row `!@u (p(u)&&b(u)->r(u))&&(p(u)&&r(u)->s(u));`
- B: `!b(1);`

The grouped controller owns one cumulative 64000000-work budget across its run.
Other phase primitives also have their own declared budgets. The result completes
2 barriers, then exhausts the controller budget in round3 certificate-binding.
INCOMPLETE publishes no fixed/private/carrier output, history or refutation prefix.
It is not a contradiction or a proof of saturation. The original source/program
semantics and depth/work bounds are unchanged in this stage.

## Reproducible qualification-only measurement

Run `python3 scripts/profile-context-production-work.py` after building the Console
JAR. The script compiles the qualification harness and creates TEMPORARY instrumented
copies of 9 existing Core files, wrapping 17 selected verification methods plus
controller budget/phase/round boundaries. It NEVER edits those production sources
or the JAR; exact source hashes, JAR SHA256 and git HEAD are checked before/after.
Explicit in-repository output must be under target/, protecting source directories.

Baseline runtime is qualification classes plus ACTUAL JAR only. The explicitly
named diagnostic-overlay runtime places the temporary instrumented Core classes
before that same JAR. It is not an actual-JAR-only qualification or a product build.
Only the owning controller's actual callback is wrapped. Work in separate nested
budgets is NOT charged to this measurement. A zero for another phase means zero
OWNING-counter charges, not zero computation/time in that phase.

Counters use exact object identity, expected depth in relevant labels, a scoped call
stack, disjoint leaf charges and overlapping inclusive charges. Sum of leaf charges
and phase charges must each equal total attempted ticks. The failing callback attempt
is included; accepted callbacks are reported separately. Completed targets require
normal return, not merely leaving a scope. Failed/rejected verification is explicitly
counted as aborted. No stack sampling, pruning, evidence reuse or new authority.
Identity repetition is evidence of repeated visits; several helper labels deliberately
key only a receiver/history, not every application/policy argument. It NEVER licenses
a cache or proves that an arbitrary repeated call may be skipped.

## Semantic controls and counter correctness

The harness runs BOTH stable and failing fixtures against the actual JAR and the
explicit temporary diagnostic overlay: 4 executions, 2 semantic comparisons.
Stable control independently passes GroupedChainAudit in each mode. Comparison
includes the ENTIRE recorded round sequence: flags, all supplied cut proof ledgers,
incoming/outgoing fixed/unit/compound inventories, exact whole-source sets and depth
minima. Physical original sources are mapped bijectively to X/A/B row occurrences,

explicitly restricted to these numeric fixtures; this is not a general serializer

completed2 and absence of every output/history/refutation prefix.
