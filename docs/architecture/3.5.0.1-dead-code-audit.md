# KANGER 3.5.0.1 — Dead-code audit register

## Purpose

This register records evidence before code is removed. It distinguishes executable dead code from historical source debris, compatibility surfaces, diagnostic specification, and unresolved candidates.

The audit baseline is:

```text
fix/3.4.4.2.3-mind-lifecycle-safety
937c7d663925193cb5d37023776a95fd7751f79e
```

## Classification

| Class | Meaning | Action |
|---|---|---|
| D1 | Demonstrably unreachable or unused executable code | remove after compile/regression proof |
| D2 | Historical source debris: commented-out former implementation | remove; history belongs to Git |
| R | Intentional architectural or compatibility reserve | retain and document |
| S | Diagnostic or executable-specification support | retain unless deliberately replaced |
| U | Unresolved indirect-use risk | retain pending evidence |

## Confirmed D1 candidates

### `kanger-data-dumb/src/org/kanger/storage/DB.java`

`DB` contains a private recursive helper:

```java
private boolean deleteDirectory(File directoryToBeDeleted)
```

The method calls itself recursively but has no root invocation anywhere in `DB`. It does not implement `IData`, is not exposed through a method reference, and storage removal uses the separate `deleteStorageFiles(...)` / `deleteRecoveryLogs(...)` path. Because the method is private, ordinary external Java linkage is impossible; its only theoretical indirect path would be explicit reflective access by its exact private name, for which there is no architectural or diagnostic contract.

**Classification:** D1 — unreachable executable code.

**Removal boundary:** remove only the complete private method. Do not change `remove(...)`, reindex replacement, storage-file deletion, WAL cleanup, or recursive storage listing.

## Confirmed D2 candidates

### `kanger-data-dumb/src/org/kanger/storage/Index.java`

The current source contains several complete former implementations preserved only as line comments:

1. abandoned `ReentrantReadWriteLock` / read-lock / write-lock fields;
2. abandoned `getBlockLength(Collection<IndexOne>)` helper;
3. abandoned `add(long id, long data)` wrapper whose behavior is subsumed by `set(long,long)`;
4. abandoned full-scan `size()` implementation.

These fragments are not compiled, cannot be reached through reflection, serialization, persistence hydration, scripting, CLI dispatch, or external Java linkage, and have no diagnostic effect. Their only remaining function is historical, which is already provided by Git history.

**Classification:** D2 — safe source cleanup.

**Removal boundary:** delete comments only; do not change adjacent executable statements, iteration order, synchronization, index layout, sentinel handling, or counters.

### `kanger/src/org/kanger/interfaces/internal/IBase.java`

The interface retains one former declaration only as a line comment:

```java
// int size() throws Exception;
```

It is not part of the compiled interface and therefore has no binary or source-compatibility effect.

**Classification:** D2 — safe source cleanup.

The commit must satisfy all of these conditions:

4. the compiled class API is byte-for-byte equivalent apart from debug line-number metadata;

A whitespace-only normalization is permitted only on blank lines made adjacent by the deletions.

## Confirmed retained specification support

### Safety and qualification runners

The following classes may appear isolated from product call graphs but are explicit CI entry points and executable architecture specifications:

- `KangerMindSafetyRunner`;
- `KangerFactorySafetyRunner`;
- `KangerRuleRenderingRunner`;
- DUMB qualification, integrity, recovery, and concurrency runners;
- semantic telemetry and prediction runners.

**Classification:** S — retain.

A zero-reference report inside ordinary Java code is irrelevant for these classes because the workflow invokes their `main` methods by fully qualified class name.

### Reflection in safety runners

Reflective access to private fields such as factory `top`, `bottom`, `connection`, Mind transient maps, and `transactionCounter` is intentional test instrumentation. These field-name strings form part of the current regression contract.

**Classification:** S — retain during 3.5.0.1.

Any later naming change in 3.5.0.2 must update the corresponding runner atomically.

### Linker semantic notes

Documentation around `Linker.isValidFor()` and `Linker.linkDatabase()` is not obsolete commentary. It freezes observed legacy semantics until a dedicated semantic model and regression corpus permit behavioral refactoring.

**Classification:** R/S — retain.

## Storage surface audit

### `DB` / `IData`

The following `DB` methods are live interface contracts and are not cleanup candidates:

- `init`, `use`, `close`, `flush`;
- `remove`, `reindex`;
- `isClosed`, `getStorageName`;
- `getBase`, `connect`;
- `getDescription`, `list`.

Private helpers `deleteStorageFiles`, `deleteRecoveryLogs`, and `recurseList` each have an active root invocation. Only `deleteDirectory` lacks one.

### `Base`

`Base` implements the complete `IBase` contract and additionally exposes:

- `isClosed()`;
- `iterator(boolean backward)`;
- public inner `StorageIterator` and its constructor.

These are not classified as dead. Directional iteration and direct iterator construction may be used by qualification/recovery code or implementation-level diagnostics even though they are absent from `IBase`. `Base.isClosed()` remains unresolved until all owners and compatibility callers are checked.

**Classification:** U/R — retain pending repository-wide caller and compatibility analysis.

The following are contract implementations, not cleanup candidates:

- cache telemetry getters;
- `lastId()` / `nextId()`;
- `deleteAll(...)`;
- `getRoot()` / `getTop()`;
- `reindex(...)`;
- iterable support.

### `Data`

The persistence hydration path is indirect but live: `Data.readOne()` creates a `Sapato`, applies serialized bytes, and reconstructs an `IStep`. Constructors and hydration methods reached only through this path must not be removed by ordinary call-count analysis.

The private execution graph in `Data` is closed and rooted:

- `readOne(...)` is reached by cached reads, uncached scans, and iteration;
- `getOne(...)` is reached by `get(...)`;
- `addToCache(...)`, `cacheWeight(...)`, and `clearCacheState()` are active cache-lifecycle helpers;
- `DataOne.saveBlock()` is reached by write-through, flush, and eviction.

No private D1 candidate was found in this class.

The following public methods are implementation-level diagnostic or storage primitives rather than declared interface methods:

```text
getUncached
getVersion
getReadCounter / getWriteCounter
dropReadCounter / dropWriteCounter
isClosed
getFile
cache telemetry getters
setMaxCacheSize
iterator
DataOne accessors
```

Several are directly consumed by `Base`, integrity/recovery, lifecycle safety, qualification, or diagnostics. The remainder are retained as a compatibility surface until external use is excluded.

**Classification:** S/R/U — retain.

### `RecoveryLog`

`RecoveryLog` is package-private and its complete private helper graph is rooted in the live protocol methods:

```text
prepareUpsert
prepareDelete
rollback
checkpoint
```

Observed chains include:

```text
prepare* -> capture -> readPacked
prepare* -> append -> packRecord -> openOutput -> validateHeader
rollback -> load -> unpackRecord
rollback -> restore/removeCurrent -> writePacked/invalidate
checkpoint/rollback -> closeOutput
```

The nested `Record` and `BeforeImage` types are protocol carriers instantiated by capture, append, and parse paths. No unused private helper, field, nested type, or constant was identified.

**Classification:** S — retain in full.

### `IntegrityManifest`

The integrity protocol has now been reviewed through the end of the class. Snapshot, delta, bootstrap, validation, compaction, and recovery helpers are all connected to `openOrBootstrap`, `put`, `remove`, `clear`, `flush`, `compact`, or `recoverSubset`.

Distinct live chains include:

```text
openOrBootstrap -> loadGlobal -> loadSnapshot -> applyDelta -> applyDeltaBody
flush -> appendDelta -> packDeltaBody
compact/recoverSubset/openOrBootstrap -> writeSnapshot -> packSnapshot
put -> Entry.fromStep -> Entry.fromBytes
bootstrap/validate/recoverSubset -> Entry.fromStored -> Entry.fromBytes
```

The local/global subset helpers remain semantically distinct:

- `bootstrap` constructs local integrity state from storage;
- `selectLocal`, `addLocal`, `removeBase`, and `replaceLocal` maintain one logical-base subset inside a shared physical manifest;
- `readExpected` validates semantic ID identity in addition to CRC metadata.

Nested `Change`, `Key`, and `Entry` are all active protocol value types. Their factory, comparison, equality, and hashing methods participate in delta creation, ordered snapshot storage, map identity, and checksum comparison.

No unused private helper, field, nested type, or constant was identified.

**Classification:** S — retain in full.

### `DumbFaultInjector`

`DumbFaultInjector` is deliberately package-private, non-instantiable, and inert unless the qualification property is set. `hit(String)` is called from DUMB mutation, flush, and recovery phase boundaries; subprocess runners select a phase through `kanger.dumb.fault.haltAt` and expect hard termination with code 86.

The private constructor is the conventional non-instantiability guard for a static utility class, not dead executable behavior.

**Classification:** S — retain in full as test-only process-crash instrumentation embedded at production boundaries.

## Initial unresolved candidates

The following patterns require whole-tree call analysis before action:

1. public methods on implementation classes not declared by interfaces;
2. no-argument constructors used by persistence hydration;
3. `createMap` / `applyMap` methods potentially used by API serialization;
4. factory `mark` / `commit` / `release` overloads that may be called only through Linker transaction choreography;
5. CLI runner classes whose entry points may be named only in shell/workflow files;
6. public getters/setters retained for source compatibility;
7. storage counters and diagnostic snapshots read indirectly by console commands.

**Classification:** U — retain until all modules, workflows, reflection strings, persistence constructors, and external API interfaces have been checked.

## Audit order

The whole-tree review proceeds in this order:

1. build/workflow entry points and runners;
2. public API and interface implementations;
3. persistence hydration and serialization constructors/methods;
4. reflection and scripting exposure;
5. private methods, fields, and imports;
6. historical commented implementations;
7. duplicate helpers and no-op wrappers.

The conservative order prevents removing apparently isolated code before its indirect contracts are known.

## Connector execution note
