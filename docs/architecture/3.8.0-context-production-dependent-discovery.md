## Coverage boundary

`ContextDependentRoundInspection.discoverNext` first validates and reconstructs the complete supplied prefix with its original local/independent/TRUST descriptors, private/common classification and currentness guards. For each receiver it freezes exactly the preceding common products plus its own preceding private products and exact original units. It then searches all supported non-unit original clauses and every retained literal. Ordinary original units and dependent positive roots are already seeds, so they are not copied as new productions.

A depth-first search visits each remaining literal in original compiler order. It tries every pool donor with matching predicate/arity and opposite polarity, standardizes that donor apart and propagates the whole MGU through all remaining literals. Thus shared variables correlate donor coordinates; separate occurrences of a universally quantified donor are fresh while witness functions keep their declaration identity and dependency arguments. A complete donor tuple becomes a whole signed recipe. There is no first-match shortcut or Source minimization.

The pool remains fixed during enumeration: newly discovered heads cannot feed other discoveries in this layer, even within the same cut. They become donors in the next call/barrier. The pre-existing explicit API can still accept earlier same-cut steps; this automatic API deliberately chooses one synchronous layer at a time. All results come from full original clauses and units, not generated clauses or arbitrary multi-clause resolution. Completeness means all supported residual-unit applications over this exact finite pool, not all logical consequences.

Every discovered recipe is replayed again from whole originals, without using the search's partial substitutions as authority. A second fresh projection compares both the exact ordered donor/producer recipe list and its complete typed proof digest. Original proof ancestry is rebuilt; no decoded generated atom is accepted as an axiom. The round's global total ancestral recipe bound is checked before return, and the existing synchronous API independently checks the entire extended prefix, including original/final finite-pool refutations.
