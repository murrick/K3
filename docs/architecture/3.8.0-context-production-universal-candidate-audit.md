# Stage3ax — exact candidate applicability and whole-proof attribution

`ContextUniversalCandidateAudit.audit` independently checks whether a completed
historical evaluation applies to the requested assertion, base snapshot and exact
foreign initialized snapshots. It exposes no publication capability and changes
neither existing family statuses nor native authoring behavior.

## Concrete attribution boundary

On the pre-stage3ax code, actual native snapshots reproduce this case:

* existing X: `!@x p(x)->q(x);`
* A: `!@x p(x);`
* B: `!~q(9);`
* trial candidate: `!@x unrelated(x);`

The evaluation returns COLLISION at barrier2 with two actual opposition proofs;
zero proofs use the trial candidate Source. Probe output is preserved in
`/tmp/k3-stage3ax-probe.log`. The family verdict is correct. Inferring that the
unrelated assertion itself caused this collision would be unsupported. No old
family API promised that every localX Source meant the newly added candidate.
This stage adds the missing explicit attribution boundary before writer handoff.

## Exact applicability checks

The auditor checks the requested assertion text and base object identity, actual
context/revision, append-only staged cardinality, candidate occurrence/view,
complete one-to-one original Source rebasing and semantic equality of each original
whole entry. Foreign snapshots must match by identity, with no missing/duplicate
context; their ordering is irrelevant. Matching only context/revision/fingerprint
is insufficient. The verdict must refer to staged X and that exact complete family.

For CONSISTENT, it independently reruns exact stable factored family coverage and
all-value model checks with shared work/instance allowances. For COLLISION, it
checks the full factored sealed receipt family, replays the complete merge,
validates all carried/exported and parent/result Source groups against the exact
family, replays every final unit opposition kernel and its parent-union/cumulative
depth, and matches every complete-barrier opposition one-to-one. Sealed immutable
local receipts retain the existing factory guarantees from their triple-audited
private evaluation; this is not a second execution of every historical local step.
The final kernel is reused rather than claiming a second unifier implementation.

Every whole opposition gets an immutable Attribution: exact proof, usesCandidate
based on that exact candidate Source, and originalSources translating rebased X
Sources back to their actual pre-trial identities. Foreign Sources and the trial
candidate Source remain unchanged. Original proofs are never rewritten. Mixed
candidate-dependent and candidate-independent proof alternatives are all retained.
usesCandidate expresses derivation dependence, not unique/minimal causality or
standalone falsity of an assertion. A proof without that Source witnesses a
contradictory base-family subset without needing the new assertion.

One work allowance spans applicability, rebasing, full certificate/barrier checks,
final opposition replay/matching and attribution. Bounds or late failure expose
no attribution prefix. INCOMPLETE evaluations are never upgraded. Neither kind
of collision can authorize a write. A verified CONSISTENT audit is still historical:
current owning-session checks and a consumed native transaction authority remain
separate requirements.

## Regression and handoff requirements

Controls cover actual candidate collisions, the unrelated-candidate counterexample,
a mixed factoring case retaining both kinds of opposition, original Source
translation, exact safe certificates, permuted family order, semantically equal
but distinct base/foreign snapshots, assertion mismatch, incomplete rounds,
shared instance/work limits, immutable results and unchanged native inputs. A
binary search of the public work bound checks that the last insufficient allowance
cannot expose earlier successful attributions.

A future explicit writer must acquire/qualify inside the owning provider monitor,
audit the exact newly requested trial, recheck current source/topology/initialized
views, accept only verified CONSISTENT, and consume the lease before native
settlement. Historical caller receipts must never be accepted as write authority;
post-commit finalization failures must propagate without reopening/retry. This
stage introduces no writer. Default authoring remains unchanged (stage3r RED56/2).
Native residual/witness/function scope and question3 remain open.
