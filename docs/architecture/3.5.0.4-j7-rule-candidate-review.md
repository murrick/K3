## RuleCandidateIndex contract reviewed

The package-private class now documents:

```text
ID-only ownership boundary
signature, position, and fallback maps
safe positional eligibility
wildcard handling for dynamic arguments
nested delta journals
child snapshot merge without Rule ownership transfer
mutation generation and per-Mind weak memo lifetime
version-checked memo publication
resolved selection phases
Mind-dependent batching outside metadata locks
source/candidate used-state effects
non-persistent lifecycle and hydration obligations
```

The governing lock-order invariant remains:

> Candidate metadata locks protect coherent ID snapshots and memo publication only. Rule hydration, deletion checks, TValue resolution, and Mind-dependent semantic effects execute outside candidate metadata locks.

The source implementation preserves the required sequence:

```text
resolve values outside lock
copy/filter IDs and read memo/version under lock
hydrate Rules and compute batching outside lock
publish memo under lock only if version is unchanged
```
