## Execution sequence

1. Build a reproducible manual fixture for protected Q, opposite source opinions,
   successive explicit restrictions, proof inspection and recovery. Preserve the
   actual Context/rule pins instead of asking the operator to invent them.
2. Use the matrix above to design the public symmetric derived-conflict branch
   family, preserving explicit caller proof selection as the interactive path.
   Qualify both alternatives and consecutive splits before claiming completeness.
3. Extend required language and proof forms in manageable stages, including the
   concrete distributed father/friends scenario. Complete branch-specific free
   results and hypotheses, and validate against ordinary monolithic references.
   Develop and measure the shared immutable source attachment required by §20.4;
   replay of a small fixture alone does not prove that storage requirement.
   Cross-check §20.12 and resolve open semantic choices as they become material.
   Keep refusals explicit where a requested form has no qualified implementation.
4. Complete the required manual entry points and update the walkthrough to cover
   every intended user operation, including limits, errors and corrected retries.
5. Run the final appropriate automated gate and the manual walkthrough on the
   packaged candidate. Record limitations and results, then prepare the changes
   for review and integration. Publication and merge remain separate actions.

## Completion criteria

- Every intended requirement from the recovered specification is implemented
  and evidenced, or an exclusion has been explicitly agreed with the user.
- A clean manual environment can be prepared from documented steps; users can
  invoke every intended operation and inspect opinions and both conflict sides.
- Several successive conflicts, independently supported caches, protected Q,
  source/Q revision boundaries and corrected retries have visible expected
  results. Q and source storage remain unchanged after query-only workflows.
- Complete, partial, unsupported and budget-refused outcomes are distinguishable;
  historical proof display does not grant fresh replay permission.
- Documentation, executable candidate and qualification agree on the supported
  language, branch semantics and available interfaces.
