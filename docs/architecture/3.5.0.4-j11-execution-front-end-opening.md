## Pipeline under review

```text
source text
    |
    v
Parser
    tokenization, precedence, arity and AST normalization
    |
    v
Compiller
    AST to Rule / Domain / Function / Term / variable structures
    |
    v
Linker + Calculator
    saturation plus system/UDF operation execution
    |
    v
Analyzer
    solution/value interpretation, unresolved-branch control,
    hypothesis admission and reporting
```

## Ownership boundaries

### Parser

- owns no Mind state;
- recognizes the historical KANGER syntax and produces mutable `Leaf` trees;
- normalizes operator aliases to internal names;
- parses inline UDF declarations through the configured `User` UDF provider;
- reports source positions through `ParseErrorException`;
- does not register semantic objects.

### Compiller

- is a per-Mind semantic translator;
- registers and canonicalizes Rule, Domain, Predicate, Function, Term and
  variable structures through Mind factories;
- preserves quantifier polarity, branch-cloning order, external parameter
  consumption and function binding classification;
- does not execute functions or decide query truth;
- retains the compatibility spelling `Compiller`.

### Calculator

- is a per-Mind operation-dispatch facade;
- owns the built-in Functions and Predicates catalogs, but not semantic units;
- resolves explicit `FunctionBinding` before invoking infrastructure or Library
  operations;
- publishes calculated results through the normal FValue lifecycle;
- does not drive fixed-point iteration or own transactions.

### Analyzer

- reads the saturated Mind state;
- clears and repopulates query-local solution/value stores;
- recognizes calculated and opposite-polarity coincidences;
- rejects incomplete unresolved query branches unless a calculated result
  closes the query;
- admits hypotheses only when the primary result is absent;
- does not mutate persistent Rule identity or replace Linker convergence.

## Frozen semantic boundaries

J11 does not authorize:

- grammar, precedence, arity or tokenization changes;
- renaming `Compiller`;
- reordering Rule tree cloning or quantifier translation;
- changing `FunctionBinding` resolution or legacy fallback order;
- changing built-in operation return conventions;
- changing Analyzer candidate ordering, query closure or hypothesis policy;
- turning Parser, Calculator or Analyzer into transaction owners.

## Documentation targets

```text
org.kanger.compiler.Parser
org.kanger.compiler.Compiller
org.kanger.calculator.Calculator
org.kanger.Analyzer
```

`Functions` and `Predicates` are large built-in operation catalogs. Their
registry role and invocation contract are documented through Calculator in this
stage; individual public operation methods belong to the public API audit.

`Leaf`, `Token`, semantic units, stores, enums, exceptions and public interfaces
are intentionally assigned to `3.5.0.5 — public API documentation audit`.
Vendored Mozilla Rhino sources and test/diagnostic runners are outside KANGER
architectural documentation ownership.
