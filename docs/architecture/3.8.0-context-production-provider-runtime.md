# Stage3r: production DUMB2 candidate facade

ContextProductionSnapshotSession moved from qualification to the DUMB2 production
module with its owning-thread, settled-root, complete topology, exact pin/view,
before/finally freshness and consumed publication-lease behavior retained. Its
only external runtime dependencies are the Core APIs extracted in stage3q. It
remains internal; tests and reference executors stay in qualification.

DB now exposes two explicit bounded operations:

- qualifyProductionCandidate(source,statement,rows,rounds,depth,work,events):
  acquires a fresh lease, prepares and qualifies the detached candidate, then
  closes the lease. Returned evidence is historical, not a reusable write permit.
- writeProductionCandidate(source,statement,rows,rounds,depth,work,events,logging):
  rejects immutable revision authoring, acquires a fresh lease and independently
  qualifies before reaching ordinary native query publication. The provider
  returns PUBLISHED, COLLISION, INCOMPLETE or NATIVE_REJECTED, with immutable trial
  evidence and actual before/after physical revision references.

No supplied historical Artifact is accepted by the write API. INCOMPLETE never
falls back to an unchecked write. The native transaction still performs its
existing local/connection commit validation. Native settlement errors propagate;
the bridge never rewrites an applied post-settlement error as safe rejection.
Default query/compile and commit hooks remain unchanged. This explicit API does
not claim unrestricted language admission or new command/HTTP transport.

## Artifact isolation

ContextProductionProviderJarRunner uses the public provider facade. It is also
compiled/run with only Core and DUMB2 artifacts, without qualification, bootstrap,
command, Console or Server dependencies:

```
javac -cp kanger-core/target/kanger-core-3.3-SNAPSHOT.jar:kanger-data-dumb2/target/kanger-data-dumb2-3.3-SNAPSHOT.jar \
  -d /tmp/k3-stage3r-provider-only \
  kanger-qualification/src/org/kanger/storage/dumb2/ContextProductionProviderJarRunner.java
java -cp /tmp/k3-stage3r-provider-only:kanger-core/target/kanger-core-3.3-SNAPSHOT.jar:kanger-data-dumb2/target/kanger-data-dumb2-3.3-SNAPSHOT.jar \
  org.kanger.storage.dumb2.ContextProductionProviderJarRunner
```

It checks actual current-family diagnosis without publication, unsupported/query
refusal with unchanged state, native publication and physical revision receipts,
local consequence query, close/reopen, unrelated Mind and pending child refusal,
immutable revision refusal, and delayed family collision before physical writes.
The earlier internal lease and authoring bridge runners continue to check stale
initialization/topology, thread affinity and consumed authority.

## Remaining integration

Production placement is now complete for this scoped engine and explicit owning
provider path. The next correctness prerequisite is signed/foreign-primary-fact
coverage required by the original masked counterexample and its unrelated
foreign-only disagreement control. Only then can default write/commit/topology
gates be redirected without treating an unsupported case as either successful
qualification or a proved collision. Default authoring contract remains
RED56/2. Question3 and broader language/TRUST/new-witness coverage remain open.
