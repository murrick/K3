# Fresh ground/universal checks at native commit (stage 3bl)

Ground and universal explicit writers now qualify the actual prepared native child
before settlement, following the witness writer's stage3bk boundary. Their earlier
staged trial (and universal staged audit) alone never authorize native publication.
The existing successful-write result still reports that staged diagnostic evidence;
it does not relabel staged Sources as the actual native or published revision.

The common control is now package-private ContextPendingNativeWrite. Witness,
ground and universal evaluators share one implementation of baseline acquisition,
thread/source/current ownership, exact single ordinary child requirement, pending
snapshot acquisition/rechecks, child identity binding, refusal invalidation and
finally-close. The provider has one active attempt across all three kinds, so a
nested writer cannot replace another kind's attempt. The native validation and
close methods are final; only qualification and typed incomplete construction vary.
No caller supplies a historical proof, verdict or public mode flag.

Ground and universal writers consume their original settled lease, enter a fresh
owned scope and call the original source.query once. Baseline comparison guards
parent and initialized foreign inventories and exact connection object identities.
Fresh complete native binding uses the actual proposed child and actual cuts.
Ground runs ContextGroundClauseFamily with its own round/local/depth/work/event/
probe/model limits. Only GROUND_FIXED_POINT proceeds: its unchanged shared recipes,
local reduction/composition coverage and separately checked models retain the
existing certificate semantics. Ground cannot silently accept universal variables.
ContextGroundProductionCommitException retains the full ground Evaluation, including
complete collisions or incomplete reason/rounds; legacy string pairs remain empty.

Universal runs the existing pending universal family inspection plus independent
FamilyAudit with its own preparation/event/inference/instance/model/audit limits.
The standalone strict adapter and explicit universal scope now share one verdict
mapping helper, preserving verified complete CONSISTENT, audited COLLISION and
INCOMPLETE distinctions and full evidence. No default parameter set replaces the
owning explicit operation's limits.

DB.validateCommit uses the active operation's evaluator, and rechecks its held
pending lease after existing legacy validation. The strict adapter routes that same
scope without starting a second native transaction. Repeat validations for one
unchanged live child only recheck the lease. Qualification/snapshot refusal poisons
that attempt; a different, released or edited child cannot reuse it. Wrong-thread
calls are denied before borrowing the owning scope. Finally clears the scope on
success, pre-settlement refusal or post-durable failure, preserving native outcomes
and original causes without retry or an alternate publisher.

New native controls cover both actual explicit writers and reopen primary inventory;
strict-hook routing with one original commit; masked barrier2 collision in both A/B
orders with complete ground proof or verified universal audit; own round limit;
universal independent audit limit; ground model limit without a certificate; ground
refusal of universal variables; refused-attempt reuse; repeated immutable validation;
cross-kind nested attempt; wrong thread; post-qualification pending edit; released
child/replacement; exact same-metadata reconnection; and real writer COMMITTED flush
failure with original cause, no retry and durable exact primary set. Existing witness
controls exercise the extracted common lifecycle as well.

Ordinary default validateCommit is not switched at this checkpoint. All three
explicit writer routes now have a fresh owning native boundary, but supported-scope
behavior for ordinary native authoring still requires a deliberate decision.
Unsupported residual/witness/function language is not silently admitted. General
coverage and question3 remain open; no claim that the default authoring contract
or the whole DMZ is complete.

Stage3bm follow-up: a separate ordinary pending-policy adapter now selects from the
complete bound native family, preserving each explicit scope's engine/limits. It
has not replaced the default; a legal existing nullary primary proves a compatibility
blocker in current binding. See 3.8.0-context-production-automatic-pending-policy.md.
