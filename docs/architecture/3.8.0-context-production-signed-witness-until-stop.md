# Signed witness bounded advancement until qualified termination — stage473 (2026-10-30)

The new explicit driver combines one-transition grouped advancement, four-inventory Source/
minimum-depth change checks and actual final-barrier stopping qualification. It returns
QUIESCENT only with the actual stopping receipt, REFUTED only with complete all-cut owned
proofs, or INCOMPLETE without start/output/history/terminal/stopping prefixes. Reaching the
round/generation cap after progress is INCOMPLETE, never equilibrium or a contradiction.
It stops at the first qualified unchanged transition rather than consuming the maximum.

Every completed progressing transition uses its actual audited grouped one-round receipt as
the next input. A nominally unchanged transition still requires the full Stop contract. A
Stop refusal is never parsed as a conflict: only a fresh typed all-cut grouped refutation can
reject; otherwise the driver fails closed. Final scope, terminal proofs, stop receipt and
exact maximum/row/kernel/local request identity are bound in the termination ledger.

The direct overall inspector does not run this controller. It replays actual child receipts,
consecutive inputs and Source-grade flags, rejects ignored earlier unchanged transitions,
and authenticates the exact final Stop receipt or terminal rejection. This same complete
history audit runs before a positive result is exposed. Public inspect/check starts its own
fresh invocation before minting/rechecking an overall termination receipt.

## Bounded invocation authentication and child verification

Concrete prototypes exposed repeated historical replay: a two-transition native five-Source
scenario exceeded120s, and then the final certified transfer hit its existing witness work
quota. The final implementation does not increase either quota. It uses bounded invocation-
owned authentication of already verified immutable lineage scopes, plus the EXISTING certified
transfer/product validation-reuse APIs under their original work bounds. No inference rule,
Source minimum or required proof check is removed.

Scope checks still preflight complete consecutive metadata/cycles before reuse. Memo keys are
actual receipt identity, requested audit work/capacity and captured frame references/policy.
Only completed successful semantic checks are reused. Scope-authentication reentrancy,
frame change or failure poisons the invocation memo. Owner-thread, bounded entry count, explicit memo-operation budget and lexical
close prevent cross-call reuse. Close clears all entries; nested invocations are separate.
No live-provider/currentness/write authority is cached. Outside an explicitly owned invocation
scope checks retain fresh replay. Detached graph immutability is a precondition, not a hostile
serialization or in-place concurrent-mutation guarantee.

Grouped successor and stopping transfers use the existing bounded validation sessions with
the requested capacity. The legacy three-argument merge keeps its original no-reuse policy;
ordinary paths remain ordinary. Child inference/transport/audit quotas remain separate; the
memo counter is not a new aggregate inference-work limit.
