`checkCertificate` runs the EXISTING full grouped-local certificate checker inside

## Exact key, lifetime and trust boundary

The memo uses actual Result IDENTITY, never clause equality or Source subset,
and a separate EXACT maximum-depth key (0..64). A header guards actual input/common/
local/private/unit/compound/grouped-base/grouped-manifest/proof/empty-proof references,

The policy namespace is ONLY the compiled FrozenConstraints.check authentication
predicate. Other candidate/closure/product policies still execute outside it.

The normal detached data model is immutable: constructor-copied final collections,
final proof/receipt parent links, captured ordinary semantic values and native

snapshots still require their existing acquisition/current-view authority outside

Reflection corruption BEFORE a pass or BETWEEN passes must face a fresh checker;

## Completion, refusal and bounds

A miss reserves an IN_PROGRESS entry before executing the entire old authentication
body. The entry becomes reusable ONLY after normal return through groupedCoverage;
no catch/finally exit is confused with success. A reserved recursive key is rejected,
not treated as a coinductively valid proof. Full-cache misses execute ordinary real
authentication; they are not considered covered or omitted. No eviction by logical
subsumption or source/grade pruning exists.

Every lookup, including a hit, consumes one actual work tick. Scope work limits are
unchanged counting budgets; cache capacity is1..4096 Result/depth keys including
reservations. Once full, verification falls back to the original body. Cache size
never controls a logical acceptance shortcut. Any failed/interrupted authentication
poisons the scope, clears all earlier completed entries and prevents further use.
A later bad batch request or certificate failure returns no successful Metrics;
try-with-resources releases all retained graph references on every exit. A callback
cannot be used after scope close or on a different thread.

There is intentionally NO memoization of saturation, fresh candidate scans, manifest
completeness, products, four-pool stability or family qualification. Their existing
validators still execute. Closed=true and normal authentication are not enough to
claim those stronger properties. Metrics are not evidence for them.

## Why reuse preserves the authentication predicate

For fixed immutable graph F(r) and depth d, a completed old check establishes the
same authentication predicate P(F(r),d) every time. First misses run that whole body.
A hit has the identical actual r/depth and unchanged frame, within the same trusted
invocation, so P remains established. Failure never creates a completed entry and
invalidates the session. A new invocation starts empty. Capacity exhaustion merely
repeats full checks. This is an induction over successful entries, not a proof by
assuming an in-progress dependency valid.

The resource behavior can improve because redundant work is avoided. It is not a
promise that old and optimized paths refuse at identical small work limits; a work
limit is cost, not an additional logical axiom. Strict depth, whole physical Source
sets, rigid Origin identities and closure/product obligations are unchanged.

## Concrete controls and measured improvement

`ContextUniversalValidationSessionRunner` has39 reported checks. An actual local
certificate from the prior grouped-chain fixture needs85964 plain callback attempts;
explicit session checking needs2832, with55 hits/12 fully authenticated keys/peak12,
same64000000 work bound. This is about30.35x fewer counted callback attempts for
THAT certificate, not a global runtime benchmark or removal of the controller limit.

Controls include:

- Same actual frame/depth reuses exactly one tick; equal-content different Result
  requires a real check. Another depth requires another authentication; depth0
  refuses after a looser success. Capacity1 stays bounded and performs real fallback.
- Failure clears all earlier entries; subsequent use of even an old valid frame
  refuses. A new result with an authentic but WRONG physical Source cannot be stored.
  Repairing the object and checking in a FRESH invocation performs real validation.
- Scope close clears entries; escaped callback and cross-thread work refuse. Another
  invocation with work1 cannot exploit an earlier successful invocation. Missing late
  request/certificate evidence publishes no success. Invalid work/cache bounds refuse.
- Equal contents but a different actual common Packet cannot reuse an old cached
  frame. Fresh sessions reject post-success forged depth and complete manifest loss.
  A forged self-grouped Result is not accepted as an in-progress success.
- Two distinct private binders of the SAME physical Source/grade remain distinct;
  proof inventory is unchanged. A real sourced refutation remains a refutation after
  successful proof authentication. No private result is made common by this helper.

A test-only empty Source construction initially failed in the Support constructor,
so the actual poisoning test uses a nonempty authentic foreign Source replacing the
correct one. This tests physical attribution rejection rather than constructor input
