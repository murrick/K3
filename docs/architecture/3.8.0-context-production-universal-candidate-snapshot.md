# Stage3aw — fresh read-only universal candidate diagnostics

`ContextUniversalCandidate.qualify` stages exactly one actual assertion using the
existing native `ContextProductionCandidate.stage`, then evaluates that exact
staged snapshot with `ContextUniversalFamilyInspection`. It supports the flat
ordinary universal relational scope already checked by stages3at–3av. No new
native write capability, default authoring hook or fallback is introduced.

## Exact staged identity

The artifact retains the actual base snapshot and its context/revision, a fresh
private staged view, the candidate's distinct authenticated primary Source, an
explicit mapping of every original X Source to its rebuilt staged occurrence and
the unchanged foreign snapshot identities. The resulting family certificate or
collision input refers to staged X, never unstaged base. Another trial gets a
fresh view/identity. Neither a successful model nor a staged artifact is a write
lease. INCOMPLETE may retain a fully prepared historical staging artifact, but
never a partial family certificate/collision proof.

The staging boundary remains one complete assertion: no queries, multi-assertion
scripts, duplicate/replacement occurrences or unsupported whole native clauses.
An empty actual X needs no synthetic seed. Native staging preserves its existing
per-operation preparation work/event bounds. The separately named inspectionWork
is one shared allowance across the entire factored family evaluation, including
all rounds, models and independent final rechecks. This change does not claim a
single aggregate work budget for native binding plus staging plus inference.

## Owned provider freshness

`DB.qualifyUniversalProductionCandidate` opens an owning snapshot session. The
new `ContextProductionSnapshotSession.qualifyUniversalCandidate` executes under
the provider monitor and checks current authority before binding and in finally
after qualification. It reuses existing exact inventory/family capture:

* active settled physical source and owner thread;
* exact X context/revision and connection topology;
* complete original-row fingerprints;
* exact pinned source revisions and private initialized view fingerprints;
* no TRUST view flattening or repeated source context.

A separately advanced foreign HEAD does not invalidate a deliberately pinned old
view or leak new knowledge into it. Changing X, private initialization or topology
invalidates the old lease. Close/cross-thread access refuses. Results remain
historical after return; there is no API accepting them for publication. Fresh
binding/staging use existing native per-operation preparationWork/preparationEvents
allowances; inference gets its explicit separate inspectionWork allowance.

## Controls and next boundary

The Core driver checks exact staging/rebasing/foreign identity, all-value generic
consequences, repeat-trial isolation, source-bound collision, empty-X factoring,
invalid assertion shapes and both preparation/inference limits. Original caller
inventories remain unchanged. The provider driver checks the actual masked
left/right->p counterexample with a universal candidate, safe universal models,
physical identity/pins, lease lifecycle, source/private/topology invalidation,
foreign HEAD isolation, TRUST refusal, source presentation stores and reopen.
Only explicit fixture edits become durable. All fixtures use disposable storage.

Validation totals are recorded in the main checkpoint. Manifest counts are only
registrations, not a full DMZ run. Default authoring remains unchanged (last
stage3r RED56/2); native residual/witness/function scope and question3 stay open.

Next: candidate verdict/source applicability and transactional handoff requirements
before enabling any explicit universal writer. Historical consistency evidence
must not become a reusable publication capability.
