# Stage3o: detached native-bound candidate trials

## Purpose and identity

The previous lease can qualify its existing native-bound family, but does not
accept an uncommitted assertion. ContextProductionCandidate supplies a separate,
immutable single-assertion trial without first publishing that assertion in X.
Its Artifact is a historical diagnostic, never a publication authorization.

Preparation validates base/foreign snapshot identities and the single complete
assertion boundary. It preflights the candidate alone in a private native Mind,
then rebuilds every base primary declaration in another private Mind and adds
the candidate there. Each append must preserve all previous primary IDs and add
exactly one actual primary occurrence. Duplicate/replacement operations and
multiple statements are outside this append-only scope.

The rebuilt base is native-bound and compared against every original Entry
before adding the candidate. The final staged inventory is bound again, and
whole signed clause shape or global witness sharing is checked for every original
Entry and the separately parsed candidate. Generated caches are rebuilt by the
native runtime and remain excluded from primary source evidence.

The staged view retains X's actual context/historical revision, but has a distinct
inventory fingerprint including a per-trial identity. Actual rebuilt native IDs
are not represented as original physical IDs: an immutable complete map records
original Source -> staged Source. The candidate has a separate actual staged
Source. Foreign snapshots and their initialized pin/source identities are reused
exactly. The final family is assembled through the existing complete row ledger.

This is declaration/semantic correspondence in the already supported native
binding scope, not a portable clone of the full runtime graph. Unsupported native
binding, missing/replaced primaries, local native compilation refusal or bounds
produce no prepared Artifact. A successful parse/preparation can still yield
INCOMPLETE in family qualification. Local native refusal is not relabelled as a
sourced family collision without proof.

## Owning storage bridge

DUMB2 production snapshot lease.qualifyCandidate performs bind -> prepare ->
family evaluate under the provider monitor and initial/final freshness checks.
A closed lease or changed source/topology/effective initialization refuses.
Preparation itself only uses detached bound snapshots and private runtimes;
physical X and foreign Minds are not candidate compilation targets.

Results remain COLLISION / scoped FIXED_POINT / INCOMPLETE. They carry the
immutable trial receipt when prepared. They do not append or commit a rule,
advance a revision, or lift transient family products into durable X.

## Controls and remaining work

The candidate runner checks exact source rebasing, no candidate/base alias,
original foreign authority, independent trial views, immutable receipts/lists,
actual depth2 cross-cut output, delayed sourced candidate refutation, physical
inventory preservation, local refusal, wrong roles/repeated contexts,
query/multistatement/duplicate rejection, row/work/event/round boundaries and
unsupported universal unit coverage. A first ground fact may supply the seed
for an otherwise empty base; a candidate without any supported resulting seed
anchor still cannot qualify.

Real DUMB2 trials qualify a safe rule and refute a delayed-collision rule while
preserving revision and rule count. Trial receipt binds the exact leased base
fingerprint. Closed and privately changed effective-view leases cannot qualify
a candidate.

Main/Core/DB provider implementation is unchanged. Ordinary authoring gate is
still last RED56/2 and is not wired to this diagnostic API. Next: authoring
integration with explicit handling of unsupported qualification, freshness and
atomic publication. Question3, general foreign primary facts, signed/TRUST/new
witness coverage remain open; FIXED_POINT is only for the supported supplied
family, not unrestricted language admission.
