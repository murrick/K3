# Stage3as: checked factoring in immutable local steps and family barriers

The stage3aq diagonal counterexample now has an actual source-bound refutation
through the new opt-in factored path. The old unit-only and binary-only APIs
remain unchanged and retain their prior explicit incomplete boundaries.

## One immutable resolution/factoring step

ContextUniversalUnitLedger.stepFactored runs unary factoring, unit resolution
and compound resolution over the SAME immutable input rows. Every factor uses
the stage3ar whole-owner authentication and all actual Source alternatives,
retaining parent.depth+1. All conclusions merge only into the successor ledger.
New factors cannot become donors in the same step. The ordinary min-depth per
whole-source group, clause/proof caps and no-new-Source invariant are unchanged.

Before any successful Step, independent unit, compound and factoring obligation
audits all complete under the SAME work budget as enumeration, MGU/proof building
and row merging. Even an already observed opposition is not returned before all
three audits finish. Any later error discards unit/compound/factor evidence and
opposition prefixes. Successful steps expose immutable factoringEvidence and an
explicit includesFactoring flag; failures retain no inference prefix.

## Actual diagonal refutation

X @x @y p(x)||p(y), A @x @y ~p(x)||~p(y):

1. Step1 proves actual generic p and ~p, each with its one original Source at
   depth1, and inserts both into a new sealed ledger. There is no same-step
   opposition because neither fresh result can be a parent yet.
2. Step2 proves typed unit opposition with exactly the two original Sources and
   cumulative depth2. All three obligation audits complete before it is exposed.
3. inspectFactored returns that X-dependent private proof. The FIRST complete
   common barrier rejects the theory; missing self/other receipts still force
   INCOMPLETE, even when another cut has already proved the opposition.

This closes the specific proven incompleteness from stage3aq in the factored
inference mode. It does not redirect the default writer or turn pool stability
into an automatic general admission certificate.

## Family closure and independent scope

ContextUniversalUnitRounds.inspectFactored repeatedly runs these immutable steps
under bounded local rounds/depth and a shared opening/step/three-audit allowance.
Receipts explicitly record both includesCompounds and includesFactoring. Only
positive-depth X-dependent rows export; foreign-only factors remain local.
The existing exact-input complete-family barrier and generic carrier replay use
those actual sealed rows without constant sampling or depth reset.

ContextUniversalFamilyCoverage adds FACTORED_CUTS/FACTORED_STABLE_SHARED. It
requires both receipt and stable-step factoring flags, reruns the independent
factoring audit and verifies that every proved factor is actually retained with
the same whole-source group and no greater minimum depth. All previous original/
common inventory, recipe stability, unit/compound coverage, export and exact-family
checks remain in force. The stable factored mode requires an unchanged common
merge. The old STABLE_SHARED mode keeps its conservative unresolved-factoring
guard; binary-only receipts cannot certify the new mode.

Handled same-sign clauses therefore pass the new mode through actual proof and
retention checks, not by disabling a guard. Every success reason still explicitly
states satisfiability and write admission unknown. A collision cannot pass any
collision-free coverage mode.

## Concrete transport/separation controls

* Positive p(x)||p(y) factors to generic p with the original X Source/depth1.
  Its first common carrier round must still be qualified in all cuts before
  stable factored coverage succeeds.
* Adding A p→q and B ~q(9) proves the exact three-source collision at barrier2
  in either sibling order. The factor-derived universal result covers value9
  without requiring it in the producing cut.
* With unrelated X, foreign positive and negative diagonal clauses factor
  separately but export nothing and do not collide across siblings.
* A foreign positive diagonal clause factors to private p; X p→done produces
  X-dependent generic done with two Sources/depth2. p itself is not exported.
  B ~done(9) then yields the exact three-source barrier2 collision.

The driver additionally covers all three exact-input audits, no same-step feeding,
late bound failure after successful factor proofs, strict mode/stale evidence,
incomplete-family collision blocking, local-round/work/depth limits and immutable
factor proof lists. Final counts are in the main checkpoint/journal.
