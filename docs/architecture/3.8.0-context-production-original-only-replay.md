# Stage510: original-only reconstruction of dependent Horn products

The dependent Horn candidate can now be captured as a bounded historical packet and rebuilt in a fresh process from original assertions and a supplied derivation recipe. Generated rows, bindings and proof traces are recomputed; none is loaded as an axiom. The actual pending DB session exposes the capture under its unchanged owning/currentness/physical-member guards. No DB schema or durable generated-fact store was added.

## Packet boundary

`ContextDependentProductionReplay` uses a separate `K3HP/version1` format. The older unit/refutation `K3DP/version1` capsule is unchanged and does not decode Horn recipes. A Horn packet contains:

- The captured context/revision and historical effective-view fingerprint.
- Every whole original occurrence, in source-ID order, with exact UTF-8 assertion text.
- The finite search capacity and ordered Horn steps, each naming a whole original rule and original-unit or earlier-product donors.
- The expected final canonical audit digest from the checked original/product/donor/refutation graph.

There is no generated-row section, serialized application graph, scalar-CVar descriptor, current binding or decoded conflict claim. An original manifest may include uncommitted assertions from a captured pending view. Its rows are assumptions of that historical candidate, not assertions that those rows were already admitted at the parent's stored revision.

Capture first runs the full stage509 native/origin-bound inspection. It encodes the packet and then independently reopens those exact bytes before returning `Saved`. `Saved.bytes()` is detached; its separately retainable SHA256 pin covers the entire packet. An unsupported or unroundtrippable original cannot escape as a successful saved artifact.

## Reader reconstruction

The reader checks the externally supplied pin before parsing. It validates format/version, strict UTF-8, length/count bounds, ordered distinct occurrences, exact original donor membership, backward-only product indexes and end-of-packet consumption. Reader policy independently limits bytes, originals, recipe/depth, nodes, work and maximum allowed search capacity; the packet cannot raise those limits.

The original manifest labels historical Sources. A fresh Mind compiles every original, builds an explicit old-occurrence-to-new-native-ID bijection, and refuses additional/deleted/compiler auxiliary rows. The Horn kernel then reconstructs all generated units and both original/final finite-pool unit-refutation passes. A second fresh reconstruction repeats that work. Their full canonical audit digest must agree with the saved claim before any public result escapes. Source IDs, witness declaration coordinates, dependency parameters, late bindings, typed values, Source supersets and generation grades survive native-ID changes.

`ContextDependentProductionInspection` now uses a common immutable original manifest for live inspection and historical reconstruction. Live capture still pairs actual native rows with compiler copies; a reader has original text under the file pin, not a live native provider to reauthenticate. The original captured native-view fingerprint remains a historical coordinate: it cannot be recomputed as a current physical-native fingerprint from source text alone.

## Authority and persistence scope

A pin identifies historical bytes, not a physical provider, current revision, TRUST cut, accepted candidate or future write lease. Reconstructing the graph does not grant eligibility for native publication. A matching pin for a false graph still fails reconstruction; a newly supplied pin for a wholly different valid knowledge set is a different historical input, not provider authentication.

The file preserves one supplied recipe, not automatic Horn saturation or branch/family completeness. Final unit-refutation absence is still not a consistency/model certificate. The private typed candidate remains outside legacy `Term`/`RuleFactory` storage. Actual child attachment, query/runtime integration, per-cut synchronized transport and independent original/actual-final/model admission gates remain open; mixed/default guards are unchanged.

The component returns complete byte artifacts; file replacement, fsync, crash recovery and managed DB-file lifecycle are not implemented by this codec. Tests write ordinary temporary files and verify fresh readers, including a reader started only after a separate writer JVM exits. Source and graph limits are per-phase safeguards, not a preemptive compiler time/heap guarantee.
