## `Index.emptyIndex` resolution

The initial audit classified `Index.emptyIndex` as a probable dead-state candidate because the first local pass did not identify an active read path.

Later full-source inspection superseded that hypothesis. The map is populated from deleted block heads while opening an index and when live blocks become empty. It therefore records storage-allocation/bookkeeping state associated with reusable or deleted physical blocks.

Final classification:

```text
Index.emptyIndex
  retained storage bookkeeping state
  not approved for dead-code removal
```

The earlier `U/D1` classification must not be used as removal authority.
