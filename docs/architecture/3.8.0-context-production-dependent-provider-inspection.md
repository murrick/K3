# Stage508: provider-owned dependent local-X inspection

`ContextPendingProductionSnapshotSession.inspectDependentLocal` now runs the dependent proof/capsule path on an actual prepared child under the existing owning DB lease. It checks currentness before and after, retains the existing parent/child/retained-owner and all initialized physical-member baselines, and reuses the provider's qualified execution topology. It never reserves, settles, commits or publishes a child.

## Storage boundary: actual rows and stable private matching

A concrete integration attempt showed why the in-memory adapter cannot be dropped directly onto a storage-backed child. For the inherited persisted `!anchor(1);`, two `child.getRules().get(id)` calls returned different Java objects, while newly compiled child rows were stable. The original strict prenex observer correctly refused the persisted object (`Different native prenex observation owner`). Evidence: `/tmp/k3-stage508-owner-probe.log`. This is a boundary mismatch with the adapter's identity contract, not a claim that DB hydration is incorrect.

The bridge checks each actual whole original against a fresh compiler-produced copy before any matching. Positive units use native prenex/dependency observation; ordinary headless originals use the shared whole-branch shape extractor. Role, typed constants, variable sharing, binder ownership and dependency coordinates must agree. Every original is included; source text alone is insufficient. Tests with a fresh inventory stamp but mismatched native/text producer or receiver refuse.

The new `observeFactoryRow` fetches its row internally from the actual factory and does not accept a caller-supplied Rule object. The original `observe(Rule,...)` and matching-arena owner identity requirements remain strict. Source and scope validation is separated from operational matching: the latter runs on canonical private copies, so no live TValue binding or generated fact needs to be installed in the pending child.

`captureProjected` writes the actual provider inventory coordinate, original occurrence IDs and view label into the existing version1 capsule, with a complete native-original-to-private-copy bijection. It checks all whole origin texts, cardinality and injectivity. The graph and recipe refer to original ordinals; private operational IDs never replace source identity. The ordinary unprojected capsule API remains compatible and is requalified.

## Provider and authority scope

The new public core facade `ContextDependentReplayInspection` is a read-only diagnostic. Its request names an exact receiver, branch and producer/pivot sequence. It performs whole native/text binding, checks the actual inventory before/after, captures a projected capsule, and independently restores it before returning immutable historical evidence. Returned Sources use the actual pending view, including any uncommitted rows; they are not lookup claims about rows already stored at the parent's physical revision.

The internal storage method fixes the Mind and inventory from the existing owning pending session. Callers cannot substitute the source, row bound or topology. Parent/retained ownership, active caller/thread, source revision, connection instances, initialization and every physical foreign inventory continue through the same guards. An unrelated advance of a foreign HEAD leaves an already pinned immutable revision valid; changing the actual initialized layer invalidates the lease.

This operation proves one supplied **local-X chain**. It does not enumerate a branch family or import separate A/B members into one theory. The lease still guards both physical members of a TRUST group; local proof Sources do not borrow either member. Closed and partial branches remain historical diagnostics, not eligibility, saturation, consistency or publication receipts. The API accepts no saved result as future writer authority. Detached historical replay remains possible after the live lease is stale or closed.

Existing `requireCurrent` remains unchanged. There is no relaxation of physical-view checks to accommodate a mutating legacy Linker, and no claim that the inventory hash snapshots every private inference cache. Live matching mutations are avoided by the private projection. Integration of generated productions into an actual candidate still requires their qualification and the original/independent actual-final gates.
