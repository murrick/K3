# KANGER 3.5.0.4 — J8 Linker checkpoint balance invariant

## Proven defect

`Linker.linkDomains()` opened paired local checkpoints in `TValueFactory` and `FValueFactory` for every opposite-polarity domain candidate.

Before the correction, only two outcomes closed those frames:

```text
new substitution -> commit
explicit failure -> release
```

Two successful/no-op outcomes did not close either factory:

```text
successful ground-domain match -> Rule/Domain used state survived, frames leaked
substitutable match with no new TValue -> candidate dumped, frames leaked
```

The leak was not merely unused memory. Every `mark()` created six correlated LIFO frames:

```text
TValue cache checkpoint
TValue additions journal
TValue action snapshot
FValue cache checkpoint
FValue invalidation journal
FValue action snapshot
```

Later commits and releases therefore operated inside stale outer frames rather than at the intended operation boundary.

Thus one simple ground query leaked four operation frames in every correlated stack.

## Minimal correction

```text
c6420fa99930300d8d7d1aeef72d301434bcd3fd
Balance Linker local checkpoints
```

The production diff contains four added calls and no deletions:

```text
successful ground/no-substitution match -> commit TValue and FValue frames
substitutable dumped/no-op match         -> release TValue and FValue frames
```

The existing new-substitution commit and explicit-failure release paths are unchanged.

## Preserved boundaries

The correction does not change:

```text
KANGER source-language semantics;
active Rule-set construction;
Rule candidate selection;
descending/ascending traversal order;
unification direction;
TValue or FValue identity;
used/excluded/cause classification;
deferred TSolve publication;
branch classification in linkDatabase();
materialization timing in updateDatabase();
hypothesis policy;
persistence format;
public API;
lock topology.
```

It restores only the structural invariant that each Linker-local paired `mark()` has exactly one paired `commit()` or `release()` before the candidate operation completes.

## Permanent invariant

> Every local TValue/FValue checkpoint opened by Linker domain matching must be closed in the same candidate-operation frame. Surviving substitutions or ground used-state effects commit the frame; discarded or failed speculative work releases it.

The focused runner remains a permanent KANGER CI step.
