## Architectural conclusion

Naming debt in the core is not predominantly lexical.

It concentrates at boundaries where names currently compress one or more of:

- ownership;
- lifetime;
- directionality;
- publication timing;
- cleanup authority;
- semantic versus acceleration state;
- historical compatibility.

A mechanical rename without these dimensions would improve appearance while reducing truthfulness.

Any clarification of `isValidFor()` must include:

```text
all callers
```

`linkDatabase()` is excluded from 3.5.0.2 executable work.

## Next audit front

The next search for genuine N1/N2 candidates should move away from semantic kernels and inspect narrower private implementation surfaces:

```text
factory/cache helpers
owner-local diagnostics
private reset/clear helpers
storage lifecycle names already proven behavior-neutral
```

Priority rule:

1. inspect private helper graph;
2. prove single role and single owner;
3. exclude reflection, persistence, scripting, and diagnostics;
4. only then classify N1;
5. otherwise retain as N2/N3/N4/U.
