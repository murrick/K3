# KANGER 3.5.0.3 — Escalera frame ownership invariant

## Scope

This checkpoint audits stack ownership for:

```text
Escalera.mark()
Escalera.commit()
Escalera.release()
```

It is independent of the already proven empty-root checkpoint defect.

## Observed behavior

`Escalera.commit()` and `Escalera.release()` silently do nothing when the internal stack is empty.

That behavior appears harmless for a single isolated call, but it is unsafe for nested marks because completion operations carry no frame identity.

Consider:

```text
mark outer
add A

mark inner
add B

release inner
release inner again by mistake
commit outer
```

Historical execution:

```text
first release  -> consumes inner frame; B is removed
second release -> consumes outer frame; A is removed
outer commit   -> stack is empty; silently accepted
```

A duplicate completion in the inner scope therefore consumes a checkpoint owned by the outer scope. The later legitimate outer completion cannot detect that its frame has already been stolen.

## Invariant

> Every `commit()` or `release()` must consume exactly one currently open frame owned by the corresponding `mark()`. Completion without an open frame is an invariant violation and must be rejected.

Consequences:

1. empty-stack `commit()` must not be a no-op;
2. empty-stack `release()` must not be a no-op;
3. duplicate inner completion must be rejected before it can consume an outer frame;
4. nested frame depth must remain stable until the legitimate owner completes each frame;
5. auxiliary factory stacks must follow the same depth contract as the canonical Escalera frame stack.

## Regression gate

```text
kanger-console/src/org/kanger/KangerEscaleraFrameOwnershipSafetyRunner.java
```

The runner creates a non-empty baseline, opens outer and inner frames, rolls back the inner frame, then deliberately repeats the inner release.

It requires:

```text
duplicate release -> IllegalStateException
outer frame remains open
outer commit retains outer mutation
commit with no open frame -> IllegalStateException
```

The current implementation is expected to fail because the duplicate release consumes the outer frame and the final commit is silently accepted.

## Relationship to empty-root defect

The two defects are separate:

```text
empty-root mark defect
    mark may fail to create any frame

frame ownership defect
    completion may consume the wrong existing frame
```

Both must be corrected for a strict stack protocol.

## Approved correction boundary

A future production correction should make `Escalera` enforce:

```text
mark depth +1
commit depth -1 or throw
release depth -1 or throw
```

This correction must be coordinated with nullable checkpoints for empty roots and with factory auxiliary stacks. It must not be implemented as an isolated guard that leaves cache and auxiliary depths capable of diverging.

## Classification

```text
frame ownership violation: proven
underflow policy: silent historical behavior rejected
red regression gate: committed
production correction: pending unified checkpoint-frame redesign
```
