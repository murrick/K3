# Fresh witness-family validation at native commit (stage 3bk)

Stage3bi's witness counterexample remains outside flat universal unit-family
inspection: X has `$w seed(w,1)&&flag(w,1)` and `@w seed(w,1)->warm(w,1)`, WA has
`@w seed(w,1)->q(w,1)`, candidate is `@w q(w,1)->out(w,1)`. This stage connects the
existing explicit witness writer to native validation without trusting its earlier
staged result as a publication permit.

After its existing fresh candidate qualification succeeds, the witness writer
consumes that old lease and enters one provider-owned `ContextPendingWitnessWrite`.
The scope captures the actual settled source inventory and initialized cuts, exact
connection objects, bounded limits, source Mind and owning thread before native
compilation. Nested attempts are rejected. The original source.query compiles and
commits once; finally clears the provider scope and closes its pending lease even
on a post-durable native finalization failure. The scope takes no trial/proof input.

At the actual native validation hook, the scope requires one ordinary live direct
physical-root child, exact source/current/provider/thread identity, and acquires the
existing owning pending lease. Parent and initialized-cut fingerprints must match
the precompilation baseline, including exact effective connection object identity.
It binds the complete actual proposed native inventory and actual foreign views,
assembles them with ContextProductionFamilyAssembly and executes the existing
witness family qualification. Only FIXED_POINT continues the original commit.
This is a fresh check of actual pending X; the previous candidate trial alone never
allows publication. There is no alternate write or recursive writer call.

Witness qualification retains its existing synchronous barriers, full supplied-cut
collision scans, productive declaration coverage and bounded proof accounting. It
is not the universal unit-family model/audit algorithm and this stage does not
claim to add a new independent witness auditor. Unsupported coverage and exhausted
limits fail as STORAGE_CONTEXT_INCOMPLETE. Proved clause refutation fails as
STORAGE_CONTEXT_CONFLICT. ContextWitnessProductionCommitException keeps the whole
family Evaluation; its new immutable refutations expose producer, falsified clause,
witness assignment, opponents and all Source/depth proofs plus common barrier.
Legacy string-pair collision arrays remain empty for these richer clause proofs.
The diagnostic object grants no later write authority.

DB.validateCommit performs this scoped check for the actual explicit writer even
while the default flat policy is off. The strict pending universal adapter also
routes a live witness-write scope to it. Multiple validation calls for the same
immutable live child within that single native attempt recheck the held lease,
without rerunning witness inference. After legacy validation the lease is checked
again. A qualification or snapshot refusal permanently invalidates that attempt. Wrong-thread
calls are denied before borrowing the owner's scope. A different/released child,
changed pending inventory, changed parent/view, wrong thread or closed scope cannot
reuse its completed check. Limits come from the owning witness attempt, not the flat
adapter's default parameters. No global witness admission switch is left behind.

Controls exercise the original flat refusal and real explicit writer publication,
reopen source persistence, absence of materialized foreign-dependent primary facts,
strict-hook routing with one actual native commit, full pending collision proof,
incomplete round bound, refusal reuse, nested attempts, wrong thread, released child
replacement, post-qualification child edit, private initialized-view edit, exact
same-metadata reconnection, and real writer post-durable flush failure preserving
COMMITTED/original cause/durable source with no retry. Reopen asserts retained source
and nondecreasing revision; it does not assume close creates no further revision.

This resolves the bounded witness-writer integration counterexample. Ground and
universal explicit writers retain their current routes, and ordinary default
validateCommit still uses its historical validation. Before default activation,
remaining writer routes and supported-scope behavior need the same explicit review.
General native residual/witness/function coverage and question3 remain open.
