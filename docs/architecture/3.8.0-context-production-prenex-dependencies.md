# Stage503: paired prenex scope metadata and false native conflicts

## New two-sided counterexample

Stage502 still has three missed-conflict cases in the original16-case mixed-prefix
gate. A separate actual-JAR probe establishes a false conflict as well:

```text
!@a $u @b rel(a,u,b);
!@u ~(rel(1,u,1)&&rel(2,u,1));
```

Interpret rel(a,u,b) as u=a over ALL admissible values. For every a, choose u=a;
then the first row holds for every b. The prohibition also holds: no u equals
both the distinct named numeric values1 and2. No finite-domain assumption,
Origin inequality or query/hypothesis result is used. Fresh binder identity does
not require its interpreted value to differ from a. An injective witness choice
is permitted here; the prefix does not require every choice to be injective.

Contrast with `!$u @a @b rel(a,u,b);`. It requires a single u to work for a=1
and a=2, contradicting the prohibition. Native Core rejects both prefixes.
The dependent prefix is rejected in both insertion orders and after alpha
renaming. LastCompileQualification contains actual invalid/conflict witnesses;
this is not an INCOMPLETE/resource refusal relabelled as a semantic bug.
The later-witness control `!@a @b $u rel(a,u,b);` remains accepted in both orders.

NativeWitnessDependencyGate expresses required behavior:8 cases,4 missing,
exit1. These four cases are the original/alpha false rejection in two orders,
not four independent architecture defects. This RED is separate from the original
native RED16/missing3 and required-family RED101/missing8. A refusal of a valid
input is NOT counted as a passing conservative boundary in the required gate.

## Native trace and the missing distinction

On the exact502 JAR, the linker creates both `rel(1,%2,1)` and `rel(2,%2,1)`
using the same primary witness%2, then closes the prohibition and reports two
stored coincidences. The preceding universal argument changed while the witness
identity remained shared. Evidence: /tmp/k3-stage503-false-conflict-trace.log.
The new dependency gate runs against actual native authoring, not query answers.

Both forall-a/exists-u/forall-b and exists-u/forall-a/forall-b mark u as domini.
That flag describes a later universal; it does not say whether earlier universals
are allowed witness parameters. The full native declaration indices can differ;
we do not claim all native metadata is identical. Likewise null parent is not a
proof of independence. The original positive prefix gives u's allowed parameter
scope: [a] in the first case, [] in the second. It does NOT prove that u must vary
with a; a function of a may be constant when the other rules allow that.

This counterexample requires no independent contexts or DMZ federation. It proves
a native witness projection/qualification defect, not an A-X/B-X policy change.
Simply overriding the Analyzer conflict would leave the overstrong generated
premises in the working state. Future correction must preserve parameter scope
before their joins/materialization, and also close the earlier missed-conflict
cases without turning forall-exists into one global witness.

## Detached positive-unit prefix observation

NativePrenexUnitScope is a deliberately narrow metadata foundation:

- one positive primary ordinary unit with a leading @/$ prefix;
- every binder occurs in that atom, with flat binder/fixed-value argument leaves;
- exact ordered binder kind, each existential's preceding universal positions,
  every argument's binder position or typed native semantic value;
- owner Rule, native identities, domini flags and a fresh observation UUID.

The parser AST supplies declaration order and names. Native uses independently
check binder kind, Rule ownership, repeated identity, primary parentlessness and
position: nativeIndex = Rule.getVarIndex() + declarationPosition +1. The global
allocation base is significant; indices are not assumed to restart for each Rule.
The observed domini flag must agree with the presence of a later universal, but
is never substituted for the preceding-universal vector. Arrays/vectors/slots are
detached and immutable. Source scan, vector construction and comparisons charge
work, including every dependency coordinate. No fixed arity/variable threshold is
introduced;7/17/65-declaration alternating controls are qualified.

Declaration positions are NOT witness-first-use ordinals, packet Origin indices,
native IDs or cross-context identities. Any future transport needs an explicit
bijection and the full physical Source/revision/view envelope. Shape equality
between observations does not merge existential witnesses or assert inequality
between their interpreted values. Operational IDs are scoped by observation UUID.

Conjunctions, conditionals, nested/negated prefixes, functions and unused binders
are outside this observer. Stop rather than guess a dependency AST for them.
Its structural comparison preserves prefix order and alpha-renaming; it does not
claim complete logical equivalence under arbitrary quantifier commutation.

An isolated observation alone does not authenticate fixed source text. It records
the native fixed value at a source leaf position. The QA deliberately changes
origin's fixed literal1 to2 while retaining native value1: a single observation
still reports the native shape. A fresh independent compilation reports value2,
and comparison detects the mismatch. Treating that one observation as a complete
text/native certificate would be wrong.

exact Source and checks inventory currentness. For a used witness plus universal
unit, it now obtains both observations and compares prefix/roles/dependencies/
all uses/typed fixed values before refusal. Shape/dependency disagreement fails.
A successfully matched mixed unit still fails with
`Mixed quantifier prefixes require dependency-aware qualification`.
Wider shapes retain the old bundle rejection. This is a refusal diagnostic and
checked representation foundation, NOT mixed admission or a native projection fix.

Acceptance is preserved: this branch requires a native witness AND a TVariable.
The old witness bundle extractor already refuses every such row. Accepted ordinary
clauses and closed witness bundles follow their existing paths. No Entry kind,
Scope carrier, writer, storage format, Term field, runtime dependency evaluation,
model choice or sealed admission receipt is added. The observer's output itself
contains no Source lease or authority. Existing whole-Source and final-audit
requirements remain in force; no all-Source-alternative coverage is claimed.
