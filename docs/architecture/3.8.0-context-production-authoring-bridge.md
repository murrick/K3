# Stage3p: explicit live candidate-to-authoring bridge

## Production dependency boundary

The candidate engine and provider lease currently belong to kanger-qualification,
whose pom explicitly states that production modules do not depend on it. A direct
Mind/DB hook into this module would reverse the dependency boundary. This stage
therefore adds an explicit qualification-plane bridge that invokes the normal
native authoring transaction, without redirecting default authoring.

## Live operation

ContextProductionSnapshotSession.writeCandidate requires the owning active
settled physical X and current complete family lease. Under the provider monitor
it freshly performs bind -> candidate preparation -> family qualification and
rechecks source/topology/effective-view freshness. It accepts raw single
assertion input, not a caller-supplied historical Artifact or reusable permit.

COLLISION and INCOMPLETE return typed declines before invoking the physical
Mind.query path. They do not alter physical rules/revisions or clear the caller's
presentation stores. A bounded productive prefix is not sufficient to write.
A fresh independent trial can be run with the same still-current declined lease.

Only scoped FIXED_POINT reaches the ordinary native query transaction, which
retains its local inference, provider commit validation and revision publication
semantics. The lease is consumed immediately before native invocation so the
operation cannot reuse stale authority after native settlement or an exception.
A normal false result is NATIVE_REJECTED. Exceptions propagate unchanged; in
particular a committed post-settlement failure must not be rewritten as a safe
rejection or automatically retried. This last behavior follows from using the
existing native path without catching its settlement exceptions; no new fault
injection into that path is introduced here.

The result distinguishes PUBLISHED / COLLISION / INCOMPLETE / NATIVE_REJECTED and
includes the freshly qualified trial plus actual before/after physical revision
references. The trial's staged Sources remain historical trial identities, not
identities of the newly published physical rules. Transient family proof results
are not separately compiled into X; only the original candidate statement is
sent to normal native authoring.

## Verification and limits

Real DUMB2 controls prove delayed collision refusal, unsupported universal unit
and non-authoring input refusal, round cap refusal, unchanged rules/revision and
presentation stores on declines, a successful ordinary publication with the
exact freshly qualified base, consumed authority, cross-thread rejection,
changed private view and source-removal rejection, close/reopen revision and
unchanged foreign physical pin. Rejected candidates do not become primary rules.
The normal native settlement/fault behavior is inherited; it is not newly claimed
as fault-injection coverage by this runner.

Default ordinary authoring still bypasses this explicit bridge, so the original
signed/foreign-fact authoring contract is expected to remain RED56/2. Main/Core/
DB production implementation remains unchanged. Enabling a default hook requires
extracting the supported runtime engine/provider bridge into appropriate
production modules and resolving unsupported language behavior; a fallback from
INCOMPLETE to unconditional acceptance would reintroduce the original problem.
Question3 and general signed/TRUST/new-witness/foreign-primary-fact coverage are
still open. This bridge is a concrete publication-path control, not completion
of the unrestricted ordinary authoring gate.
