# KANGER 3.5.0.2 — Naming and lifecycle alignment closure

## Status

The naming and lifecycle alignment audit is complete.

No executable rename is authorized for this stage.

This is an affirmative engineering result, not an incomplete cleanup: the reviewed names that appear generic, historical, or aesthetically uneven encode ownership, lifetime, directionality, compatibility, reflection, or legacy semantic boundaries that are not safely reducible to mechanical renaming.

## Governing invariant

> KANGER 3.5.0 must not intentionally change observable execution semantics.

A naming change is acceptable only when its semantic neutrality and complete dependency surface are proven. No reviewed candidate met the N1 threshold.

These names hide or compress semantic contracts. They must not be altered as style cleanup. Relevant findings transfer to the invariant and architectural-documentation stages.

## Vocabulary established

The audit established the following preferred lifecycle distinctions:

```text
create    instantiate a new object
register  publish into a registry or owner namespace
bind      associate a value/context without asserting graph symmetry
link      establish a graph relation
unlink    remove that graph relation symmetrically
attach    associate an externally owned resource/context
detach    remove attachment without destroying the attached object
release   relinquish an overlay/temporary ownership claim
clear     remove mutable contents while keeping the owner usable
reset     restore reusable state or diagnostics to a baseline
flush     force pending state across a persistence boundary
close     terminate an owned external/resource lifecycle
remove    delete a logical or persisted entity
destroy   permanently invalidate an object/resource
```

The vocabulary is a documentation and review constraint. It does not authorize replacing existing verbs where their exact contract is not proven.

## Important negative findings

The audit rejected several tempting but false symmetries:

```text
TValueFactory.top / current
KangerFactory.top / bottom as assumed head/tail
init / close
use / release
connect / disconnect
flush / clear
```

Stylistic symmetry is not evidence of lifecycle symmetry.

## Stage result

`3.5.0.2` closes as an architectural alignment artifact with zero intentional behavior changes and zero executable renames.

Its deliverables are:

1. explicit lifetime classes;
2. controlled lifecycle vocabulary;
3. candidate classification by risk and compatibility surface;
4. atomic rename boundaries for future work;
5. transfer of semantic ambiguities to `3.5.0.3` and documentation debt to `3.5.0.4`/`3.5.0.5`.
