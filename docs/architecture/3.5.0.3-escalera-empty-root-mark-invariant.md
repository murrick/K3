# KANGER 3.5.0.3 — Escalera empty-root mark invariant

## Scope

## Historical implementation

The historical `Escalera.mark()` recorded a checkpoint only when the current root was non-null. A mark created while `root == null` therefore had no representation in the checkpoint stack.

Historical transition:

```text
root = null
mark()
add(A)
release()

expected: root = null
actual:   root = A
```

For `TValueFactory`, this also split the canonical chain from its auxiliary rollback index:

```text
additionsStack
localByVariable index
Escalera root chain
```

The auxiliary journal removed the speculative value while Escalera retained it.

## Invariant

> Every successful `mark()` creates exactly one reversible checkpoint, including the empty-root state.

Required properties:

1. every `mark()` increases checkpoint depth by one;
2. every matching `commit()` or `release()` decreases it by one;
3. releasing an empty-root checkpoint restores `root == null`;
4. nested empty/non-empty marks remain LIFO;
5. commit preserves current root while discarding exactly one checkpoint;
6. release invalidates acceleration metadata consistently;
7. completion at depth zero is rejected.

## Production correction

The current implementation stores a nullable root inside an explicit frame object:

```java
private Stack<Checkpoint> stack = new Stack<>();

private static final class Checkpoint {
    private final IStep root;

    private Checkpoint(IStep root) {
        this.root = root;
    }
}
```

Every mark now pushes one frame, including a frame whose root is `null`:

```java
public long mark() {
    stack.push(new Checkpoint(root));
    return root == null ? -1 : root.getId();
}
```

Release restores the recorded nullable root and invalidates the acceleration index:

```java
public long release() {
    if (stack.isEmpty()) {
        throw new IllegalStateException(
                "Escalera release without an open checkpoint");
    }
    root = stack.pop().root;
    invalidateIndex();
    return root == null ? -1 : root.getId();
}
```

Commit consumes exactly one frame and rejects underflow.

This correction changes neither semantic inference nor persistence format.

## Regression gate

`KangerEscaleraMarkSafetyRunner` verifies:

- single mark/add/release from an empty TValue cache;
- nested outer-empty and inner-non-empty rollback;
- physical cache size after rollback;
- canonical TValue lookup after rollback;
- preservation of the outer value after inner release;
- restoration of true emptiness after outer release.

The adjacent `KangerEscaleraFrameOwnershipSafetyRunner` verifies nested LIFO completion and underflow rejection.

Both runners are invoked by `KANGER CI`.
