# KANGER 3.5.0.3 — Escalera empty-root mark invariant

## Scope

This checkpoint audits the shared `mark / commit / release` protocol implemented by:

```text
org.kanger.storage.Escalera
```

and consumed by all Escalera-backed factories.

Focused regression gate:

```text
KangerEscaleraMarkSafetyRunner
```

## Historical implementation

`Escalera.mark()` records a checkpoint only when the current root is non-null:

```java
public long mark() {
    if (root != null) {
        return stack.push(root).getId();
    } else {
        return -1;
    }
}
```

`release()` restores state only when the stack contains a checkpoint:

```java
public long release() {
    if (!stack.isEmpty()) {
        root = stack.pop();
        invalidateIndex();
    }
    return root == null ? -1 : root.getId();
}
```

Therefore a mark created while `root == null` has no representation in the checkpoint stack.

## Proven violation

The required invariant is:

> Every successful `mark()` creates exactly one reversible checkpoint, including the empty-root state.

Historical transition:

```text
root = null
mark()
add(A)
release()

expected: root = null
actual:   root = A
```

The problem becomes more severe when a factory maintains auxiliary rollback state.

For `TValueFactory`:

```text
additionsStack
localByVariable index
Escalera root chain
```

A mark on an empty Escalera pushes an auxiliary additions frame but no Escalera checkpoint. On release, the auxiliary frame unindexes the added TValue while the Escalera chain retains it.

Result:

```text
cache.size() / physical chain -> object present
canonical variable index      -> object absent
```

This splits the primary cache and its acceleration index into contradictory states.

## Nested reproducer

```text
outer mark on empty root
add A
inner mark on root A
add B
release inner -> correctly restores A
release outer -> cannot restore empty root
```

After the outer release, A remains in Escalera even though the factory rollback journal removes A from its auxiliary index.

## Architectural impact

The defect is shared infrastructure, not a TValue-only issue.

Any Escalera-backed factory can fail to roll back the first object created after an empty-root mark. Factories with auxiliary indexes or overlays can additionally become internally inconsistent.

Affected protocol dimensions:

```text
mark/release symmetry
nested checkpoint depth
empty-state representation
factory cache/index coherence
rollback isolation
```

No persistence-format change is involved.

## Approved correction shape

The empty-root state must be represented explicitly in the checkpoint stack.

A correction may use:

```text
nullable checkpoint wrapper
sentinel object distinct from every valid IStep
separate checkpoint record containing nullable root
```

It must not use `-1` alone as an implicit non-frame because stack depth itself is part of the invariant.

Required properties:

1. every `mark()` increases checkpoint depth by one;
2. every matching `commit()` or `release()` decreases it by one;
3. releasing an empty-root checkpoint restores `root == null`;
4. nested empty/non-empty marks remain LIFO;
5. commit preserves current root while discarding exactly one checkpoint;
6. release invalidates/rebuilds acceleration metadata consistently;
7. extra commit/release behavior must be characterized separately rather than silently changed.

## Regression gate

`KangerEscaleraMarkSafetyRunner` verifies:

- single mark/add/release from an empty TValue cache;
- nested outer-empty and inner-non-empty rollback;
- physical cache size after rollback;
- canonical TValue lookup after rollback;
- preservation of the outer value after inner release;
- restoration of true emptiness after outer release.

The runner is expected to fail against the historical implementation.
