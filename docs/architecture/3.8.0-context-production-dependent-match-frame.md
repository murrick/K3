# Stage505: whole-inventory dependent matching frame

## Adapter boundary

NativeDependentMatchFrame consumes actual compiler-produced primary rows and the
stage504 typed term projection. It performs polarity/predicate/arity matching,
propagates substitution through the ENTIRE remaining receiver clause, and retains
a verifiable chain with whole original row labels. This is an isolated frozen
matching API. No existing Linker, materializer, query, storage or writer caller is
redirected. Raw native errors and mixed DMZ refusal remain unchanged.

## Complete inventory and original binding

Construction captures one actual Mind's ContextProductionInventory, including
deleted/generated cache accounting and initialization labels. Before exposing ANY
Entry it preflights every live primary row: positive prenex ordinary units use
paired whole-origin projection capture; receivers require whole ordinary headless
clauses and matching fresh whole-origin replay. Other original shapes refuse the
entire construction, even after earlier usable rows. Generated caches are visible
in the manifest but cannot become input axioms.

An Entry is an actual original Rule, its entire origin and all receiver clauses,
or its actual positive projection root. Each receiver clause keeps its index in
that whole row; literals retain their original positions. Splitting a row into
separate Source identities is not permitted. Entry/Instance objects belong to the
exact frame; identical inventory labels in another frame do not make them usable.

Source labels are the existing inventory-local tuple (context, revision, native
row, localX, inventory fingerprint). Provider-supplied context/configuration
identity is not authenticated by this class. It is NOT a physical-member Source
transport, provider lease, cross-cut stitching, Source-alias recovery or admission
receipt. A real federation adapter must retain verified physical declarations and
all aliases/alternatives rather than relabel an imported union as one inventory.

## Matching and retained equations

instantiate creates fresh receiver variables across the whole selected negative
clause. It begins with the whole receiver Source at grade0. match accepts only a
positive unit and an exact remaining negative pivot. It checks predicate and arity
BEFORE unifying typed terms. Each positive application has fresh universal
variables and declaration-owned dependent functions. A successful unifier applies
to every other receiver literal, including every occurrence of a shared variable.
Unknown arguments remain symbolic expressions; they are not scalar C-variables.

A Match retains the producer Entry, whole before/after Instance, original pivot,
the full positive application and immutable substitution. Those two objects retain
the binding needed by later materialization; this stage does not allocate native
productions. The support is the exact previous Source union plus producer Source;
grade increases by one. Reusing one producer does not invent another Source.
Independent alternatives remain independent receipts, including Source supersets.
There is no Source minimization, saturated ledger or claim to enumerate all proofs.

No match means only that this one predicate/arity/term choice did not match. It is
not entity inequality, query FALSE, a consistency result or a coverage certificate.
An empty residual is checked data for that derivation; it is not an existing sealed
DMZ refutation/admission token and cannot be used as an explosion premise.

## Verification and freshness

verify iteratively walks the complete chain. It reconstructs the initial clause's
fixed values, variable-sharing bijection, literal positions and receiver Source0.
Each producer is reprojected from its actual root; an explicit fresh-variable
renaming must reproduce the entire recorded positive application. The verifier
recomputes unification, checks the recorded substitution's effects on the producer
arguments/binders AND matched receiver, rebuilds all residual literals and compares
the exact Source union/cumulative grade. It uses the qualified component primitives;
it is not described as an algorithmically independent final model checker.

Whole native inventory fingerprint and actual Rule objects are rechecked before
and after operations. An unrelated source change also invalidates the frame.
Failure is terminal; repairing a source does not revive its old receipts. Work,
step and node bounds refuse without a partial successful receipt. Off-thread use
refuses before mutating owner state; close invalidates the frame and its receipts.
The frame also checks the underlying arena lifecycle, so arena exhaustion cannot
leave a usable facade. Empty operations now spend one arena work unit: a specific
zero-argument accounting gap in the504 component was fixed and regression-tested.

This inventory includes native text/digests and caches. Its strict frozen check is
NOT yet a drop-in policy for a live Linker that changes current substitutions,
used flags or generated rows. Production integration must distinguish stable
original/source pins from permitted inference-local mutations without weakening
currentness. Local fingerprints do not replace real provider revision/lease checks.

## Actual-row qualification

NativeDependentMatchFrameRunner has321 checks.32 combinations cover the four
mixed-prefix controls, two receiver families and both insertion/body orders. It
uses the real adapter instead of the504 QA-only term-resolution harness. Every
successful step is verified; the native rows and owning dictionary remain unchanged.

Multi-existential controls use `!@a $u @b $v rel(v,a,u,b,u,v);`: u(a) and v(a,b)
retain different parameter lists despite body-first-use order being v before u.
A prohibition demanding the same v across b=1/b=2 does not close; allowing separate
v/w does close. The full-domain model u=a, v=b establishes the consistent control;
sharing source u across later b establishes the contradictory control.

Tests also cover:

- predicate/arity mismatches and a non-first pivot;
- exact alternative footprints, including a larger Source superset, with no anchor
  or generated-cache Source borrowed into proof support;
- two clauses of one original negative row using the SAME receiver Source;
- 17-step proof with all18 originals and exact cumulative grade;
- later unsupported originals refusing construction without a successful prefix;
- complete inventory mutation, whole receiver text tampering, bounds, closed/failed
  receipt reuse, wrong frame and owning-thread behavior;
- empty unification consuming its one-unit work budget rather than allocating
  indefinitely outside accounting.

These are compiler/native-row tests in private Minds and an actual Console JAR,
not a real database matching callback or durable projection qualification. A passing
321 does not close native RED16/missing3, false-conflict RED8/missing4 or required
universal-family RED101/missing8. Those remain separately tested and OPEN.
