# M3.12a — native causal frontier capture

The opt-in `CausalFrontierCapture.query` surface executes the historical
canonical FALSE-then-TRUE query lifecycle. It observes the root query Domain
and a Domain pair already selected by native Linker. For a two-literal native
branch, the remaining unresolved ordinary Domain becomes a detached child
query with a positional `FrontierProjection` attached to the parent pass.

For `parent(a,b) -> ancestor(b,a)`, a free `ancestor(right,left)` request
produces `parent(v1,v0)`. Parent position 0 maps to child position 1 and parent
position 1 to child position 0. Partial parent bindings become semantic fixed
arguments in the child template; repeated arguments become descriptor-local
equality classes. Conflicting fixed bindings produce no child demand.

Projection accepts a full concrete child argument vector, including fixed
positions. It rejects incompatible fixed values or repeated-variable values
with semantic equality, and returns immutable positional parent candidates.
An unmapped parent argument remains null. A candidate does not prove the
parent, populate root Values, or supply evidence. Native target reproof is
still required by SMART §§11–14.

## Boundaries

- Capture is opt-in and operation-local. Ordinary query and federation
  orchestration continue to use their existing surfaces.
- The observer does not search rule sets, recurse through productions, create
  TValue substitutions/Causes, or import foreign rules. Temporary positional
  binding is confined to the already selected native pair.
- Returned parent/child descriptors and projection contain semantic snapshots,
  query-local variable names, positions and synthetic equality groups. They
  retain no Mind, Domain, Rule, TVariable, TValue, or Context-local identity.
- Native calculated predicates, function arguments, C-variables and branches
  with compound residuals remain local. This is a qualified narrow surface,
  not a claim that arbitrary branch capture is complete.
- A free positive query's native FALSE-pass may introduce C-variables; these
  are not exported as ordinary values. Ground FALSE-pass demands and explicitly
  negative free queries preserve their actual parent and child polarity.
- A locally resolved canonical query returns truth with no unresolved demands.
  Existing Analyzer frontier, hypotheses, Values and inference counters retain
  their native behavior.

## M3.12b — exact-target response and invocation address

`LocalFrontierExecutor` now uses the opt-in native capture surface. Its full
`FrontierAnswer` carries ordinary truth, ordered values, local hypotheses and
detached unresolved frontiers with positional parent projections. Each answer
also retains the exact target revision and its `FrontierInvocation` address.

An invocation contains only an opaque operation-local response token and the
detached requested frontier. Fan-out shares one token across its exact targets;
distinct calls, even for the same semantic query, receive distinct addresses.
The exact target revision identifies which target emitted each causal edge.
The demand's parent descriptor preserves the actual native TRUE/FALSE pass,
which may differ in polarity from the original requested frontier.

The invocation token is a response address, not a semantic execution-cache
key. A future scheduler may reuse a blocked logical invocation with newly
relevant evidence; its dedup state must separately include the evidence
fingerprint required by SMART §12. This slice does not implement that cache
or the evidence-bearing request.

Aggregation and semantic lift reject a batch containing distinct invocation
addresses. Lift performs this check before creating any foreign Terms.
Aggregates, lift results and lift sessions preserve the common address;
empty response batches have no address. Resolved answers cannot carry
unresolved demands. Child TRUE therefore cannot be pooled with parent NULL.

Target execution still attaches only the requested immutable snapshot and
never follows the target ConnectionVector. Capture results survive runtime
close, and request execution does not publish or mutate any target generation.
Hypotheses remain the unchanged native provisional surface, separate from
unresolved demands and factual evidence. Federation continuation does not
schedule the new child demands yet; that remains the causal scheduler slice.

`CausalFrontierResponseTest` adds 11 executable checks: detached reordered

## M3.12c — minimal evidence-bearing request and native reproof

`SuppliedEvidence.fromAnswers` builds detached concrete facts only from a
decisive TRUE aggregate for one child invocation. FALSE, UNKNOWN, CONFLICT and
local hypotheses yield no supplied facts. Each atom preserves predicate,
polarity, typed full argument positions and exact source supports. Semantic
twins merge with their independent supports. No source Term ID, Rule,
TVariable, Mind, or storage handle enters the packet.

`FrontierRequest.continueWith` scopes the packet to the blocked logical
invocation and its exact target revision. It selects only facts matching an
immediate child demand's predicate, arity and polarity whose positional
projection satisfies fixed and repeated-argument constraints. Descendant or
unrelated facts, incompatible bindings and the parent conclusion are excluded.
Previously supplied premises in the same invocation's filtered history remain
available for reproof; the request never replays an X user layer.

The target canonicalizes each semantic atom into its isolated ephemeral Mind,
compiles the donor assertion and invokes ordinary Linker with that donor Rule
as the native indexed seed. No independent authoritative ACCEPT is performed
against generated query demand. This saturation boundary is necessary for
native free-variable Values: compiling facts without native saturation closes
ground proofs but leaves free parent queries unresolved. The canonical
FALSE-then-TRUE parent query then runs normally and returns its own proof and
values. Target connections remain local-only and all evidence is discarded
after the call. Duplicate concrete donor assertions are idempotent.

`FrontierExecutionState` identifies an alpha-equivalent semantic frontier,
exact target and relevant `EvidenceFingerprint`. The fingerprint is an exact
order-independent semantic set; hash is only a prefilter. Provenance, physical
IDs, response tokens, variable names, duplicate facts and packet order do not
change execution state. New relevant facts do; hash collisions cannot conceal
them. The response preserves this state separately from its logical invocation
address. A batch containing stale and resumed states for the same exact target
is rejected before lift. Latest responses from different targets may have
different relevant packets and still aggregate within the same invocation.

This slice supplies the execution-state value needed by fixed-point scheduling;
it does not install a scheduler or response cache. Cached alpha-equivalent
results must eventually be rebound to the requested positional variable order,
not replayed with another invocation's variable names.

`SuppliedEvidenceRequestTest` adds 16 checks for native ground/free/negative
reproof, reordered and repeated arguments, typed fixed strings, decisive-proof

## M3.12d — X-owned causal fixed point

`CausalFrontierScheduler` expands only child demands returned by native target
responses. Each alpha-equivalent semantic frontier has one logical invocation
in its operation graph; fan-out shares that address across X's exact direct
pins. Every target keeps its own minimal evidence state, latest response and
exact-state cache. Positional child facts are filtered through each native
edge's projection; variable names and foreign IDs never join branches.

Calls with unchanged relevant evidence are skipped. Each wave consumes complete
latest response batches from the preceding wave and issues independent target
proofs in parallel. Demands captured before a target resolves remain attached
to it: later child tuples must reopen even an already TRUE parent, so an early
John result cannot suppress a later Mary variant. Alpha sharing is confined
to one canonical invocation; cached values retain that invocation's order, and
full semantic argument vectors cross edges. No cached answer with another
invocation's variable names is replayed.

Cycles without decisive factual support settle with UNKNOWN rather than
manufacturing proof. Ground demand expansion also preserves the native
FALSE-pass/contrapositive branches; it is not a positive-only dependency scan.
The existing 128-wave defensive bound is retained, and exceeding it is an
error rather than a successful fixed point.

A native TRUE/FALSE contradiction witnessed for a causal frontier remains
known for the operation. That node supplies no facts thereafter; packets are
rebuilt from currently usable child proofs, so earlier donor facts can be
withdrawn and their parent returned to its packet-free native result. Exact
cached states avoid re-executing a withdrawn empty packet. This prevents an
anti-monotone contradiction loop from repeatedly forgetting and rediscovering
its own evidence. The conflict witness is observation metadata, not pooled
stale/resumed answers. Only latest responses form the returned root batch.
A blocked child conflict does not override an independent decisive root proof:
truth remains invocation-addressed. A root conflict, or a blocked root whose
causal child conflicts, is retained in continuation diagnostics and cannot
supply root evidence or provisional hypotheses.

`FrontierContinuationEngine` now uses this graph for each externalized native
frontier. Only fully re-proven root answers reach its existing semantic lift
and same-compiled-query continuation. Child TRUE/tuples never become root
Values by projection alone. Ordinary `Mind.query` therefore runs the distributed
A:p→q, B:q→r, C:p(John)/p(Mary) example automatically and returns both independent
root Values. Operation-local evidence still disappears at query completion.

Child demands may also be resolved by native proof against the original live
initiating X, including its working layer. This probe is sequential, in a
discarded ephemeral child, and never calls a federation provider. It uses the
original source Mind rather than the continuation Mind containing generated
root-query demand: such demand must never become factual X proof. Only proven
relevant semantic child facts are then supplied to foreign targets; no user
layer, Context or rule set is replayed.

`Mind.query`, X-local donor facts, late tuples after TRUE, reordered and repeated
arguments, typed fixed strings and hash collisions, seeded/unseeded cycles,
initial and late contradictions with donor withdrawal, independent root proof
beside a blocked conflicting branch, negative native proof, exact old pins
across CURRENT advance and published target connections remaining local-only.
The complete DUMB2 corpus contains 258 tests, zero failures/errors/skips.

## Private initialization of direct connections and hypothesis provenance

The accepted operator model now permits `ctx ask N !...`, `+...`, and `-...`
against a direct connection. A foreign published Context remains an immutable
artifact: edits belong to X's connection vector, not N's CURRENT or revision
generations. Direct queries, frontier requests, rules inspection and isolated
opinions all use the same effective view. No target connections are traversed.

Initialization is an ordered list of original native commands, including
quantified rules and production-generating additions/deletions. It is not a
list of previously generated rule IDs or flattened facts. Stored commands
are replayed once when X opens; a subsequent edit executes only its new command
in a private child. Runtime versions retain previous views for X transaction
rollback, and reference counting releases their snapshot roots when X closes.
Queries and opinion optimization run in discarded children of the selected
view, preserving its initialized rule state. Native duplicate/empty-selection
warnings are valid no-ops; syntax, native conflicts and new composition
conflicts reject the edit without replacing the previous view or command list.

Explicit X transactions checkpoint the immutable connection vector, including
initialization. Rollback restores all of it; commit retains changes in the
parent environment. Publishing X seals content and connection initialization
in one revision. Ordinary live working topology remains visibly unsaved until
publication. Historical X forbids connection edits. Reconnecting preserves
configuration. Switching a pin checks identity, replays initialization against
the proposed target and qualifies the effective view before installing it;
failure preserves the old pin, commands and runtime.

Qualification must inspect the configured target rather than reintroduce its
masked base rules. Both write-candidate pair qualification and foreign/X
composition use effective views. The exact target revision still identifies
the immutable base; initialization is source-owned metadata. Console and Server
mark source opinions/rules as configured by X so they are not attributed to the
unmodified published target. Saved opinion cache guards include initialization
and existing query/state invalidation; repeated identical collection does not
rerun inference or optimization.

Connection metadata format 4 adds the ordered command list to each connection
inside the existing checksummed, atomic revision-indexed sidecar. Formats 2 and
3 remain readable; previous readers reject format 4 instead of silently losing
configuration. The semantic unit and revision-generation formats are unchanged.
Each connection has at most 4096 initialization commands. Canonical `.k`
metadata places `//! ctx init <command>` immediately after the corresponding
`//! ctx connect <locator>@<revision>`; `//! ctx init+` continues multi-line
commands. Source compilation installs prepared topology inside its technical
transaction, so failure also rolls back initialization.

Native proof projection continues through derived donors. A leaf matching a
source-local hypothesis retains its source Context UUID/revision and original

### Pair compatibility before native settlement

A pair rejection carries STORAGE_CONTEXT_CONFLICT and native collision witnesses; technical children are discarded, while explicit user levels remain available for amendment or rollback.
