# Stage501: direct native universal unit collision repair

## Proven scope

Stage500 demonstrated that native authoring accepted `!@x p(x);` together with
`!@y ~p(y);`. The original named-value-only Linker comparison left both variables
empty, and the stored-only Analyzer comparison never reached the pair.
Stage501 repairs direct opposite ordinary unit rows in authoring and explicit
current-context qualification. It does not repair general Horn/constraint closure
or mixed universal/existential prefixes.

For two universally closed ordinary unit literals, standardize their variable
scopes apart and compute their principal unifier. If complementary literals unify,
their shared instance is forced both true and false. No choice of a database
constant is required. Repeated positions impose equations within a parent's scope;
separate binders in different Rules do not impose equality until unification.
Typed ordinary values must agree. This is the existing Clause.resolveWithUnits
operation, not a second implementation of substitution or resolution.

## Native integration and evidence

NativeUniversalUnitCollision extracts the actual complete unit shape only from
visible, non-query, non-generated Rules with a single branch and a single literal.
All arguments must be owned TVariables or ordinary semantic values. System,
calculated, function and existential argument shapes are excluded. Signature and
polarity buckets enumerate exact complementary pairs. Two entirely ground rows
retain the historical stored comparison; a pair considered here has at least one
universal variable. Neither live current TValue selections nor database values
supply its meaning: Clause.shapeOf reads the complete variable pattern.

A Pair retains both actual root Rules and their original symbolic shapes. Before
Analyzer records it, verify reconstructs both whole shapes, checks equivalence,
and rechecks the empty unit resolvent. This uses the existing qualified primitive;
it is not described as an algorithmically independent second unifier. Independent
behavioral evidence comes from the separate tuple-intersection test below.
Existing Analyzer.recordCollision emits native diagnostic witnesses and invokes
CollisionProofCapture with both roots. This is a direct refutation, not a sealed
DMZ model/proof receipt. No invented stored fact, Source or representative term is
introduced. The helper does not assert consistency for any unsupported remainder.

Analyzer enables this additional comparison for ACCEPT operations. Mind's explicit
current-context CHECK qualification requests it through a private analysis overload
that retains the existing afterAnalyze callback. Other query/hypothesis passes use
the historical analysis path. Solutions/Values are not populated from this helper.
No writer, transaction topology or persistence format is switched or migrated.

Each search has a one-million-work-unit ceiling. It charges the Rule/argument scan
and candidate unification; rechecks have their own same-sized budgets. Exhaustion
throws rather than returning a partial list or a consistency verdict. This ceiling
is not an overall runtime/scale guarantee and adds no public configuration option.
The surrounding technical transaction retains ordinary rollback on exceptions.

## Counterexample and independent controls

The new NativeUniversalUnitCollisionRunner fails on the old stage498 JAR at the
first opposite diagonal-unit comparison. That before test uses the unchanged old
Analyzer/Mind; the helper class is present only to link the new QA entrypoint and
is not called before the observed failure. The development overlay is not final
artifact evidence.

The final runner independently expands nine binary argument patterns over all
mentioned typed constants plus one other representative. It intersects their tuple
sets for every 9x9 pair and both insertion orders:162 native authoring comparisons.
This is an oracle for existence of a unifying tuple in a flat, function-free unit
pair, not a change to finite-domain semantics. It covers repeated positions,
independent variables, incompatible fixed values and numeric versus string values.
Every rejected insertion checks atomic row-ID preservation and actual diagnostic
collision witnesses. Additional cases cover explicit CHECK qualification and its
native capture roots, no invented intermediate fact, bounded helper refusal,
unseen-value queries/unresolved queries, single-row queryAccept refusal, the
consistent forall-forall-exists control, arities17/65 and zero-arity legacy behavior.

The required broader gate is retained: ContextAlternatingPrefixCollisionGate now
reports RED16/missing5/exit1, compared with stage500's missing7. Both direct universal
unit insertion orders are repaired. The three original alternating-prefix misses
and two universal compound-constraint misses remain OPEN. A reduced missing count
is not a passing native-language certificate. Mixed-prefix DMZ binding refusal is
unchanged. Stage402's broader ordinary DMZ symbolic closure remains a separate path.
