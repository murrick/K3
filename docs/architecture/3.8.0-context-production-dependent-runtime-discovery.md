`ContextDependentRuntimeContinuationInspection.Request.automatic` replaces the second caller-written plan with bounded discovery from its own freshly obtained first receiving state. ## Frozen discovery domain

For every actual cut the scanner observes the child's actual primary originals and every physical member of that cut. All TRUST members remain one pool. A foreign independent member is not added to another cut. It observes every actual row before considering plans; unsupported ordinary rows fail the whole operation rather than being silently omitted. The domain is the current observer's supported positive prenex units and ordinary signed units/single Horn clauses, not the full language.

Native units are original donors; all raw received runtime occurrences are additional donors, with their exact indices and proof ancestry. Metadata filtering uses only predicate, sign and argument count. For every ordinary multi-literal row and every retained literal, discovery enumerates the full Cartesian tuple of opposing donors in native literal order. A single shared typed MGU for the entire tuple must succeed. Repeated variables, typed constants, rigid Source/binder/dependency graphs and occurs checks retain existing executor semantics. Variable coordinates are not matched independently. A rigid no-match only rejects that recipe and proves no inequality or semantic falsity.

No newly found output is a donor in this discovery pass. Every discovered donor is an actual original or an occurrence from the frozen received input. New outputs are replayed only after the complete pass, followed by a complete receiving pass across all cuts. The implementation is sequential; its frozen-input semantics do not depend on worker parallelism. It preserves every accepted raw recipe, including duplicate proof occurrences and all Source alternatives/supersets; it performs no fact-level or minimal-support deduplication.

## Limits, authority and completion

Separate positive limits bound candidate tuples, accepted outputs and scanning work. Execution work and term/certificate nodes are cumulative across successful AND failed candidate tuples; independent certificate audit work remains separate. Enumeration uses an iterative mixed-radix cursor, not recursive nesting by predicate or clause rank. Capacity/refusal at any stage yields INCOMPLETE and exposes no first bundle, frame, discovered plan/counts, outputs, history, tickets or epoch. Interruption and native currentness retain the owning contract. Actual source refutations remain distinct from invalid model guesses.

Only a successful full second receiving audit attaches immutable discovery steps, outputs and attempted/no-match counts to a fresh CONTINUED_PENDING result. Callers cannot supply a discovery receipt, frame or output to bypass fresh qualification. The existing pending session retains this result with the continuation epoch and invalidates old views exactly as for explicit plans. No native fact, model choice, factory row, revision or durable packet is written. Existing explicit continuation remains supported.

The substitution auditor independently checks the soundness of every accepted result; it is not a separate exhaustive-search completeness certificate. The small qualification fixture additionally builds an independent typed Cartesian oracle and compares every exact donor recipe, candidate count and failed shared-variable combination, including raw occurrence duplicates.

This stage discovers ONE next frozen pass after the first explicit barrier. It does not automatically repeat discovery, filter already-known proof frontiers, project the post-second state, claim quiescence/saturation, construct new models, or activate ordinary Console/query/writer admission. An empty plan, if reached internally, still needs the complete receiving audits and does not assert semantic completeness. Full loop/frontier handling and receiving-refutation-before-stability remain next work.
