# Stage504: isolated dependent witness applications and unification

## Structural result, not default activation

NativeDependentWitnessTerms implements symbolic applications such as u(a), not
just the preceding-parameter lists observed at503. It is an isolated component
with no existing production caller. Linker, Argument, Term, materialization,
queries, persistence and mixed DMZ admission are not redirected. All2143 previous
JAR class entries are byte-identical. The native authoring RED cases remain RED.
Passing component tests must not be presented as a repair of ordinary Core.

## Root and application identity

An Arena belongs to one Mind/thread and a fresh UUID. capture checks a complete
positive prenex unit against fresh whole-origin compilation, using the503 scope
comparison. Roots retain their actual Rule, exact origin and detached binder/use
shape. Before operations, local currentness rechecks ownership, shape and native
binder identities; changed/deleted/replaced originals fail. This is local source
currentness, not a provider lease, entire-view certificate or DMZ receipt.

A symbol is keyed by arena, actual native Rule and declaration position. Each
project creates fresh formal variables for the unit's universal binders. Every
existential is an application of its own declaration symbol to precisely its
preceding universal parameters. Later universals are excluded. Repeated uses of
one binder reuse the same application in that instance. An unbound a stays a
formal argument of u(a); it never silently becomes a zero-parameter global u.

Node kinds are VARIABLE, ordinary semantic VALUE and symbolic APPLICATION.
Ordinary values use SemanticTermSnapshot equality, including exact logical type.
Applications are interned by symbol plus the complete ordered canonical argument
tuple. Substituting a=1 in separate fresh instances yields one canonical u(1);
changing only a later b leaves it unchanged. Changing a parameter changes the
symbolic key. A leading existential has one zero-parameter application.

Different application keys do NOT assert different interpreted values. A model
may assign the same value to u(1) and u(2). Likewise separate declarations retain
different symbols without an entity inequality claim. No source fact, ordinary
constant name, C-variable child or chosen model value is generated in the owning
Mind. Fresh replay uses a separate private Mind; semantic snapshots may materialize
detached value objects for comparison.

These symbols are local to the Arena. Native IDs and declaration positions are
not stable transport Source identities, packet Origins or witness-first-use
ordinals. Different arenas never alias, even when native IDs match numerically.
A future adapter must provide the full physical Source/revision/view mapping and
stable lineage required by the actual production/retained transaction protocol.

## Substitutions and first-order term comparison

The component includes first-order syntactic unification with local bindings,
standard fresh variables, function-symbol/arity matching, typed semantic values
and direct/indirect occurs checks. A successful Substitution is immutable and
arena-bound. A failed logical comparison returns null with no leaked bindings;
other alternatives can still be explored in the same Arena.

Application/substitution traversal uses explicit stacks and canonical DAG nodes.
Rewriting nested terms does not recurse on the Java stack. Work and node budgets
are caller-supplied positive resources, not language rank/arity limits. Exhaustion
poisons the Arena; a fresh attempt is required. Stale-source and wrong-arena
operations also refuse. Off-thread calls refuse before mutating owning state.
Close releases caches and makes future operations invalid. Detached immutable
historical nodes are data, never reusable authority.

An empty argument list still validates the substitution's Arena. Zero-arity
projection and empty substitutions cannot bypass provenance checks. This edge
was addressed during component development before the frozen qualification.

A syntactic unification failure is NOT a proof of semantic inequality, FALSE to a
query, consistency of an entire context or completeness of Source alternatives.
The comparison engine handles terms, not predicate polarity, complete clauses,
Source proofs or independent final model audits. Its result cannot be supplied as
an existing model/admission receipt. Those distinctions are required when wiring
it to real inference; do not convert application strings into ordinary constants.

## Concrete component controls

NativeDependentWitnessTermsRunner has323 checks. It compiles the actual positive
prefix and actual headless constraint into raw native primary rows, captures the
positive whole root, and converts the actual ordinary negative clause's typed
slots into independent formal variables. Predicate and negative sign are checked
before comparing term vectors. A fresh positive instance is used at each premise;
substitution applies to the entire remaining premise. This is a QA resolution
harness, not a production qualifier or a new all-language solver.

Four prefixes (dependent, alpha-renamed, global, later-dependent), two constraint
families, both insertion directions and both body orders give32 comparisons:

- forall a exists u forall b: the shared-a/two-b prohibition refutes; the
  cross-a/shared-u prohibition does not;
- exists u forall a forall b: both prohibitions refute;
- forall a forall b exists u: neither prohibition refutes.

These results distinguish both earlier missed collisions and the false native
collisions. The original countermodel/refutation proofs from499/503 establish
those expectations; native query/hypothesis answers are not an oracle. The
harness preserves all native rule IDs and dictionary sizes on both outcomes.

Additional tests cover repeated slots, reuse of complete tuples, exclusion of
later parameters, distinct declarations, permitted coincident interpreted values,
direct/indirect occurs checks, failed-substitution cleanup and typed constants.
All parameter coordinates at7/17/65 are preserved. The same complete tuple is
canonical across fresh formal instances; the final typed coordinate matters.
A257-deep application chain is rewritten iteratively. Zero-arity, immutable
outputs, wrong-root/arena/thread, stale source, failed-attempt reuse, work/node
caps and paired source-text tampering are qualified.

Scope of these tests is deliberately limited: multi-existential production joins,
conditional/conjunctive source bodies, full Source/view transport, native matching
callbacks, durable generated witness identity and cold reopen of such projections
remain integration obligations. The503 metadata observer's wider binder tests do
not automatically qualify those504 runtime paths.
