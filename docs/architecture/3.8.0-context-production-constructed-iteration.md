# Constructed receiving interpretations and complete diagnostic iteration

`ContextDependentConstructedIterationInspection` combines fresh constructed startup
with frozen runtime discovery, actual producing/receiving replay, receiving model
construction and independently audited proof-frontier stability. Its request contains
an actual append, startup/receiving typed palettes, explicit search/projection bounds
and a finite schedule of `RoundLimits`. It accepts no interpretation maps, donor
recipes, runtime frame or qualification receipt. Results remain diagnostic pending;
ordinary eligibility, default/query/writer activation and native RED gates are open.

## Receiving boundary

Each pass consumes the prior frozen native/indexed state. Complete producing and
receiving histories are replayed, and actual sourced refutations are checked before
any receiving model guess. Only the freshly replayed final barrier enters the
package-private search kernel. The public standalone family search retains its
fresh qualification contract; there is no public checked-result-taking search API.

The search schema includes every native original and every raw final common/private
occurrence, imported function Source/binder/ordered dependencies, typed constants and
all exact ancestry. Independent cuts get separate models; whole TRUST members share
one model. Functions in receiving models use actual child Sources directly. Startup
continues to translate preserved parent-original keys through fresh qualification.
New incoming and foreign witness declarations preserve their exact identities.

Receiving construction checks native originals/finals and an independent indexed
projection. The iteration then separately repeats native original/final audits with
the round's audit limits and a fresh indexed projection/truth check. All counts must
agree. Only after these checks does the complete signed typed/full-Source/min-depth
frontier comparison decide whether another round is needed. Empty discovery and
stable duplicate recipes are subject to the same receiving construction/audits.
No model choice assigns native Cvars or converts symbolic functions to values.

The legacy supplied-model iteration remains available. The explicit constructed
receiving factory refuses nonempty supplied receiving maps instead of ignoring them.
Its search template is rebound to the actual append iteration and receiving
projection configuration. Startup and each receiving search have separate bounded
per-family allowances shared across their cuts/attempts; the finite schedule bounds
the number of searches. No finite palette/search completeness is claimed.

## Failure and ownership

A failed bounded model search is INCOMPLETE, never evidence of no model or source
collision. Actual source proofs alone produce BASE_REFUTED/CANDIDATE_REFUTED or
ROUND_REFUTED. Search, bridge, final audit, projection, frontier or schedule failure
clears all startup/model/cycle/frame/epoch prefixes. A productive final scheduled
round cannot masquerade as saturation. Only an unchanged fully qualified receiving
frontier yields STABLE_PENDING and an epoch.

Each successful cycle exposes immutable historical constructed models and spent
attempt counts for inspection. No public result can bypass fresh native qualification.
The provider's `prepareDependentConstructedIteration` clears earlier preparations
before work, retains only the successful final nested iteration under its exact epoch,
and refuses wrong-thread, stale or closed use. Historical startup frames/models and
received-frame UUIDs are not default-runtime capabilities. Native revisions and
factory state are unchanged.

Known native false/missing-conflict gates, full-family/default readiness, broader
language, resource scaling/pruning, signed/multi-cut recovery and Question3 remain
open. There is no Console/manual activation or semantic baseline change here.

## Whole-cycle candidate limit

A constructed iteration request can set a positive `totalCandidateAttempts` limit.
The effective limit cannot exceed the sum of the two startup allowances and the
scheduled receiving allowances. The existing constructor uses that sum.

Each inspection starts with a fresh allowance. The base search, proposed search,
and every receiving search charge it before materializing a candidate. A candidate
rejected by the truth audit still spends its attempt. Existing per-search limits
continue to govern schema, work, audits, and projection. The aggregate limit measures
candidate attempts. Replay, proof history, and aggregate audit work have separate
resource considerations.

Exhaustion returns INCOMPLETE at the affected phase and clears the successful prefix.
A sourced refusal encountered before the search requires no attempt. A complete run
can use its last attempt and still finish the required audits and frontier comparison.

## Cumulative replay barrier limit

The constructed diagnostic request can also set a positive
`totalReplayedBarriers` limit for receiving passes. Each pass reserves its
complete history length plus two barriers before invoking replay. The two
barriers represent producing and receiving. A historical barrier consumes an
allowance each time it is replayed. The existing constructors use the scheduled
round count times the per-replay step limit as the ceiling.

The allowance resets on each inspection. Exhaustion returns INCOMPLETE at
round-bridge and clears the successful prefix. Startup qualification, work
inside each barrier, model audits and proof history storage have their own
resource considerations.
