# KANGER 3.5.0.3 — TValue ordering resolution

## Defect

Historical `TValue.compareTo()` implemented ordering by subtraction followed by
narrowing to `int`:

```java
return (int) (tVarId == o.getTVarId()
        ? id - o.getId()
        : tVarId - o.getTVarId());
```

This does not define a valid total ordering over the full `long` domain. Large
differences can collapse to zero, reverse sign, or overflow before narrowing.

## Intended contract

The method expresses lexicographic ordering by:

```text
(tVarId, id)
```

1. values belonging to different TVariables are ordered by `tVarId`;
2. values belonging to the same TVariable are ordered by TValue `id`.

## Correction

```java
int variableOrder = Long.compare(tVarId, o.getTVarId());
return variableOrder != 0 ? variableOrder : Long.compare(id, o.getId());
```

The correction preserves the intended key hierarchy while making comparison
valid for the complete `long` domain.

## Regression gate

```text
kanger-console/src/org/kanger/KangerTValueComparableSafetyRunner.java
```

Covered cases include:

- ordinary same-variable ordering;
- same-variable IDs separated by `2^32`;
- `Long.MIN_VALUE` / `Long.MAX_VALUE` value IDs;
- different-variable ordering independent of TValue IDs;
- variable IDs separated by `2^32`;
- full-range variable IDs;
- equality and antisymmetry.

## Impact boundary

The change does not modify:

- `equalsTo(...)` semantic-pair identity;
- `equals(...)` object identity by TValue ID;
- `getHash()` canonical pair hashing;
- `hashCode()` object-ID hashing;
- persistence bytes;
- `TValueFactory.find(...)` resurrection semantics;
- factory index keys or lookup policy.
