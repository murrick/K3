## Required protocol and finite implementation order

1. Shared durable-I/O layer: define and qualify a supported local filesystem /
   device profile, including directory barriers and atomic replacement. Refuse
   explicitly where this contract cannot be provided; no silent process-only
   fallback. Flush-honouring devices and no out-of-band mutation are assumptions.
2. Before exposing a new CURRENT, persist the selected frame: rewritten and
   copied bases, schema/type metadata, dependency vector, seal, staging and
   installed generation directories and their necessary parent entries. Include
   initial creation, fork and newly created ancestors. A source file force does
   not force the destination of Files.copy.
3. Force the new marker, replace atomically, then force its parent before ACK.
   Distinguish visibility from durable acknowledgement. After a visible-marker
   barrier failure, keep an unconfirmed-publication fence. Reading back the new
   number cannot clear it: reconciliation must reestablish durability first.
4. Protect exported pins between modules: a dependent context must not ACK a
   reference to a merely visible but unstable producer revision. Implement a
   short publication gate or explicit stabilization of the selected view; the
   exact mechanism is an implementation choice to be reviewed with the code.
   This requires neither recursive knowledge acquisition nor a transaction
   across every connected context. Preserve exact identity and isolation.
5. Qualify a finite matrix: create/append/topology/reindex/fork; failures before
   install, after install, before marker, after visible marker and before final
   barrier; recovery/retry and cross-module pin consumption. Reuse existing
   process-death gates and add namespace/data persistence projections. Record
   the supported-profile crash/power-loss evidence and its limits before
   advertising the strong guarantee.

Implementation belongs to P1/H4. Each phase must preserve typed errors, owning
checks, immutable retained history and pending intent. D09 legacy authenticity
remains a separate boundary: durability must not manufacture missing knowledge.
Do not close H4/P1, activate symbolic defaults or declare hardware acceptance
from the model alone. Next work is the shared I/O/protocol implementation,
followed by the stated failure matrix, not another decision about D07.


## Follow-up — stage 650 — own frame and marker persistence barriers

The stage-649 counterexample is repaired in the measured namespace scope.
[Stage-650 observation](3.8.0-context-marker-model-stage650.json) records an
unchanged R5 control and R5 after the permitted model projection, with a
successful parent-directory barrier between replacement and ACK. The stronger
trace gate also checks every captured own-frame file, seal and selected
generation/state/metadata directory after generation install and before marker
replacement. Nine packaged provider classes match built bytes; 13 real fixture
controls pass. This remains full_power_loss_acceptance=false. Older observations
and their hashes are preserved separately.

DurableFiles forces copied and rewritten immutable bases, seal, Context metadata
and optional connection sidecar before CURRENT. Generation directory and state
root are forced, followed by metadata ancestors bottom-up. The shared publication
helper covers data flush, topology/prepared publication and reindex; fork forces
its own frame before creating the initial marker. Initial markers are forced
with their parent chain. A barrier failure after marker visibility becomes an
UnconfirmedRevisionException and retains the existing CURRENT fence. Checkpoint
validates the selected frame and repeats frame/marker barriers before clearing
that fence; mere rereading is insufficient. A failed fresh-marker barrier removes
only the marker created by that call, preserving retry and existing markers.

Test-only overlays now inject directory-barrier failure after an actual marker
replacement for native checked write, checked topology save and both reindex
entries. They require a readable new marker but old diagnostic cursor, blocked
CURRENT/old receipts/authoring, failed checkpoint while the barrier remains
unavailable, then exactly-once adoption and cold reopen after repair. Additional
controls cover initial creation refusal/retry and pre-marker frame refusal.
ZIP-provider directory force and symbolic-link traversal are explicitly refused.
No production fault hook or configurable silent fallback is added.

This is the own-publication implementation slice, not closure of H4/P1 or D07.
The selected frame is conservatively forced in full: O(frame bytes/files), with
no performance claim. Filesystem/device profile qualification, genuine
persistence fault evidence and durable exported pins between independent modules
remain open. In particular an external consumer can still see the producer's
marker between replacement and acknowledgement; local fencing alone cannot
certify that exported pin. Next prove and close that modular boundary, then
qualify the supported profile and remaining failure matrix. Ordinary symbolic
default activation and trust semantics remain unchanged.
