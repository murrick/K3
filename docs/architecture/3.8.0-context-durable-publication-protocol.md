# Durable publication — accepted D07 and implementation contract

17 November 2026, stage 649. D07 is ACCEPTED / IMPLEMENTATION_OPEN.
The author explicitly requires acknowledged publications to survive power loss
and reboot because contexts participate in modular systems. Earlier stage-648
OPEN text is historical. Process termination alone is insufficient.

## Proven gap

`python3 scripts/qualify-context-marker-durability.py` traces actual publication,
captures the precise predecessor marker and acknowledged image, and uses the
real backend to open disposable copies. The unchanged-image control reads R5.
In the namespace projection, only the unforced CURRENT replacement is lost:
R4 opens, but exact R5 is unavailable. All other captured files are retained.
The trace has no successful parent-directory barrier between rename and ACK.
This establishes a counterexample under the stated persistence model; it does
not claim an observed power cut or filesystem corruption on the measured ext4.
The gate returns **1 / RED** until this necessary namespace condition is met.
Passing it will not alone prove full power-loss durability.

The runtime baseline remains stage 647. The [stage-648 audit](3.8.0-context-durability-contract-audit.md)
and its immutable JSON are preserved; the new [model observation](3.8.0-context-marker-model-stage649.json)
records a separate acquisition. This stage changes qualification and contracts,
not the storage protocol.

## Required protocol and finite implementation order

1. Shared durable-I/O layer: define and qualify a supported local filesystem /
   device profile, including directory barriers and atomic replacement. Refuse
   explicitly where this contract cannot be provided; no silent process-only
   fallback. Flush-honouring devices and no out-of-band mutation are assumptions.
2. Before exposing a new CURRENT, persist the selected frame: rewritten and
   copied bases, schema/type metadata, dependency vector, seal, staging and
   installed generation directories and their necessary parent entries. Include
   initial creation, fork and newly created ancestors. A source file force does
   not force the destination of Files.copy.
3. Force the new marker, replace atomically, then force its parent before ACK.
   Distinguish visibility from durable acknowledgement. After a visible-marker
   barrier failure, keep an unconfirmed-publication fence. Reading back the new
   number cannot clear it: reconciliation must reestablish durability first.
4. Protect exported pins between modules: a dependent context must not ACK a
   reference to a merely visible but unstable producer revision. Implement a
   short publication gate or explicit stabilization of the selected view; the
   exact mechanism is an implementation choice to be reviewed with the code.
   This requires neither recursive knowledge acquisition nor a transaction
   across every connected context. Preserve exact identity and isolation.
5. Qualify a finite matrix: create/append/topology/reindex/fork; failures before
   install, after install, before marker, after visible marker and before final
   barrier; recovery/retry and cross-module pin consumption. Reuse existing
   process-death gates and add namespace/data persistence projections. Record
   the supported-profile crash/power-loss evidence and its limits before
   advertising the strong guarantee.

Implementation belongs to P1/H4. Each phase must preserve typed errors, owning
checks, immutable retained history and pending intent. D09 legacy authenticity
remains a separate boundary: durability must not manufacture missing knowledge.
Do not close H4/P1, activate symbolic defaults or declare hardware acceptance
from the model alone. Next work is the shared I/O/protocol implementation,
followed by the stated failure matrix, not another decision about D07.
