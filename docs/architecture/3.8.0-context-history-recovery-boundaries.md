# P1/H2–H3 — historical binding recovery and finite reclamation policy

Stage 647, 2026-11-17. Requirement R10 of the
[delivery board](3.8.0-dmz-delivery-board.md). H2 classifies what remaining
metadata proves; H3 consolidates the already implemented cleanup policy.
Neither checklist authorizes a general historical repair or stronger durability.

## H2: one executed refusal defect

`HistoricalBindingRecoveryTest#missingHistoricalRowsUseEvidenceOrTypedRefusal`
fails before repair (`/tmp/k3-647-before.log`): a valid unsealed Context-v2
historical generation with a missing sidecar row throws NoSuchFileException
for its optional revision.manifest, instead of STORAGE_CONTEXT_CONFLICT.
The optional manifest's absence is supported legacy state, not evidence that
its missing connection vector was empty.

ConnectionStore's sealed-empty fallback now first requires a regular no-follow
revision manifest. If none is available, the fallback cannot prove anything and
the existing named, typed missing-binding refusal is retained. A present corrupt
proof is still rejected; no metadata is created and no empty inference is added.
The active storage remains selected on refusal through the H1 preflight boundary.

## H2: finite matrix

These rows distinguish a missing entry in a present sidecar from whole-file
absence. They must not be combined into a generic “missing means empty” repair.

| Remaining state | Result / evidence | Recovery boundary |
| --- | --- | --- |
| Exact stored row, supported generation | Select that exact vector, including an explicit empty vector | Validate ownership, framing, generation and any dependency seal; no inference needed |
| Present valid sidecar, missing positive historical row, valid seal explicitly binds empty dependencies | Proof-based empty selection without writing | Existing stage-643 fallback; only 0 < selected R < CURRENT |
| Missing historical row, seal binds nonempty dependencies | STORAGE_CONTEXT_CONFLICT | Need original exact binding; never reuse current pins/recipe as historical authority |
| Missing historical row, codec-v1 manifest without dependency digest | STORAGE_CONTEXT_CONFLICT | Data integrity alone does not prove the missing topology |
| Missing historical row, legitimately unsealed legacy generation | STORAGE_CONTEXT_CONFLICT after this repair | Missing optional proof is not an I/O restoration signal and does not grant emptiness |
| Missing current row or R0 row in an existing sidecar | STORAGE_CONTEXT_CONFLICT | Do not infer from a historical empty seal or invent a R0 binding |
| Requested future revision, even with installed candidate files/rows | Not published / unavailable | CURRENT remains the publication selector; the existing death matrices cover physical candidates |
| Corrupt sidecar CRC / wrong owner | STORAGE_SEMANTIC_CORRUPTION; no fallback | Preserve evidence and require consistent original recovery data |
| Present corrupt revision proof | STORAGE_SEMANTIC_CORRUPTION; no fallback | Absence and invalid proof are different; do not discard corruption to obtain an empty answer |
| Whole sidecar absent, selected positive sealed revision binds empty dependencies | Existing absent-file empty contract is consistent with that seal | Test also covers a disconnected sealed CURRENT; does not imply every historical revision is readable |
| Whole sidecar absent, selected positive seal binds nonempty dependencies | Snapshot refuses dependency mismatch as STORAGE_SEMANTIC_CORRUPTION | Digest detects loss for that selected revision but cannot reconstruct the original vector |
| Whole sidecar absent, selected codec-v1 / unsealed legacy revision | Existing compatibility contract reads empty; prior topology is underdetermined | This is NOT authenticated restoration. Lost metadata and an originally disconnected state may be indistinguishable (D09) |

### Concrete underdetermination, not a restoration algorithm

The permanent test constructs two format-valid old states over identical Source
identity, marker and data: no sidecar, and an explicit nonempty sidecar at the same
revision. Actual pinned DB opening observes zero versus one connection. After
removing the latter sidecar, every remaining Source file is byte-identical to
the originally empty state. Both codec-v1 and unsealed formats reproduce this.
No function of those remaining bytes can determine which prior vector existed.

A second control constructs distinct vectors with identical target identity/pins
but different private initialization and trust configuration. Their dependency
identity digests are equal. This is the declared digest's scope, not a hash
collision or by itself a new seal-integrity defect. Such a digest is insufficient
to reconstruct locators, certificates, private commands and trust configuration.

The inherited legacy absent-file interpretation is preserved by this stage.
Changing it to reject all legacy disconnected Contexts would change compatibility
and requires an explicit policy decision. Historical authenticity after this loss
must not be claimed merely because the empty compatibility view opens. D09 records
that boundary; no automatic repair/migration is introduced.

### Original artifact control

For sealed, codec-v1 and unsealed historical states, with empty and nonempty rows,
tests restore the exact saved sidecar bytes in an isolated offline fixture while
identity, marker and generation data remain unchanged. Pinned open then selects
the original vector and the complete Source file image equals its original image;
CURRENT remains 3. All probes, refusals and proof-based empty reads leave their
input file images unchanged.

This shows what original evidence supplies. It is not a supported online recovery
command and not advice to overwrite one file in live user storage. A real recovery
needs a consistent artifact for the same identity/revision/data/configuration,
including its exact private recipe and pins; a plausible newly qualified current
configuration is a new publication, not restoration of the lost past.

### Permanent H2 coverage

[HistoricalBindingRecoveryTest](../../kanger-data-dumb2/test/org/kanger/storage/dumb2/HistoricalBindingRecoveryTest.java)

## H3: guards and finite artifact matrix

[ContextStore checkpoint](../../kanger-data-dumb2/src/org/kanger/storage/dumb2/ContextStore.java)
requires an open confirmed Context, a live exclusive writer lock, matching CURRENT,
a freshly validated own snapshot/identity and current connection vector.
Quiescent checkpoint is the caller; a historical read-only checkpoint is not a
mutable cleanup authority. Reconciliation of unconfirmed publication precedes it.

[InterruptedPublicationReclaimer](../../kanger-data-dumb2/src/org/kanger/storage/dumb2/InterruptedPublicationReclaimer.java)
uses secure descriptor-relative operations and no-follow attributes inside the
candidate namespace. If those operations are unavailable it retains artifacts.
These are reserved protocol namespaces, not a general filesystem cleaner.

| Artifact class | Decision | Exact boundary |
| --- | --- | --- |
| Own sibling `Source.revision.next-UUID` / `Source.connections.tmp-UUID` regular file | Delete | Canonical UUID v4/variant 2 and exact Source prefix; incomplete file contents are allowed for these reserved temporaries |
| Other Source prefix, malformed suffix, unrelated `.context` temporary | Retain | No inferred ownership from a similar name |
| Hidden `.staging/.topology/.reindex/.reclaim-R-UUID`, positive R <= CURRENT+1 | Delete as one known candidate | Canonical UUID; whole directory scanned before deletion; only regular allowed `.base` names and revision.manifest; no subdirectories/links/unknown files |
| Hidden candidate with unknown child, nested directory or link | Retain whole candidate | No partial consumption of ambiguous evidence |
| Farther hidden future, unknown namespace/kind (including `.fork`), malformed number/UUID | Retain | Not a recognized interrupted attempt in this cleanup scope |
| Canonical numeric generation CURRENT+1 | Retire, then delete known files | Validate owned seal, exact revision/parent and complete generation digest; require only known regular files, then rename to an own `.reclaim` namespace |
| Numeric CURRENT+1 with bad/missing/foreign seal, unknown or nonregular content | Retain whole generation | Lack of an ownership proof never permits deletion |
| Numeric generation <= CURRENT or > CURRENT+1 | Retain | Published history and farther future are not targets of this checkpoint |
| Partially deleted own retirement directory after process death | Retry known cleanup | Reserved retirement namespace preserves the prior ownership decision; current publication is unchanged |
| Own linked marker/connection temporary, linked state root or nonregular candidate | Retain / never traverse it | No-follow relative operations; absence of secure support yields retention |
| Sidecar entry CURRENT+1 | Prune only after file cleanup and successor-namespace scan | No canonical successor or unresolved known-kind successor name; no own marker/connection-temp prefix survivor; current and stored historical vectors preserved |
| Sidecar current/history/far-future row; linked official sidecar; unresolved successor evidence | Retain | Never delete the whole file merely because remaining vectors are empty; retain ambiguity and explicit empty bindings |

A bad current marker, identity or current binding blocks cleanup before mutation.
Repeated successful cleanup is a no-op without a new revision or child reservation.
Sidecar rewriting changes file count/CRC/encoding bytes, but preserves each retained
vector's canonical locators, pins, certificates, private initialization and trust.

H3 evidence: the existing 16
[InterruptedPublicationReclamationTest](../../kanger-data-dumb2/test/org/kanger/storage/dumb2/InterruptedPublicationReclamationTest.java)
cases map deletion, retention, links, unsupported secure operations, owner/current
refusal, R0, whole owned successor and exact-only vector pruning. The native
recovery profile contains the 53-control orphan reclamation and 87-control sidecar
pruning matrices, including actual process termination and retries. No new cleanup
logic or additional artifact namespace is introduced by stage 647.
