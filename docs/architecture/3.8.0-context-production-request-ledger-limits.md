# Immutable request-local ground ledger limits (stage3bu)

Stage3bt proved genuine distinct-clause growth beyond the legacy64-clause cap.
A capacity increase must be explicit and must not delete Source alternatives,
change the native default, or turn an incomplete pass into authority for a later
write. Existing round/depth/work/event/model/probe budgets already belong to bounded
qualification requests; ledger capacities were the remaining fixed insertion gates.

## Owning policy

`ContextOrdinaryResidualRounds.LedgerLimits(clauses,proofs)` is immutable and requires
both capacities positive. They are independent: a proof cap may be smaller than the
clause cap. DEFAULT remains64/256. Existing start/evaluate/owning inspectGround
signatures delegate to that same default. New overloads accept an explicit policy;
null is rejected rather than silently selecting another budget.

A Frontier seals the policy at creation. Every subsequent barrier retains the exact
same object. All ledger insertion paths receive it explicitly: primary/carrier
loading, ordinary/parameter/isolated reductions, donor combinations, ground and
universal composition sweeps, local combinations, generalization and family merge.
There is no thread-local or mutable global override, and no private insertion
fallback to defaults. Receipt input identity already binds observations to that
exact request; receipts cannot cross to a new request even with equal numeric caps.

The read-only owning pending lease has an explicit-capacity inspectGround overload.
It retains fresh complete snapshot binding, original Source views and requireCurrent
checks. The automatic selector and actual native write adapters continue to use
legacy64/256. A detached larger-capacity inspection is never publication permission.
No other observer, language, work, event, depth, model or probe bound is raised.
