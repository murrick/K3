# 3.5.0.4 J10 — DUMB container lifecycle invariants

## Scope

J10 found two independent container-level lifecycle violations in concrete DUMB
`DB`. Neither defect changed the on-disk format, `baseCode` assignment, WAL
record format, integrity manifest, semantic IDs or `Base` record semantics.

## Invariant 1 — close failure isolation

### Violated behavior

Historical `DB.close()` stopped at the first `IBase.close()` exception and
cleared the registry only after every close succeeded. With bases A, B and C,
when B failed:

```text
A — already closed but still registered
B — failed and still registered
C — never attempted and still registered
storageName — still published
```

A retry revisited A before reaching C. The registry therefore mixed closed,
failed and still-open resources.

### Red evidence

```text
runner: kanger-data-dumb/src/org/kanger/storage/DBCloseFailureIsolationSafetyRunner.java
runner commit: 6f29385433c226b40ce2676fbab0bfe9f490f701
workflow step: 6dec7bf084d51470f1dfe169f6a4bac605485bcb
red KANGER CI run: 30652087087
```

All earlier regression and invariant gates passed. The new step failed with:

```text
A base after the failure must still be closed
```

### Correction

```text
7ca03945ec1eecf0f97e76c4953f348c3dc20600
Isolate DUMB base close failures
```

`DB.close()` now:

1. attempts every registered `IBase`;
2. removes each successfully closed base immediately;
3. retains only bases whose close failed;
4. propagates the first failure and attaches later failures as suppressed;
5. retains `storageName` while any base remains retryable;
6. clears the name only when the registry is empty.

The permanent gate proves that a clean retry revisits only the failed base.

## Invariant 2 — reversible reindex publication

### Violated behavior

Historical `DB.reindex()` completed temporary generation construction, closed
both generations, deleted the live `.index`, `.store`, `.integrity`, delta and
WAL files, and then invoked unchecked `File.renameTo()` calls.

A publication failure after live deletion could therefore leave no usable live
generation even though the complete temporary generation still existed.

### Red evidence

```text
runner: kanger-data-dumb/src/org/kanger/storage/DBReindexSwapAtomicitySafetyRunner.java
runner commit: 30867c6dcbba991ce1fdd1eb0c86366fc9807521
workflow step: 06dee56f52b4700a45192e65b25d13922de05264
red KANGER CI run: 30652541987
```

The Java 8 fault injector failed the first temporary-index publication after
live-generation destruction. All earlier gates, including close-failure
isolation, passed. The new step failed with:

```text
Original index must survive a failed publication (file missing)
```

### Correction

```text
05f4cb953a1b8acdcb345c593ca5db38810ef6cb
Make DUMB reindex publication reversible

33f4e3d31a00de2ce58cc58339e3417373121fcd
Align reindex fault with reversible swap
```

Publication is now a reversible runtime swap:

```text
validate complete temporary core generation
move live index/store/integrity to unique backups
move temporary index/store/integrity to live paths
on any failure:
    move installed files back to temporary paths
    restore backups to live paths
    attach rollback failures as suppressed
on success:
    remove backups best-effort
    clean delta/WAL side files
```

The permanent gate injects failure after backup and before the first install,
then proves:

- original index/store/integrity survive byte-for-byte;
- temporary index/store/integrity remain available;
- the original publication error is propagated.

This is exception-atomic publication inside the running process. It does not
claim a new crash-atomic multi-file filesystem transaction across abrupt power
loss or process termination.

## Preserved boundaries

Both corrections preserve:

- DUMB file headers and packed record formats;
- base-code addressing and canonical schema acquisition order;
- WAL and integrity recovery protocols;
- linked endpoint reconstruction;
- Base/Data cache policy and telemetry;
- generic `IData` / `IBase` signatures;
- successful reindex semantic content and post-swap reopen flow.

## Permanent gates

```text
DUMB close failure isolation invariant
DUMB reindex swap atomicity invariant
```
