# KANGER 3.5.0.4 — J2 canonical factory checkpoint

## Status

J2 is open.

Scope:

```text
DictionaryFactory
PredicateFactory
```

These are the two canonical root registries shared directly across child `Mind` construction. They establish the concrete factory vocabulary before documentation proceeds to factories whose child instances own explicit transaction overlays.

## Why this pair comes first

There is no concrete production class named `KangerFactory`.

The historical phrase identifies a common subsystem and regression family, not a Java inheritance root. Javadoc must therefore explain the repeated protocol through the actual classes and the existing `IFactory` contract rather than fabricate a base type.

`DictionaryFactory` and `PredicateFactory` are paired because they share the same principal structural boundary:

```text
Mind ownership
Escalera canonical cache
schema-specific borrowed IBase attachment
root versus child transaction initialization
child promotion into parent
cache mark / commit / release protocol
root persistence update
```

They differ materially in identity, runtime metadata, and garbage-collection policy. Those differences must remain explicit.

## Common protocol to document

### Representation

A factory instance is a Mind-owned canonical registry for one semantic unit category. It is not merely an object constructor and not the owner of the enclosing storage lifecycle.

### Root and child construction

For a root `Mind`:

- the factory owns an `Escalera` cache for its schema;
- when storage is open, it borrows the current schema `IBase` from `User`;
- cache misses may hydrate canonical units through that base.

For a child `Mind`:

- the factory is initialized against the visible parent cache;
- the storage attachment is reset rather than inherited as child close authority;
- additions belong to the child transaction until parent completion.

### Promotion

Parent commit splices child cache state into the parent generation and rebinds promoted units from the child Mind identity to the parent Mind identity.

The private `top` field is a generation-local sequence anchor used by this splice protocol. It is not documented as semantic identity, durable root, newest element, or traversal direction because those stronger meanings are not required by the proven contract.

### Persistence

The `connection` field is a borrowed, generation-local schema attachment.

```text
storage owner / close authority: User / IData
factory authority: schema-local hydration and update while generation is open
```

The public `closeConnection()` method is legacy compatibility/authority debt. It must not be presented as the normal or authoritative storage lifecycle path; exact external treatment is reserved for `3.5.0.5`.

### Checkpoints

`mark`, no-argument `commit`, and `release` delegate the reversible cache checkpoint protocol to `Escalera`. This is distinct from `commit(childFactory)`, which promotes one child transaction into its parent.

Javadoc must distinguish these two meanings of commit rather than describe both as generic persistence.

### Cleanup

`clear()` has different root and child effects:

- child: discard local generation state and reinitialize from the visible parent;
- root: clear canonical cache state and rebuild the current root attachment.

Factory cleanup must not close or destroy the borrowed `IBase` generation.

## DictionaryFactory-specific contract

`DictionaryFactory` canonicalizes `Term` values and additionally owns:

- allocation of C-variable indexes within the Mind chain;
- creation and explicit Mind-local linking of C-variable parent/child terms;
- an incremental pack-candidate frontier;
- previous/current Rule-term snapshots used to detect newly unreachable Terms.

Its pack policy distinguishes durable Rule references from transient references retained by solutions, hypotheses, and values. Terms referenced only by transient stores remain candidates for later reconsideration. Removing a Term also unlinks its transient C-variable adjacency from the owning `Mind`.

The factory does not make C-variable links persistent knowledge; those links remain runtime state owned by `Mind`.

## PredicateFactory-specific contract

`PredicateFactory` canonicalizes predicates by the compound identity represented by predicate name Term and range.

Its pack policy removes deleted or otherwise unreferenced predicates after examining active Rules and the current solution/hypothesis projections. Unlike `DictionaryFactory`, it currently performs a full cache scan and does not own a separate incremental candidate frontier.

The name Term is canonicalized by `DictionaryFactory`; `PredicateFactory` does not own the lifetime of that Term or the enclosing query-result stores it consults during packing.

## Concurrency boundary

Synchronized mutation points protect factory-local canonicalization and counters where implemented. They do not establish a blanket guarantee that factory instances or returned units are independently thread-safe.

Child transaction publication and completion remain governed by `Mind`; storage generation replacement remains governed by `User`.

## J2 acceptance criteria

J2 closes only when:

1. both class-level comments explain representation, Mind ownership, root/child lifecycle, promotion, borrowed persistence attachment, checkpoint protocol, cleanup, and caller boundary;
2. category-specific identity and pack semantics remain explicit;
3. no public interface or executable behavior changes;
4. rendered Java 8 and Java 21 Javadoc contains both architectural introductions with resolved links;
5. the complete existing qualification contour remains green on the same final HEAD;
6. a paired review confirms the comments do not imply factory storage ownership or a nonexistent common production class.
