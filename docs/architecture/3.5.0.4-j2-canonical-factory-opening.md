# KANGER 3.5.0.4 — J2 canonical factory checkpoint

## Status

J2 is open.

Scope:

```text
DictionaryFactory
PredicateFactory
```

These are the two canonical registries published directly across a `Mind` chain. They establish the concrete factory vocabulary before documentation proceeds to categories whose child `Mind` levels own separate transaction-overlay factory instances.

## Why this pair comes first

There is no concrete production class named `KangerFactory`.

The historical phrase identifies a common subsystem and regression family, not a Java inheritance root. Javadoc must therefore explain behavior through the actual classes and the existing `IFactory` contract rather than fabricate a base type.

Source inspection establishes a stronger distinction than the generic factory audit vocabulary initially suggested:

```java
terms = (DictionaryFactory) root.getTerms();
predicates = (PredicateFactory) root.getPredicates();
```

A child `Mind` does not construct normal child overlays for these two categories. It reuses the exact canonical instances visible through its parent. `DictionaryFactory` and `PredicateFactory` are therefore paired because they share this principal boundary:

```text
root-Mind ownership
exact-instance publication across the Mind chain
Escalera canonical cache
schema-specific borrowed IBase attachment
canonical hydration and identity
root-generation update and packing
```

They differ materially in identity, runtime metadata, and reachability-cleanup policy. Those differences must remain explicit.

## Common protocol to document

### Representation

Each instance is a root-Mind-owned canonical registry for one semantic unit category. It is not merely an object constructor, not a child transaction overlay, and not the owner of the enclosing storage lifecycle.

### Ownership and publication

The root `Mind` constructs and owns the factory. Standard child `Mind` construction publishes the same instance by reference:

```text
root Mind       -> owns canonical factory
child Mind      -> observes the same canonical factory instance
further child   -> observes the same canonical factory instance
```

This differs from `DomainFactory`, `RuleFactory`, `TVariableFactory`, `TValueFactory`, `FunctionFactory`, `FValueFactory`, `CommentFactory`, and `LibraryFactory`, whose child levels initialize explicit transaction state.

Consequences:

- Term and Predicate canonical identity is shared across the active Mind chain;
- normal parent commit does not promote a separate child Dictionary/Predicate factory;
- factory-local counters and canonical cache state are not transaction-private merely because a call originated from a child Mind;
- the factory's retained `mind` reference is the context that constructed the canonical instance.

### Persistence attachment

When the owning root `Mind` has open storage, factory initialization borrows the current schema `IBase` from `User`. Cache misses may hydrate canonical units through that handle, and root update may persist cache changes.

```text
storage owner / close authority: User / IData
factory authority: schema-local hydration and update while generation is open
```

The same factory instance and therefore the same current-generation attachment are visible to child Minds. The field is not copied as child close authority.

The public `closeConnection()` method is legacy compatibility/authority debt. It must not be presented as the normal or authoritative storage lifecycle path; exact external treatment is reserved for `3.5.0.5`.

### Generation reset

`transaction(...)`, `commit(otherFactory)`, and the delegated `mark / commit / release` methods remain present implementation surfaces. They support cache generation/splice or checkpoint mechanics, but they are not the standard child-Mind publication protocol for these two factories.

J2 documents the active architecture without deleting or redefining those compatibility surfaces. Their exact public behavioral contract remains reserved for `3.5.0.5`.

The private `top` field is a generation-local sequence anchor used by creation and generic splice mechanics. It is not semantic identity, a durable database root, or proof of a particular newest/oldest traversal direction.

### Cleanup and packing

Storage close/clear is coordinated by `User`, which clears the owning Mind chain and causes the canonical factory generation to reset. Factory cleanup must not be described as ownership of the borrowed `IBase` lifecycle.

`Mind.pack()` invokes category-specific reachability cleanup at root transaction quiescence. Packing removes canonical units that are deleted or no longer retained by durable/query projections according to each category's current policy; it is not a child rollback operation.

## DictionaryFactory-specific contract

`DictionaryFactory` canonicalizes external values and internal variable descriptors as `Term` instances. It additionally owns:

- the chain-shared C-variable index allocator;
- creation of C-variable Terms;
- publication of C-variable parent/child adjacency into the retained canonical/root `Mind` context;
- an incremental pack-candidate frontier;
- previous/current active Rule-term snapshots used to detect Terms that become unreachable.

Its pack policy distinguishes active Rule references from transient references retained by solutions, hypotheses, and values. Terms referenced only by transient projections remain candidates for later reconsideration. Removing a Term also unlinks its transient C-variable adjacency from the owning `Mind` context.

The canonical Term may persist, but C-variable adjacency maps remain runtime state owned and cleared by `Mind`; the factory must not describe those links as durable knowledge.

## PredicateFactory-specific contract

`PredicateFactory` canonicalizes predicates by the compound semantic descriptor represented by name Term and range.

Its pack policy removes deleted or otherwise unreferenced predicates after examining active Rules and the current solution/hypothesis projections. Unlike `DictionaryFactory`, it currently performs a full cache scan and does not own a separate incremental candidate frontier.

The name Term is canonicalized by `DictionaryFactory`; `PredicateFactory` does not own the lifetime of that Term or the query-result projections it consults during packing.

## Concurrency boundary

Synchronized canonicalization and counter operations protect specific factory-local mutations. They do not establish a blanket guarantee that the factory, iterators, or returned semantic units are independently thread-safe.

Because the same instances are visible throughout the Mind chain, documentation must not imply transaction isolation for Term or Predicate canonicalization. Child transaction orchestration remains governed by `Mind`; storage generation replacement remains governed by `User`.

## J2 acceptance criteria

J2 closes only when:

1. both class-level comments explain canonical representation, root ownership, exact-instance publication to child Minds, borrowed persistence attachment, generation reset, packing, and caller boundary;
2. neither comment describes these factories as normal child overlays or claims ordinary parent promotion;
3. category-specific identity, runtime metadata, and reachability cleanup remain explicit;
4. no public interface or executable behavior changes;
5. rendered Java 8 and Java 21 Javadoc contains both architectural introductions with resolved links;
6. the complete existing qualification contour remains green on the same final HEAD;
7. a paired review confirms the comments do not imply factory storage ownership, transaction-private canonical state, or a nonexistent common production class.
