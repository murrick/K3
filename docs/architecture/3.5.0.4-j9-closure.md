## Architectural conclusions

1. `Escalera` is a Mind-visible transactional linked snapshot, not a physical database or storage owner.
2. `IBase` represents one logical persistent schema/address space inside a selected generation.
3. `IData` owns selection and lifecycle of the physical generation and its base registry.
4. Factories and Escalera borrow IBase references; User/IData own acquisition, publication, flush, close, remove and storage-wide reindex sequencing.
5. Chain order is defined by `IStep.next`, not IDs, hashes or physical index positions.
6. Escalera checkpoints save and restore root frames; they are not durability commits.
7. `Escalera.update()` materializes the leading memory Step segment as persistent Sapato records in chain-preserving order.
8. Escalera indexes, factory caches and IBase physical caches are distinct structures with distinct authority.
9. A storage generation is visible only after complete canonical schema acquisition.
10. DUMB WAL, file layout, base codes, cache and recovery are implementation evidence, not universal IBase/IData guarantees.
