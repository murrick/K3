# Stage511: source-qualified dependent local and foreign cuts

Dependent Horn inspection now runs over an explicit local-X scope and every exact foreign logical cut. Independent targets are checked as X–A and X–B; physical members of one TRUST group are checked together with X. Products and refutations remain in their own cut result. This stage does not pool independent premises or export a cut's products into a shared X frontier.

## Concrete namespace obligations

Two physical contexts can both contain native Rule ID0. They can also contain identical source text. Neither native ID nor text is a global Source identity. For example, A's `!$u p(u);` and B's `!$v q(v);` may use different values, even inside TRUST; the constraint `!@u ~(p(u)&&q(u));` does not force their witnesses equal. Collapsing the two native-ID0 roots would produce a false refutation. The required test preserves both physical witness Sources and finds no such unit refutation. Different symbols do not assert value inequality.

Identical ordinary facts from two physical members likewise remain two original occurrences and two proof alternatives. Required tests retain both `!seed(1);` donors, their separate Horn products and their separate refutations. Identical existential declarations retain distinct witness Sources too. They are not deduplicated by a shared RuleFactory.

## Private ownership and qualified keys

Each physical member is natively checked against a separate canonical private projection, using the existing whole-row binding. A cut's single term arena reads these distinct owners with unique cut-local row keys. `Arena.captureFrom` pins the canonical original and its actual private Mind, while symbol/application graph keys identify its occurrence in the cut. `shapeFrom` creates only an owned symbolic shape for a checked Horn row. The existing single-owner calls keep their old keys and strict identity checks.

Every entry records its owning Mind, native rule, qualified atom key and actual physical Source. Predicate lookup and head materialization use that owner. Shared ordinary values still use typed semantic equality; witness symbols retain physical context/revision/view, original row and declaration position. X's symbol identity is the same physical Source across separate cut arenas, even though their runtime Node objects differ.

The production ledger reuses the same typed Horn/MGU/constraint kernel. Multi-member graph audit includes the cut name and every physical context/revision/local-X/view manifest. Source support and head/constraint ownership use qualified occurrence keys instead of bare numeric Rule IDs. Two independent fresh native projections reconstruct each cut's full graph. Local-only packets and their old audit format remain supported separately.

## Exact descriptors and provider ownership

`ContextDependentCutInspection` accepts a complete recipe map keyed by `local:<X UUID>`, `context:<target UUID>` and `trust:<group>`. Local X is always checked, including when there are no targets. An independent descriptor has one member; a named TRUST descriptor has every listed physical member. Repeated physical contexts, split/repeated group names, missing or extra recipe keys, wrong-cut original references and bounds refuse without a returned partial map. Context/cut counts and total effective rows are bounded. Supplied recipes do not imply automatic Horn closure.

Standalone descriptors/results are historical diagnostics, not authenticated topology or admission receipts. The internal `ContextPendingProductionSnapshotSession.inspectDependentCuts` constructs all descriptors from the owning lease's actual saved connection instances, initialization, targets and group metadata. The caller supplies recipes, never a replacement membership list. The method reuses qualified execution topology and the unchanged parent/child/retained/thread/active-owner/revision/whole-physical-member currentness guards before and after. Failure in a later cut exposes no successful earlier-cut prefix.

Foreign projection retains the actual `localX=false` metadata and uses the same native/text checks. Empty initialization and primary-only/ordinary single-clause restrictions remain; unsupported initialized views refuse as a whole. No old guard is weakened and no mixed/default writer is activated.

## Qualification and remaining work

Tests demonstrate that `!p(1);` in A and `!~p(1);` in B are individually compatible with an unrelated X; TRUST combines them and then refutes them with both physical Sources. A target cannot borrow a sibling's unit. With X's `left(v)&&right(v)->p(v)` and `~p(1)`, A's `left(1)` and B's `right(1)` produce the local collision only in their whole TRUST cut. Actual DB tests run both attachment orders, keep X/child/revision unchanged, and invalidate the lease when its second physical member changes.

This is complete inspection for the finite supplied per-cut recipes/unit pools. It is not a consistency/model/saturation certificate, all-Horn consequence enumeration, family eligibility or a publication receipt. Per-cut products remain private; synchronized common/private transport, productive coverage and independent original/actual-final/model admission gates remain open.
