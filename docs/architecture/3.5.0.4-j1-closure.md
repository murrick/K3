## Established architecture vocabulary

The pilot establishes the following documentation vocabulary for subsequent implementation types:

```text
representation
architectural role
owner
publication boundary
lifetime
transaction role
persistence role
cleanup authority
principal invariants
caller obligations
compatibility boundary
```

The User–Mind pair proves that these dimensions must remain independent:

- resource ownership is not active-context publication;
- logical transaction state is not storage ownership;
- a transaction overlay is not an independently durable snapshot;
- cleanup authority is not implied by retaining a handle;
- local synchronization is not a general thread-safety guarantee;
- a compatibility slot is not an internal lifecycle root.
