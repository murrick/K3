# Stage2r: primary source bindings and match-time witness lineage

## Concrete post-state counterexample

The native fixture is exists w p(w,1), forall x p(x,1)->q(x,1), and forall x
p(x,1)->r(x,1). Native ACCEPT creates generated stored q and r statements.
Their durable C-variables are independent roots owned by different generated
Rules, with no parent links. Reading only those statements cannot recover the
shared original p witness. This is expected GeneratedCVarMaterializer behavior,
not evidence that materialization itself is incorrect: the original assertion
and rules remain present and are not replaced by the two stored consequences.
An exporter that copied those consequences as unrelated existential facts would
lose a source-witness relationship. The test establishes why later transport
needs match-time evidence rather than guessing identity from final native IDs.

## Primary bundle evidence

ContextWitnessBundle.restoreObserved opens an owning-thread, disposable Session.
Each complete primary bundle is semantically projected, replayed with its exact
Source label, and re-extracted/checked as in stage2q. PrimaryEvidence records the
whole bundle, actual target native Rule ID, native witness IDs in global
first-use order, and its singleton primary support at depth0. Input duplicates
retain separate source alternatives even if native duplicate suppression reuses
a Rule. Session.replay scopes all operational IDs; they are not portable or
stable cross-round identity. A conflicting source occurrence still refuses
restoration; failure closes capture and never returns a partial Session.

The package-local replayProjected capture helper copies the supplied semantic
queue, requires it to be fully consumed, and otherwise follows the same primary
source attribution as ordinary replay. It does not authorize source labels
against real storage pins or qualify the asserted base by itself.

## Detached match-time observation

ContextProductionCapture.observeWitnessProjections is opt-in. Immediately before
ordinary ground application capture at the existing terminal observation point,
it freezes a ContextWitnessProjection when a real complete native application
contains witness arguments. It records:

- signed conclusion and actual opposite facts of excluded premise literals;
- ordinary arguments as detached semantic snapshots;
- witness argument lineages from current child to ultimate observed parent,
  retaining native term/owner/index/domini at each node;
- existing whole producer support alternatives for that native Rule.

A nonexcluded premise, unsupported literal/slot, cycle, lineage depth>8,
branch size>8 or argument arity>8 stops observation. Every recorded application
uses the existing event budget. The default capture path does not allocate or
record witness projections. Returned metadata is detached and immutable. Native
bindings, flags, inference and materialization are not changed.

The fixture's q/r match-time lineages reach the same primary witness despite
the later independent durable roots. Duplicate producer rules retain separate
producer source alternatives; signed premises and fixed arguments preserve their
meaning. A rule shape without a matching premise cannot invent lineage.

## What is still not proved

Primary support and producer support are different. A q projection labelled by
the q-producing rule is not yet the complete X/producer proof: donor proof groups
must still be reconstructed, including witness identity, minimum carried depth
and alternatives. No depth+1 derived support is synthesized here. Existing
nonordinary capture gaps remain present and cannot be discharged by this metadata.
Neither the scalar production pool nor AUDITED_HORN accepts witness applications.
The new observations cannot authorize runtime writes or witness transport.

Next: reconstruct one narrowly scoped witness application from authenticated
primary bindings plus producer labels, with exact source-group and carried-depth
controls. Then address whole-bundle result transport and stable round identity.
Mixed prefixes, generated witness dependencies, real effective views/pins and
shared atomic runtime gates remain pending. Question3 remains OPEN.
