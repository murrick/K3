## Architectural model

J10 separates the concrete DUMB layers as follows:

```text
DB    — physical generation owner and lifecycle coordinator
Base  — one baseCode/schema subset with durability and hydration
Data  — packed block store addressed by physical offsets
Index — (baseCode, semantic ID) to offset authority
WAL   — first before-images until a completed flush checkpoint
Integrity — committed subset checksums and legacy bootstrap
```

The generic `IData` / `IBase` contract from J9 is not enlarged with
DUMB-specific format promises.

## Demonstrated corrections

### DB close failure isolation

The focused red gate proved that historical `DB.close()` stopped at the first
base failure and did not attempt later bases. The correction now removes every
successfully closed base immediately, retains only failed bases for retry and
aggregates multiple failures through suppressed exceptions.

```text
red run: 30652087087
fix: 7ca03945ec1eecf0f97e76c4953f348c3dc20600
```

### Reversible reindex publication

The focused red gate failed the first publish operation after historical live
file deletion and proved that the original index was already missing. The new
protocol validates temporary files, backs up live core files, installs the
new generation and restores both live and temporary generations if publication
fails.

```text
red run: 30652541987
fix: 05f4cb953a1b8acdcb345c593ca5db38810ef6cb
aligned gate: 33f4e3d31a00de2ce58cc58339e3417373121fcd
```

This is exception atomicity inside the running process, not a claim of
crash-atomic multi-file replacement after power loss.
