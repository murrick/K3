## Governing invariant

> Transaction snapshot navigation, canonical cache/materialization, borrowed storage ownership, physical durability/recovery, index bookkeeping, and cleanup authority are separate lifecycle dimensions and must not be collapsed into one generic “cache” or “database” concept.

No storage format, interface signature, recovery policy, synchronization topology, chain order, or public behavior may change without focused executable evidence.

## Initial ownership model

```text
User
    owns selected IData plugin and published schema-specific IBase handles

IData
    owns one selected physical storage context and its logical-base registry

IBase
    owns one schema/base-code persistent address space, durability, recovery,
    physical cache, identifier allocation, and chain endpoint reconstruction

Escalera
    owns one Mind/factory-visible linked snapshot, nested root checkpoints,
    transient Step nodes, and derived ID/hash/predecessor acceleration metadata

Step
    memory-only linked node containing an unpersisted canonical unit

Sapato
    persistent link descriptor hydrated through its borrowed IBase
```

Factories borrow `IBase`; they do not own storage close authority. Child factory overlays remain memory-only even while their shared `User` reports storage open.

## Evidence questions

J9 must answer before Javadoc changes:

1. How are root and child Escalera snapshots constructed and published?
2. Which operations mutate only the linked snapshot, and which cross the physical storage boundary?
3. How do `mark`, `commit`, and `release` interact with the root pointer and derived indexes?
4. When are `Step` nodes converted into `Sapato` records, and why is chain order preserved?
5. Which component owns base close, flush, clear, remove, reindex, and recovery?
6. How do Base and Data caches differ from Escalera acceleration metadata?
7. What is authoritative for chain order: links, IDs, index order, or endpoint reconstruction?
8. What error paths are allowed to return absence, and which must surface corruption/failure?
9. Can partial storage acquisition, close, reindex, or hydration leave stale generation ownership?
10. Which APIs are internal architecture and which compatibility surfaces must be deferred to 3.5.0.5?

## Existing proved invariants retained

- an empty-root `Escalera.mark()` still creates a real frame;
- every parameterless completion consumes exactly one open LIFO frame;
- completion at depth zero fails;
- factories borrow generation-local `IBase` attachments;
- User / IData own storage termination;
- persistent chain endpoints are reconstructed from `next` links, never inferred from numeric ID order;
- DUMB WAL/integrity/recovery qualification remains authoritative for physical persistence.

## Candidate-review rule

A suspicious implementation shape is not a defect until its complete orchestration path is traced. In particular, DUMB reindex creates the temporary Mind and all schema bases in the canonical User order before iterating the source `HashMap`; therefore source-map iteration alone does not demonstrate base-code permutation.
