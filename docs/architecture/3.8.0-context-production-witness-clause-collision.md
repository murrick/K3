# Stage3b: positive witness refutations of sourced universal clauses

## Concrete rule-mediated counterexample

X supplies `!$w p(w,1) && flag(w,1);` and the auxiliary productive p->warm
rule used by the detached-packet fixtures. A derives q(w,1), B derives r(w,1),
both at depth1 with proofs {X0,A1} and {X0,B2}. Their common-input family is
MERGED: the union has no directly opposite literals.

C supplies `!@w q(w,1) && r(w,1) -> ~flag(w,1);`. Neither A's nor B's packet
alone refutes that clause. Their union does: the one common witness w makes all
literals of `~q(w,1) || ~r(w,1) || ~flag(w,1)` false. A separate actual native
pass followed by the existing family opposition check confirms this distinction:
A-only and B-only yield MERGED, the union yields CONFLICT (three opposite pairs).
The native producer verifier reconstructs these steps successfully; successful
proof reconstruction alone is not a consistency check.

This is a collision of X-dependent products against a rule in one exact target
cut, not a union of raw sibling declarations. It demonstrates the need to qualify
merged products against rules as well as compare their signs.

## A bounded refutation certificate

ContextWitnessClauseCollision.inspect takes a sealed Packet, one exact target
Cut, sourced declarations and depth/work/event bounds. It returns COLLISION only
with positive proof evidence. All other outcomes are INCOMPLETE; the API has no
COMPATIBLE, SATURATED or ACCEPTED result and never returns a candidate Packet.
The result records the exact input Packet identity and target context/revision/view.

The carried proof pool and X cut are validated using the family boundary.
Declaration inputs are copied; at most64 are allowed. Source labels must match
parent X or the target foreign cut, with a target declaration present. Duplicate
source occurrences and unrelated/new revision/view/role labels are refused.
The source-label/snapshot correspondence remains a trusted-caller assumption;
this is not an authentication mechanism for a live Context revision.

A fresh disposable Mind compiles each sourced declaration under an owning
capture, without calling native link or importing the witness carrier as primary
knowledge. The capture must have exactly the supplied source bindings and no
gaps. The entire original Rule is checked before its structural shape is used
as universal clause evidence: no query/generated rule, one to eight conjunctive
branches, at most two universal variables, at most three literals per clause,
and only TVARIABLE or ordinary fixed TERM arguments. Existential TERM witnesses,
functions and unsupported calculated/system predicates are refused. Shape
metadata from an arbitrary application is never accepted as a proved rule.
Every declaration is validated before any certificate is constructed; a later
unsupported declaration cannot leave an earlier evidence prefix.

For each clause, matching selects one opposite proved Item per literal and one
consistent assignment of all universal variables to canonical Origin or fixed
semantic slots. Repeated occurrences share their assignment, independent
variables may bind equal or unequal slots, and fixed values/signs/arity must
match exactly. Two independent existential witnesses cannot stand in for one
shared universal variable. Instantiation uses universal elimination, valid for
any admissible value under the confirmed @x contract; it makes no finite-domain
assumption.

A certificate contains the exact sourced clause, immutable assignment, ordered
opponent Items and immutable whole refutation support alternatives. Support
construction takes the Cartesian product of donor alternatives and includes the
rule's exact Source. Identical source sets retain minimum depth. Distinct
alternatives are not flattened. Refutation depth is max(donor depths)+1 for this
single clause-refutation proof step; the declaration has primary depth0. It does
not count successive native binary resolutions. Evidence and proof alternatives
are bounded at256 each. Depth/work/event/scope failures return no evidence prefix.

This component checks/constructs the bounded falsified-clause certificate; it
neither computes new knowledge nor replaces native application closure.
