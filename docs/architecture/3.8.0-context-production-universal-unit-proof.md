# Stage3al: detached flat universal unit resolution and opposition

ContextUniversalUnitProof proves a single source-authenticated flat resolution
step with at least one whole unit parent. It does not construct transport
Products, replace the old ground Collision type, establish coverage or grant
write admission. The stage3ak universal-unit transport refusal remains unchanged.

## Why a distinct proof result

The existing ground Collision stores two concrete opposite Facts. A universal
unit is a Clause with variables and has no Fact representation. For example

    @x p(x,1)
    @y ~p(2,y)

are incompatible: the independently renamed parents unify with x=2, y=1.
This is not detected by comparing whole universal schemas for equality, nor by
identifying their local variable numbers. Conversely @x p(x,x) and ~p(1,2)
are compatible: repeated occurrences cannot bind independently. Quantification
still covers every admissible value, including unmentioned values.

The new immutable private-constructor Proof records both whole parents, exact
pivot indices, both actual parent Supports and their exact source union at
max(parent depths)+1. contradiction=true and conclusion=null represents a proved
empty resolvent; this is not an ordinary Clause or a fabricated concrete Fact.
For a nonempty result contradiction=false and conclusion is the actual schema
or ground Clause. Evidence.proved distinguishes opposition from failure: failed
evidence has no proof prefix. dependsOnX describes provenance, not admission.

## Authentication

The primary-only API provePrimary uses actual native-bound X and optional foreign
Snapshots, without creating the old ground Frontier: its existing universal-unit
start gate remains unchanged. A null foreign argument selects X alone. Evidence
records the exact x/target snapshots and input=null in this primary-only mode.
The frontier-based prove API requires an actual sealed Frontier and one of its
exact cut Snapshots. Both complete proposed parents authenticate up to alpha-equivalence
against actual whole primary declarations in X plus that cut, sealed shared
Products, or successful stage3ai compound-resolution Evidence bound to that
same input and target. The primary-only mode accepts no detached evidence.
Snapshot role/source identities, distinct context identity, the64-declaration
bound and witness exclusion are checked without the old unit refusal.
Every supplied evidence object is checked before use.
Raw sibling declarations, absent/invented clauses, stale-input proofs, other-cut
proofs and failed evidence cannot authenticate. All actual independent parent
recipes participate in the Cartesian product, preserving distinct source/depth
alternatives. No caller Support argument exists.

This stage intentionally does not recursively consume its own detached outputs
or arbitrary native residual ledgers. That requires a separately sealed unit
transport/ledger integration. Proof support does not migrate between cuts by
passing detached evidence from A into B.

## Structural rule and bounded failure

The existing standardize-apart flat MGU implementation is shared through a new
package-private resolveWithUnits path. The old compound-only resolve guard is
unchanged. The unit path removes exactly the selected opposite pair, applies
the coherent MGU to every remaining literal, retains independent remaining
variables and factors identical literals by idempotence. Only successful
unit/unit unification yields the empty resolvent. The normal Clause constructor
continues to reject empty clauses.

Under ordinary universal semantics over the nonempty admissible-value universe,
all instances of both parents hold. Their MGU instances eliminate the opposite
pivot. The remaining universally closed clause follows; if both remainders are
empty, no interpretation satisfies both parents. No known-value enumeration or
sampled witness is part of proof generation. Flat slots are universal variables
or opaque ordinary ground values; function terms containing variables and
existential witnesses remain outside scope.

One work budget covers evidence validation, source authentication, MGU and every
Support alternative. Depth overflow, bounds, failed authentication and the
256-alternative cap return proved=false with an empty proof list, including late
failure after an earlier alternative. Historical proofs confer no current-view
or authoring authority.

## Validation and next boundary

The driver includes generic p→q unit resolution, universal/ground and crossed
universal/universal opposition, coherent/incoherent repeated variables, distinct
ground constants, and a sealed composition-derived left(z) donor producing
done(z) with all three original Sources at depth2. It rejects missing sealed
evidence, stale input, wrong cut, foreign sibling, invalid pivot, two compound
parents and resource/depth limits. Proof lists are immutable and the shared
Frontier remains unchanged. The old transport unit gate is checked explicitly.

Independent exhaustive small interpretations include every actual constant plus
fresh unmentioned values. They check nonvacuous generic consequences and no
parent model for typed opposition. These are counterexample searches, not a
finite-domain semantics or the proof of universal validity.

Final validation counts are recorded in the main checkpoint and recovery journal.
Next: sealed unit-support ledger, independent unit-pair coverage and typed
opposition transport, before universal private closure/family coverage. Ground
writers/default authoring and open question3 remain unchanged.
