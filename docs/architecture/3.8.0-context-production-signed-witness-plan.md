# Stage463 — separate signed-witness data plan and independent audit

## Contract

ContextSignedWitnessPlan is package-private detached DATA, not inference, row eligibility,
a coverage certificate, a pending lease or write permission. It records each exact original
Entry once, retaining both its logical cut and physical member Snapshot. Every signed or
positive witness row stays whole. Non-bundle clauses remain OPAQUE_CLAUSES with their original
clause objects; no applicability decision or ground-fact export is made for those rows.

Each witness atom retains polarity/predicate/arguments and an exact singleton original Source
at depth0. A witness argument has a Source/binder Origin; an ordinary value stays an immutable
SemanticTermSnapshot. Different Sources with binder0 stay distinct; different binder0/binder1
inside one Source also stay distinct. Signs do not alter Origin identity. Bounds: at most15
foreign logical cuts, explicit total row allowance1..1024, witness count/atoms/arity at most8,
and an explicit work budget. These are data representation bounds, not native inference
support for every represented shape. No provisional plan is exposed on incomplete capture.

Topology validation checks exact initialized snapshot identities and unique physical contexts,
including all original TRUST members. A first-member routing inventory is never substituted
for original member provenance. Lists and row fields are immutable under the ordinary detached
graph precondition. The plan is deliberately not connected to NativeRows/InitialEntry/writer.

ContextSignedWitnessPlanAudit reads original bundle fields DIRECTLY rather than rerunning the
builder or native inference. It checks the requested snapshot identities/row policy, complete
ordered original rows/opaque clauses, every sign/value/binder and exact depth0 Source proof.
A sealed receipt only describes that historical plan. Each check reruns the independent audit
with fresh work; it neither refreshes a provider view nor grants admission. Failed/bounded
audit exposes no receipt. This is not a hostile-reflection serialization security boundary.
