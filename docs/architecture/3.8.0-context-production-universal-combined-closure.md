# Stage3ap: combined private flat binary resolution

The sealed ContextUniversalUnitLedger now offers stepCombined; the existing
unit-only step is unchanged. ContextUniversalUnitRounds.inspectCombined closes
these combined private steps before the existing complete-family barrier.
This is opt-in binary-resolution scope, not general universal write admission.

## Actual ledger parents and proof modes

The universal compound kernel now accepts complete parents from actual sealed
ledger rows through proveFromLedger. Every actual independent whole-source
alternative participates, retaining max(parent depths)+1. The existing checked
standardize-apart flat MGU implementation is reused; it does not identify parent
variable names or enumerate known values. Compound Evidence records its exact
historical ledger object. Receipt-only proof consumers reject ledger-mode
Evidence, so matching X/input/target snapshots cannot smuggle stale/different
ledger evidence into an older authority mode.

The compound coverage auditor gained auditLedger. It independently enumerates
all whole compound pairs INCLUDING self pairs and every feasible pivot using the
argument-position equality graph. It requires actual sealed consequences with
exact source/depth recipes from that ledger. The kernel still constructs the
conclusions: this is independent enumeration/feasibility, not another MGU proof.

## One immutable combined step

A combined step classifies each actual parent pair: at least one unit uses the
unit kernel; two compound parents use the compound kernel. Both use only the
same immutable input. New conclusions join the successor ledger and cannot
feed another inference in that step. A compound resolvent factoring by literal
idempotence to a universal unit is a real generic row, not a sampled fact.
It becomes a unit donor only on the next step.

Before any successful step, both independent unit and compound obligation audits
run under the SAME work budget as enumeration, kernel calls and row merging.
All whole-source alternatives/minimum depths, proof/clause caps, typed opposition
and no-prefix failure semantics remain intact. Step.evidence and compoundEvidence
are separate immutable lists bound to the same ledger. Failed steps expose
neither list. An opposition can return only after both audits complete.

## Private closure and existing family barrier

inspectCombined repeatedly runs combined steps until exact proof recipes are
unchanged, or an X-dependent typed opposition is proved. Local rounds, cumulative
depth and one opening/step/audit work allowance bound the process. Each receipt
records includesCompounds; unit-only inspection keeps that flag false. No common
carrier is visible early to another sibling. Only positive-depth X-dependent
rows export; private foreign-only chains remain available locally.

The existing complete exact-input barrier carries those authenticated rows and
requalifies them in every cut next round. Missing/duplicate/stale/incomplete cuts
still block the whole barrier. General family admission remains unknown; the
same Frontier can also have old unit-only observations, so a merged/unchanged
pool alone cannot certify combined family coverage.

## Concrete controls

* X p(x)||left(x), A ~p(x)||left(x), left(x)→done(x): first combined step proves
  generic left at depth1 with two original Sources; done is absent until step2,
  when it has all three Sources/depth2. Combined local closure exports done and
  the next common round refutes B ~done(9).
* Universal original composition counterexample X ~a(x)||~b(x)||~c(x), A d→a,
  B d→b, C d(1),c(1): unit-only observations really reach an unchanged common
  pool without proving the contradiction. Combined closure proves the exact
  five-assertion-source collision at barrier3 in both sibling orders.
* Foreign a||b, ~a||c, ~c||d produces b||d only on its second immutable local
  step. With unrelated X, that closure exports nothing and cannot collide with
  another sibling's ~b(1),~d(1). With X ~b||out it instead produces the appropriate
  X-dependent result, refuting ~d(1),~out(1) at barrier2 with all six Sources.
* Apart-renamed self-resolution of @x p(x,1)||~p(2,x) still yields
  p(1,1)||~p(2,2) with the single original Source/depth1.

The driver also checks independent dual audits, missing compound proof controls,
exact-ledger stale evidence, immutable evidence lists, no same-step feeding and
work/depth/local-round failures without unit/compound output prefixes.

clause), universal model/countermodel certificates, witness/function language

resolution is not that separate factoring rule. @x still ranges over every
admissible value including unmentioned values. Native residual acquisition,
combined-family coverage certification, default authoring and question3 are not
