# KANGER 3.5.0.4 — J3 overlay factory checkpoint

## Status

J3 is open.

Scope:

```text
DomainFactory
CommentFactory
```

This pair introduces the first explicit child-factory overlay vocabulary after J2 established the separate exact-instance lifecycle of `DictionaryFactory` and `PredicateFactory`.

No production Javadoc has been changed at checkpoint opening.

## Common child lifecycle

Each `Mind.init()` creates a factory instance owned by that exact Mind. Child construction then initializes it from the visible parent:

```text
new child Mind
    -> create child factory
    -> transaction(parent factory)
    -> child Escalera overlays parent cache
    -> child storage connection remains null
```

The parent owns completion:

```text
parent.commit(child)
    -> factory commit(child factory)
    -> splice child canonical additions
    -> rebind promoted units to parent Mind
    -> merge category-specific auxiliary state

parent.release(child)
    -> discard child logical changes
    -> retain only result/diagnostic projections selected by Mind.release
```

The schema `IBase` is attached only to a root factory in an open storage generation. Child factories inherit visible semantic state through the parent/cache relationship, not storage close authority.

## Shared protocol to document

Both classes must explain:

- one factory instance per Mind level;
- child initialization through `transaction(parent)`;
- `Escalera` as transaction-aware canonical cache overlay;
- root-only borrowed `IBase` attachment;
- distinction between typed `commit(childFactory)` and no-argument cache checkpoint `commit()`;
- parent authority over child completion;
- generation-local `top` anchor;
- child `clear()` as overlay reset and root `clear()` as generation reset;
- `User` / `IData` ownership of storage close;
- no blanket thread-safety guarantee from local synchronization or concurrent collections.

## DomainFactory contract

### Representation

`DomainFactory` is the canonical registry and transaction overlay for `Domain` units visible at one Mind level.

Domain identity includes the predicate, antecedent/consequent polarity, arguments, and Rule context used by the current equality/hash contract. Construction also classifies whether arguments make a Domain substitutable or abstractive.

### Transaction state

A child factory receives:

```text
Escalera overlay over parent cache
copy of parent waiters set
no storage connection
fresh sequence anchor
```

Parent commit promotes child units and merges child waiters.

The `waiters` set is semantic deferred-domain metadata, not logging. Linker reads it while matching complete domains against stored opposite-polarity masters. The set therefore participates in visible inference state and must be described separately from the canonical cache.

### Cleanup

`pack()` removes deleted Domains and removes the same objects from `waiters`. It does not implement general reachability collection for active undeleted Domains.

The child `clear()` path reinitializes from the parent DomainFactory; the root path clears the cache and current generation.

### Concurrency boundary

`waiters` uses a copy-on-write set and add operations are synchronized, but this does not make mutable Domain units or the full factory protocol independently thread-safe. Mind transaction completion remains the publication boundary.

## CommentFactory contract

### Representation

`CommentFactory` is a transaction-aware registry for source/provenance comments keyed by Rule ID plus reserved header/footer IDs.

Unlike ordinary append-only child additions, an existing parent comment can be redefined in a child. The factory therefore owns an explicit copy-on-write overlay in addition to its Escalera cache.

### Effective view

Lookup order is:

```text
local override
    -> parent effective view
    -> local/raw cache or root storage hydration
```

A child update of an inherited Comment first creates a child-owned copy. The parent object is not mutated before commit.

### Commit and release

Typed parent commit:

- promotes child cache additions;
- copies child overrides into the parent context;
- merges dirty-update IDs.

Release discards the child factory with its uncommitted overrides.

The no-argument `mark / commit / release` checkpoint protocol additionally journals:

```text
overrides snapshot
dirtyUpdates snapshot
```

This auxiliary journal is required because Escalera rollback alone cannot restore copy-on-write metadata.

### Persistence

New comments flow through cache update. Changes to already persistent comment IDs are tracked in `dirtyUpdates`; root update writes the effective value back into the existing storage step.

`applyOverrides()` applies accumulated root overrides before pack. Child pack must not publish overrides into parent/raw state.

### Proven regression contract

`KangerFactorySafetyRunner` verifies:

```text
child override visible in child only
parent unchanged before completion
release preserves original parent value
commit publishes child value
committed persistent override survives close/reopen
```

These are architectural lifecycle postconditions, not test-only implementation detail.

## Comparison boundary

| Dimension | `DomainFactory` | `CommentFactory` |
| --- | --- | --- |
| Child semantic state | Cache overlay plus copied waiters | Cache overlay plus parent view and COW overrides |
| Existing parent-unit mutation | Domain creation/visibility through overlay | Explicit writable child copy for inherited Comment |
| Auxiliary state | `waiters` | `overrides`, `dirtyUpdates`, `overlayStack` |
| Checkpoint journal | Escalera cache | Escalera cache plus auxiliary overlay snapshot |
| Root persistence update | Cache update | Cache update plus in-place dirty record updates |
| Pack | Delete marked Domains and waiter entries | Apply root overrides, then delete marked Comments |

The pair is intentionally asymmetric. Javadoc must not flatten both into a generic “factory transaction” description.

## J3 acceptance criteria

J3 closes only when:

1. both class-level comments explain per-Mind ownership, child initialization, parent completion, root-only storage attachment, and cleanup;
2. Domain waiter metadata is documented as inference state with copy/merge lifecycle;
3. Comment effective-view, copy-on-write, dirty-update persistence, and auxiliary checkpoint journal are explicit;
4. typed commit and no-argument checkpoint commit are not conflated;
5. no interface or executable behavior changes;
6. Java 8/21 rendered pages contain both architectural introductions with resolved links;
7. factory overlay regression and the complete qualification contour remain green on the same final HEAD;
8. paired review confirms no wording implies child storage ownership, pre-commit parent mutation, or universal factory semantics.
