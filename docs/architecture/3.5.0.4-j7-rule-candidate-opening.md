# KANGER 3.5.0.4 — J7 RuleFactory / RuleCandidateIndex opening

## Scope

J7 isolates the Rule storage and candidate-selection subsystem because it combines several independent lifecycle domains:

```text
RuleFactory
  canonical Rule cache / storage view
  child Escalera overlay and typed commit
  domain and term ID metadata
  generated-to-primary promotion overlay
  Linker continuation action flag
  root pack/update materialization

RuleCandidateIndex
  predicate/polarity/arity signatures
  direct-term positional filtering
  fallback membership for non-positional rules
  nested mutation journals
  versioned per-Mind batch summaries
  lock-order and hydration boundary
```

The checkpoint does not authorize new KANGER semantics, candidate policy, persistence formats, public API, or synchronization topology. Production changes are permitted only for a demonstrated invariant violation protected by a focused permanent regression gate.

## Preliminary ownership model

`RuleFactory` owns the canonical Rule lifecycle for one `Mind` transaction layer. `Escalera` and optional `IBase` storage remain the semantic owners of Rule objects and IDs.

The following structures are derived metadata and never become Rule authority:

```text
localDomainIndex
localTermIndex
RuleCandidateIndex.signatures
RuleCandidateIndex.fallbackSignatures
RuleCandidateIndex.positions
RuleCandidateIndex.batchSummaries
```

They retain Rule IDs only. Candidate hydration, logical deletion checks, and Mind-dependent semantic effects must occur after selection through the factory's canonical `get(id)` path.

## Transaction model to verify

A Rule checkpoint must keep these state components aligned:

```text
Escalera frame
local domain index frame
local term index frame
candidate-index journals
primary-promotion frame
promotion effective-view cache
Linker continuation action state
```

Commit must retain surviving state and collapse only the saved frame. Release must restore all state that participates in lookup, effective visibility, or Linker continuation.

Child-to-parent typed commit must preserve parent-first visibility while merging child-owned IDs and promotion intent without leaking child Rule object ownership.

## Promotion model to verify

A generated Rule may be exposed as an independent primary Rule inside a transaction without mutating the visible parent object.

Expected phases:

```text
promotion requested
  -> primaryPromotions records Rule ID
  -> effectiveView returns a transaction-local non-generated projection

child commit
  -> promotion intent transferred to parent

root pack
  -> generated/query/second/cause state materialized on raw Rule
  -> ID remains stable

root update
  -> already-persisted promoted records updated in storage
```

The temporary projection must not become an independent canonical Rule and must not change persisted identity.

## Candidate-index model to verify

The candidate index is an acceleration layer over three correlated ID maps guarded by one `ReentrantReadWriteLock`.

Candidate selection must preserve this lock-order invariant:

> Candidate metadata locks protect coherent ID snapshots and memo publication only. Rule hydration, deletion checks, TValue resolution, and Mind-dependent semantic effects execute outside candidate metadata locks.

Resolved selection therefore has four phases:

```text
resolve query values outside lock
copy/filter IDs and read memo/version under lock
hydrate Rules and compute semantic batch effects outside lock
publish memo only if version is unchanged
```

`version` invalidates stale memo publication after index mutation. `WeakHashMap<Mind, ...>` bounds memo ownership to active Mind generations and is not persistent state.

## First audit candidate

Initial source inspection shows that `RuleFactory.mark()` and `release()` journal cache state, both layered indexes, promotion state, and candidate metadata, while the `action` flag is not visibly journaled.

Because `action` is consumed by `Linker` as a continuation signal, J7 will first attempt to reproduce the following suspected asymmetry:

```text
dropAction()
mark()
add speculative Rule -> action=true
release()
  Rule and indexes disappear
  action must return to false
```

No production correction will be made unless a focused red gate demonstrates the defect on the current J6-qualified baseline.
