# 3.5.0.4 — local review and test runbook

This runbook is the manual companion to the permanent GitHub Actions gates. It
is intended for source review, rendered Javadoc inspection and a local semantic
smoke/qualification run before promoting `develop/3.5.0`.

## 1. Select the branch and inspect the exact revision

```bash
git fetch origin
git switch arch/3.5.0-core-consolidation
git pull --ff-only

git status --short
git log -1 --oneline
```

The working tree must be clean. Compare the printed HEAD with the qualified
closure SHA recorded in PR #31 and `00_KANGER` after the stage is closed.

## 2. Full Maven regression corpus

```bash
mvn --batch-mode --no-transfer-progress test
```

This is the broadest local first pass. Do not continue to manual storage
experiments if the corpus is red.

## 4. Generate rendered implementation Javadoc

Linux/macOS/Git Bash:

```bash
rm -rf build/javadoc
mkdir -p build/javadoc

find \
  kanger/src \
  kanger-udf/src \
  kanger-data-dumb/src \
  kanger-console/src \
  -name '*.java' -print \
  | LC_ALL=C sort \
  > build/javadoc-sources.txt

javadoc \
  -quiet \
  -encoding UTF-8 \
  -docencoding UTF-8 \
  -charset UTF-8 \
  -Xdoclint:none \
  -d build/javadoc \
  @build/javadoc-sources.txt
```

Open:

```text
build/javadoc/index.html
```

Recommended reading order:

```text
User → Mind
Parser → Compiller
Linker → Calculator → Analyzer
DictionaryFactory / PredicateFactory
DomainFactory / CommentFactory
TVariableFactory / TValueFactory
FunctionFactory / FValueFactory
LibraryFactory
RuleFactory
Escalera → IBase / IData
DB → Base → Data
```

The architectural workflow validates the rendered pages on both Java 8 and
Java 21. A local run on either supported JDK is useful; GitHub Actions remains
the authoritative cross-version result.

## 5. Run the public-type coverage inventory

```bash
python3 tools/audit_architectural_javadoc.py \
  | tee build/javadoc-coverage.tsv
```

Interpretation rules:

- KANGER owner/orchestrator classes are the completion criterion for 3.5.0.4;
- public interfaces, units, stores, enums, exceptions and leaf DTOs are input to
  `3.5.0.5 — public API documentation audit`;
- diagnostic/test runners are not product Javadoc debt;
- vendored `org.mozilla` Rhino sources are outside KANGER documentation
  ownership.

## 6. Manual source review

For each checkpoint document under `docs/architecture/3.5.0.4-*` verify:

1. ownership matches actual fields and callers;
2. commit/release/flush/close terms are not conflated;
3. cache/index metadata is never described as semantic identity;
4. documented ordering matches production statement order;
5. exception guarantees do not overclaim crash atomicity;
6. no public API or storage-format promise was invented by documentation.

Useful aggregate checks:

```bash
git diff --stat fix/3.4.4.2.3-mind-lifecycle-safety...HEAD
git diff --check fix/3.4.4.2.3-mind-lifecycle-safety...HEAD
git log --oneline --decorate --reverse \
  fix/3.4.4.2.3-mind-lifecycle-safety..HEAD
```

## 7. Optional runtime smoke session

Run the console through the project’s usual launch method and exercise at least:

```text
load/open an existing storage;
execute representative stored and query rules;
run a calculated function and a system predicate;
commit and release one child transaction;
close and reopen storage;
perform a controlled reindex on a disposable copy;
verify the same query answers after reopen/reindex.
```

Use a disposable copy for destructive storage operations. The permanent CI
runners cover injected failure paths; the manual session is intended to catch
integration, packaging, console and environment regressions visible to a human
operator.

## 8. Acceptance checklist

The stage is ready for personal acceptance when:

```text
[ ] working tree is clean and HEAD matches the qualified closure
[ ] mvn test is green
[ ] focused invariants are green
[ ] Javadoc renders and the reading path is coherent
[ ] coverage inventory has no unexplained owner/orchestrator gap
[ ] existing databases open, answer representative queries and reopen cleanly
[ ] disposable reindex preserves answers and storage readability
```
