## Established architecture

### FunctionFactory

The class contract establishes `FunctionFactory` as the per-`Mind` overlay for separately allocated compiled Function occurrences.

It distinguishes:

```text
schema identity
owning Mind
name Term
range
persistent FunctionBinding
argument structure
reserved result slot
```

Factory add does not perform structural canonical deduplication. Binding remains persistent semantic metadata with source-defined `LEGACY_AUTO`, `INFRASTRUCTURE`, and `UDF_DYNAMIC` dispatch contracts, including backward-compatible hydration of older records.

The add path is explicitly non-inert: after local cache insertion it may invoke Calculator under the historical `Function.isCalculable()` predicate.

### FValueFactory

The class contract establishes `FValueFactory` as the canonical result registry and child overlay for materialized Function/substitution state.

One FValue stores:

```text
schema ID
owning Mind ID
Function identity
result Term identity
captured substitution stamp
```

Add requires a complete Function. Operational lookup uses the Function hash-base bucket, excludes transaction-visible invalidated IDs, and verifies Function ID plus the current substitution stamp through `FValue.equalsTo(Function)`.

Logically deleted matching results remain reusable before physical pack. Invalidated results are excluded from lookup and cannot be resurrected by ordinary add.

Binding-sensitive invalidation remains explicit:

```text
UDF_DYNAMIC
    invalidated by matching UDF replacement

INFRASTRUCTURE
    not invalidated by UDF replacement

LEGACY_AUTO
    invalidated only when no exact or zero-range infrastructure fallback exists
```

## Category-specific checkpoint model

The corrected FValue auxiliary state is:

```text
invalidatedStack
    complete snapshots of transaction-visible invalidated IDs

actionStack
    snapshots of Linker continuation state
```

This remains distinct from:

```text
TValueFactory
    additions delta + action snapshots

CommentFactory / LibraryFactory
    copy-on-write override + dirty-update snapshots

DomainFactory
    complete waiter snapshots
```

No universal factory transaction journal is introduced.
