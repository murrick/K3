# Stage2s: reconstructing an observed step from primary witness bundles

ContextWitnessPrimaryStepVerifier reconstructs proofs for a narrow surface:
actual native witness applications with one or two premises, all proved directly
by the owning Session's verified primary bundles. It produces scoped Step
records, not SATURATED, a transport bundle, a runtime decision or a coverage
certificate. If any observed step cannot be reconstructed, the result contains
no verified prefix.

## Preconditions and matching

The verifier obtains bindings and observations from the same live owning Session;
callers cannot combine arbitrary snapshots and native IDs. It checks source
occurrence/native Rule consistency and a single qualification cut: at most one
X context and one external context, with one revision/view per role. Contradictory
roles for one context or independent sibling contexts in the same cut are refused.
These checks validate supplied labels, not their authenticity against live pins.

Non-bundle producer inputs must have complete ordinary native shape metadata,
at most two native variables and at most three literals per clause. Derived
inputs and mixed witness producers remain outside scope. Every observed
application must independently match one declared producer clause: predicates,
signs (premises reversed back to clause literals), constants and one consistent
variable assignment across every argument. Clause literal order is immaterial.
Assignments compare ordinary semantic values or exact ultimate witness root
term/owner/domini in the current replay. This comparison never infers a new
conclusion or changes native bindings.

Each actual premise then matches a primary bundle atom by predicate/sign/arity,
fixed semantic arguments and exact witness ordinal-to-root binding. Matching
occurrences contribute their whole singleton primary supports, including all
source alternatives. A witness root from another scope cannot replace the
required shared witness. Multiple different roots can legitimately satisfy a
producer with independent variables. Conclusions may reference only known
primary roots; newly generated witness identities are not guessed.

## Source groups and depth

For each complete producer support alternative and each Cartesian combination
of donor alternatives, the resulting support is their whole source-set union.
Alternatives are never merged into one larger proof. Equal whole groups share
their minimum depth. Depth is max(producer depth, donor depths)+1. This scope
admits primary producer and donor proofs at depth0 only, so reconstructed steps
have depth1. A depth0 limit or work exhaustion refuses the result. This does not
yet prove carried depth through a derived chain or across synchronous rounds.

A primary conjunction contributes one whole source group even when it supplies
two premises. Foreign-only groups can remain valid within the private cut;
they are not thereby X knowledge. No export is implemented here; any future
export must retain the existing usesX boundary. Producer labels alone cannot
replace the full donor/producer group.

The existing nonordinary primary/conclusion/premise/materialization capture gaps
remain in the native snapshot. They are expected on this proof surface but are
not discharged as completeness evidence. Other gaps stop reconstruction.

## Controls and boundaries

The 27-check runner exercises exact X/producer groups, duplicate producer and
donor alternatives, joint source bundles, signed premises, fixed arguments,
alpha-renamed producers, independent witness permutations, false diagonals,
independent versus shared-variable joins, and depth/work stops. Wrong producer
head/constants and swapped witness correspondence are rejected independently of
native matching. Source conflicts, raw witness inputs without bundle bindings,
independent sibling cuts and generated witness chains refuse reconstruction.

The p->q->r chain is an explicit boundary: generated stored q has a new durable
root, and q is not a directly bound primary donor. The verifier refuses instead
of assigning it the primary p root or silently resetting depth. Extending this
requires authenticated correspondence between observed applications and stored
materializations plus a proof-closure protocol.
