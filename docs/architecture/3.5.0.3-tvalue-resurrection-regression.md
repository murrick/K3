# KANGER 3.5.0.3 — TValue canonical resurrection regression

## Scope

This checkpoint closes the regression gap identified by the TValue canonical
resurrection audit.

Regression runner:

```text
kanger-console/src/org/kanger/KangerTValueResurrectionSafetyRunner.java
```

## Invariant

Before physical removal by `TValueFactory.pack()`, logical deletion is a
reversible transaction-visible state and must not terminate canonical identity.

```text
add(variable, value)
    -> canonical TValue A / id A

A.setDeleted(true)
    -> A remains present but logically hidden

add(variable, value)
    -> A is found
    -> deletion mark is cleared
    -> object identity and id A are preserved
```

After `pack()` physically removes the deleted canonical value, a later add may
and should allocate a new object and identifier.

```text
A.setDeleted(true)
pack()
    -> A physically removed

add(variable, value)
    -> canonical TValue B / id B
    -> B != A
    -> id B != id A
```

## Covered assertions

The runner verifies:

1. logical deletion is observable before resurrection;
2. resurrection returns the same Java object;
3. resurrection preserves the same canonical ID;
4. resurrection clears the deletion mark;
5. `find(variable, value)` returns the restored canonical object;
6. `pack()` removes the logically deleted object from canonical lookup;
7. a post-pack add creates a new object and ID;
8. the replacement is active rather than deleted.

## Production impact

No production code changes are made.

The runner protects the existing intentional absence of a deleted filter in
`TValueFactory.find(...)`. Adding such a filter would make logical resurrection
allocate duplicate identities for one semantic `(TVariable, ITerm)` pair.

## Verification status

The runner is committed as executable source. No GitHub Actions run is claimed
for this checkpoint until the branch workflow executes it explicitly or the
runner is invoked by another qualification gate.

## Adjacent finding

During source inspection, `TValue.compareTo()` was identified as a separate
invariant candidate:

```java
return (int) (tVarId == o.getTVarId()
        ? id - o.getId()
        : tVarId - o.getTVarId());
```

It performs long subtraction followed by narrowing and therefore requires a
separate ordering-contract audit. It is not part of the resurrection invariant
and must not be bundled with this checkpoint.
