# Stage3a: immutable witness-family barrier and direct opposition evidence

## Concrete counterexample

Let X supply `!$w p(w,1) && flag(w,1);` and an auxiliary X rule
`p->warm`. The auxiliary product makes this an observed productive initial
packet. From that exact same detached packet, a private A pass uses `p->q`,
while a separate private B pass uses `p->~q`. Both actual native passes succeed
independently. Their results contain respectively q(w,1) with proof {X0,A1}
and ~q(w,1) with proof {X0,B2}, both at depth1.

Union without a cross-result check would contain opposite constraints on the
same original existential binder. This is a concrete conflict, despite each
branch succeeding. It is not a conflict between raw sibling facts: both products
are X-dependent. A control with two independent X existential binders yields
q(w,1) and ~q(v,1), and remains compatible. Predicate/sign alone cannot decide
opposition; exact canonical Origin and fixed semantic arguments must match.

## Sealed input and expected cuts

A private Packet now has an opaque allocation identity. A successful exportNext
also seals its exact input identity and actual captured producer Source labels.
These are barrier metadata, not native rule IDs, source authentication, coverage
certificates or statements about logical completeness. Constructors remain
private; callers cannot submit arbitrary alleged STEP results.

Family copies a bounded nonempty expected cut list (at most16). Each context
appears once with exact revision, effective view and X/foreign role; declaration
IDs do not identify a cut. The common X cut is recovered from every complete
proof group, each of which must use X. A local-X cut must match that parent;
a foreign cut cannot reuse the X context identity.

finish snapshots the output map and requires every expected cut, no extras.
Each output must be an observed STEP from this exact input identity. Its proof
ledger must retain the same X cut. Actual new producers must be X or that
branch's expected foreign cut; there must be a producer from the expected cut.
Historical foreign support remains provenance, not newly introduced raw sibling
knowledge. Even content-equivalent packets from another barrier are refused.
The merged family output cannot masquerade as a STEP but can seed the next pass.

All steps execute in private Minds; this stage introduces no physical parallel
scheduler or live knowledge mutation. Source snapshots remain a trusted-caller
assumption, and the expected list is caller supplied, not a discovery certificate.

## Canonical aggregation and scoped outcomes

Only after all branch identities/cuts validate does aggregation combine the
input and all outputs. Atoms compare predicate, sign, exact canonical Origin
slots and semantic fixed values. Identical whole source groups deduplicate,
keeping their minimum depth. Different whole proof alternatives stay separate;
they are never flattened into a fictitious joint proof.

Pairwise opposite atoms produce CONFLICT with both immutable Items and their
complete proof alternatives; no candidate Packet is returned. MERGED returns a
quarantined proof pool, explicitly awaiting coverage/admission. Its changed
flag compares atoms plus source/depth alternatives, independently of list order
or allocation identity. New proof alternatives count as change. Unchanged pool
content is not a saturation certificate. Missing branches, wrong barriers/cuts
and work/atom limits return INCOMPLETE without candidate or conflict prefix.

A positive family p->q / p->r can feed a real next private C pass
`q && r -> out`. The runner requires depth2 and the complete {X0,A1,B2,C3}
proof. This exercises useful transport across the barrier without sharing the
raw declarations of independent contexts.

full X/scalar/rule snapshot replay, authenticated effective cuts, complete branch
coverage, no-product completion and runtime authoring admission remain pending.

ACCEPTED status is introduced. Existing refusal boundaries for witness shape,
materialization, generated witnesses and premise coverage remain in force.
