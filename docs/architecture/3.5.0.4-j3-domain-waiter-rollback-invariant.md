# KANGER 3.5.0.4 — Domain waiter rollback invariant

## Status

Resolved.

```text
focused red gate:
ddb3494a600e405d99f01f620c822864a7f2be8a
Gate Domain waiter rollback

minimal production correction:
c0d717abfe46ea026773392831d5aef3b3b029fd
Restore Domain waiters on checkpoint release
```

The defect was discovered while preparing architectural Javadoc for `DomainFactory`. Documentation work exposed an auxiliary-state lifecycle that was not covered by the existing cache rollback protocol.

## Semantic role of waiters

`DomainFactory.waiters` is not logging or optional diagnostic metadata.

`RuleFactory.expand(Rule)` adds a Domain when the expanded Rule has one tree branch, one Domain in that branch, and T-variables:

```java
mind.getDomains().getWaiters().add(r.getTree().get(0).get(0));
```

`Linker` later reads the set while resolving complete Domains against stored opposite-polarity masters. The set therefore affects future inference behavior and belongs to the visible logical state of the Domain factory level.

## Transaction path

A child Domain factory begins with a copy of its parent's waiter set:

```text
child transaction(parent)
    -> waiters = copy(parent.waiters)
```

Typed parent commit merges child metadata:

```text
parent.commit(childFactory)
    -> promote child Escalera state
    -> parent.waiters.addAll(child.waiters)
```

During composite `Mind.commit`, Domain state is first protected by a cache checkpoint:

```text
domains.mark()
domains.commit(childDomains)
analyzer validation
```

If validation rejects the composite, rollback calls:

```text
domains.release()
```

Before the correction, `release()` restored only `Escalera`; the merged waiter set was not restored.

## Violated invariant

A released composite checkpoint must restore all factory-owned semantic state, not only its canonical cache.

Formally, for DomainFactory state:

```text
S = (Escalera state, waiters)

mark(S0)
commit(child)
release()

required: S == S0
```

The old implementation guaranteed the equality only for the Escalera component.

Consequences of the gap:

- a Domain introduced by a rejected child could remain in the parent waiter set;
- later Linker work could observe inference metadata from a transaction whose logical cache changes were rolled back;
- cache state and auxiliary semantic metadata could describe different transaction histories.

## Focused regression

Permanent runner:

```text
kanger-console/src/org/kanger/KangerDomainWaiterRollbackSafetyRunner.java
```

The runner uses the production compiler and `RuleFactory.expand` path to create a child waiter, then executes the exact checkpoint protocol:

```text
capture parent baseline
compile child single-Domain T-variable Rule
verify child waiter publication
parent domains.mark()
parent domains.commit(child domains)
verify waiter merge
parent domains.release()
require parent waiters == baseline
```

On the uncorrected implementation the new CI step failed with:

```text
released DomainFactory checkpoint retained child waiters
```

All preceding invariant gates in the same job passed, isolating the failure to the new auxiliary-state assertion.

## Correction

`DomainFactory` now owns a stack of waiter snapshots parallel to nested Escalera checkpoints:

```text
mark()
    cache.mark()
    push copy(waiters)

commit()
    cache.commit()
    discard matching waiter snapshot

release()
    cache.release()
    restore matching waiter snapshot
```

A new transaction/storage generation clears the snapshot stack together with its waiter state and chain anchors.

A stack, rather than one saved set, preserves the existing nested checkpoint model.

## Scope

The correction changes only Domain waiter checkpoint lifecycle.

It does not change:

- Domain identity or hashing;
- waiter creation criteria in `RuleFactory.expand`;
- Linker matching semantics;
- child-to-parent typed commit semantics;
- storage format or persistent record layout;
- `Escalera` implementation;
- transaction reservation accounting;
- public interfaces or method signatures.

## Documentation consequence

`DomainFactory` Javadoc must describe `waiters` as checkpointed semantic overlay state. It must not state or imply that Escalera alone contains the complete Domain transaction state.
