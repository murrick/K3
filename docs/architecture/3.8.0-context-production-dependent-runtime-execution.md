# Stage522: explicit native residual execution over checked runtime graphs

`ContextDependentRuntimeExecution` executes an explicit finite sequence of ordinary native rule steps against a freshly qualified typed runtime. It first reruns the actual parent/child, cut, model and projection pipeline. Its matcher then reads the indexed product graphs, not model choices or the earlier carrier TermViews. Every completed step produces a typed conclusion, complete original Source ancestry and an independently checked substitution certificate.

## Scope and lifecycle

A step names the exact receiving cut, physical native original rule and retained literal. Its ordered donor tuple covers every other literal of that whole ordinary single Horn/headless clause. Donors are visible runtime product occurrences or internally produced earlier outputs from the same cut. Original native unit donation, automatic tuple discovery and barrier transport of these new outputs are not added here. A native unit cannot be used as a receiver. The frame is freshly prepared inside the request; caller-supplied frames, output receipts and model-audit results cannot bypass preparation.

The provider exposes `prepareDependentRuntimeExecution` and retains successful execution, its model audit and the exact prepared frame together only after currentness checks. Lookup requires the current UUID, owning thread, lease and unchanged native parent/child/retained/topology views. Structural or model-only preparation clears the old execution result. Legitimate failure clears all prior retained state; a wrong-thread call cannot clear owner state. Closing clears it. Detached results remain historical evidence. Execution writes no native row, Cvar, Term factory or revision.

EXECUTED_PENDING means local proof steps completed in their specified cuts. It is not family saturation, a new common export, native write/settlement or full-family eligibility. Even an output with local-X ancestry remains separate until a receiving-barrier qualification explicitly consumes it. Independent A/B cuts cannot borrow each other's rules or earlier outputs. Physical TRUST members share one receiving cut, so a step may consume an earlier result from another member in that same cut. Whole Source alternatives and supersets remain intact.

## One substitution for the entire tuple

All native receiver variables are instantiated once per step. Every use of a universal runtime donor receives fresh variables, including repeated use of the same occurrence. The matcher preserves repeated variables and ordered function dependencies within each donor. A shared substitution map spans the complete body: left(1) and right(2) cannot separately satisfy left(x) and right(x). Numeric1 and string1 remain different typed values.

Unification uses typed value equality, exact function Source/binder/ordered arguments, and an occurs check over the indexed symbolic terms. It never substitutes a supplied model's chosen witness value. A rigid function/constant or different-symbol failure returns NO_MATCH for this explicit recipe; it proves no inequality, semantic falsity or conflict. For example, inability to unify x with f(x) does not claim that an admissible interpretation cannot have f(x)=x. This is conservative symbolic execution, not a decision procedure for all models.

A successful output retains the selected literal's sign/predicate, substituted argument graph, exact receiver Source, union of all selected donor Sources plus the receiver, and depth1+max(donor depth). Shared function edges and arbitrary supported ranks use one implementation. An explicit chain may consume its own earlier outputs without writing them to the prepared input frame.

## Independent certificate audit

Each output includes one topological graph containing the conclusion, instantiated whole native clause, all instantiated donors and variable-to-graph bindings for the receiver and each donor use. The separate auditor reads the actual native clause again and verifies those substitutions, exact donor graphs, opposite pivot signs, ordered tuple equality, the retained head, all original ancestry and depth. It validates every function's actual declaration/rank and support, variable correlation, typed constants, reachability and graph topology. The audit performs no unification, model interpretation or execution term construction. It shares the ordinary native clause parser and verifies proof soundness, not a separate most-general-unifier theorem; generality/freshness has dedicated executable controls.

A QA-only seam challenges certificates with missing Sources, wrong depth, extra unreachable nodes, missing receiver bindings and a changed instantiated function donor. Fixtures are restored and audited again. The seam is absent from production artifacts.

The execution work allowance, audit work allowance and whole term/certificate node bound are separate from preparation limits. Plan length and consequence depth are bounded by the preparation policy. A late NO_MATCH or refusal exposes no earlier successful output or preparation prefix. Source-proved BASE_REFUTED/CANDIDATE_REFUTED preparation outcomes retain their original proof before step execution. Failed interpretations remain INCOMPLETE. Interruption preserves its flag and throws; stale actual views throw.
