# Term architectural passport review

Status: review artifact for later safe integration into `kanger/src/org/kanger/units/Term.java`.

## Architectural role

`Term` is KANGER's canonical typed semantic atom. The same implementation also represents an internal U-witness (historically called a C-variable), but ordinary values and U-witnesses have different identity, ownership and projection semantics.

A normal Term denotes a canonical value. A U-witness denotes a Rule-owned existential witness whose concrete relation to parent and child witnesses exists only in a Mind.

## Inside — architectural essence

### Ordinary Term

The stable state consists of:

- operational Term ID;
- owner/materialization Mind ID;
- `DataType`;
- canonical typed value;
- cached semantic hash.

For ordinary Terms, factory canonicalization is based on typed value semantics rather than Java object identity or persistence address.

### U-witness

The stable definition additionally contains:

- positive witness index;
- original name Term ID;
- owning Rule ID;
- dominant-witness marker.

The witness is not a user-visible substitution value. Its identity must not collapse merely because it has no ordinary concrete value.

## Outside — contextual relations and projections

The following belong to a concrete Mind rather than to the isolated Term essence:

- transaction-visible deletion;
- parent witness relation;
- Rule-scoped canonical child projections;
- debug-level textual rendering;
- lazy resolution of name and owning Rule;
- storage and map representations.

## Identity and canonicalization

For ordinary Terms:

```text
(DataType, canonical value semantics) -> canonical Term
```

`equalsTo()` compares semantic values independently of operational IDs. `equals()` and `hashCode()` use operational Term identity.

For U-witnesses, witness identity includes the witness object/ID and Rule-local definition. Two U-witnesses must not collapse solely because both lack an ordinary value.

The canonical child invariant is:

```text
(parent U-witness, target Rule id) -> canonical U-child
```

One parent may have multiple children, but at most one canonical child for each target Rule. The deprecated unscoped child lookup must not be used by new inference code.

## Value semantics

Supported value forms include numeric, date, string, period, interval, set, blob and nested Term values.

Parsing and construction normalize external values into KANGER's typed representation. This normalization creates a semantic candidate; canonical publication remains the responsibility of the Term factory.

`getHash()` is a semantic candidate hash, not proof of identity. Hash collisions require `equalsTo()` confirmation.

For sets, semantic comparison is independent of iteration order after expansion. For numeric comparison, `FLT_EPSILON` defines the historical near-equality threshold used by ordering.

## Ownership and lifecycle

Ordinary canonical Terms may be shared across transaction levels. U-witnesses additionally belong to a Rule and participate in Mind-owned parent/child relation maps.

`setMind()` selects the context used for deletion, hydration and contextual representation; it does not redefine canonical value identity.

Deletion is a visibility transition, not physical destruction. Deleting a U-witness must unlink its parent/child relations from the current Mind to prevent stale runtime topology.

## Parent and child relations

`getParent(Mind)` resolves the parent relation through the current Mind and inherited parent transaction levels.

`getChild(Mind, targetRuleId)` resolves the canonical child for exactly one target Rule.

The historical `getChild(Mind)` is unscoped and deprecated. It cannot express the Rule-scoped invariant and must not be used in new inference paths.

## Persistence

`pack()` serializes:

- operational and owner IDs;
- deletion marker;
- data type and semantic hash;
- typed value representation;
- witness index and, for witnesses, name/Rule IDs and dominant marker.

`apply()` restores a shell and embedded value representation. Persistence representation is not canonical identity; canonical registration remains a factory responsibility.

`createMap()` is an external diagnostic/export projection. It is not a stable persistence protocol.

## Representation

`toString()` is context-sensitive:

- ordinary Terms render their formatted typed value;
- dates use a diagnostic timestamp format;
- U-witnesses render either their internal value/index form in debug mode or their original name in normal mode.

Textual representation must never be used as canonical identity or a stable serialization protocol.

## Caller obligations

Callers must:

- distinguish `equalsTo()` semantic equality from operational `equals()`;
- treat semantic hashes only as candidate keys;
- never expose a U-witness as a concrete user substitution;
- use Rule-scoped child lookup for inference;
- provide a compatible Mind for contextual deletion, hydration and relation lookup;
- avoid interpreting deletion as nonexistence;
- avoid treating map/text representations as persistence identity.

## Architectural invariants

```text
ordinary Term != U-witness
semantic value identity != operational Term ID
semantic hash != identity proof
U-witness != concrete substitution
parent relation != child relation
(parent witness, target Rule) -> canonical child
unscoped child lookup != valid new inference contract
deleted != nonexistent
unloaded reference != absent entity
text representation != canonical identity
serialized representation != canonical identity
```

## Historical notes

The implementation and API historically use the names `C-variable` and `isCVariable()`. In the current architecture this object is an internal U-witness: a Rule-owned existential witness with Mind-scoped parent/child projections.

The historical name is retained for compatibility, but documentation should use "U-witness" as the semantic meaning and mention `C-variable` only when referring to existing code identifiers.
