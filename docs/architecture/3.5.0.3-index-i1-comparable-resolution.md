# KANGER 3.5.0.3 — Index I1 comparable resolution

## Scope

This note resolves invariant candidate I1 from
`3.5.0.3-index-invariant-candidates.md`.

Production source:

```text
kanger-data-dumb/src/org/kanger/storage/Index.java
```

Regression gate:

```text
kanger-data-dumb/src/org/kanger/storage/IndexOneComparableSafetyRunner.java
```

## Observed implementation

`Index.IndexOne` is a public inner type implementing
`Comparable<IndexOne>`:

```java
@Override
public int compareTo(IndexOne indexOne) {
    return (int) (id - indexOne.getId());
}
```

The subtraction is performed as `long` and then narrowed to `int`.

## Proven contract violations

### Equality collapse

For IDs separated by `2^32`:

```text
left  = 0
right = 4294967296
```

The mathematical difference is `-4294967296`. Its low 32 bits are zero,
so narrowing produces:

```text
left.compareTo(right) == 0
```

although the IDs are different.

### Sign reversal

For:

```text
left  = 0
right = 2147483648
```

The mathematical difference is negative, but narrowing produces
`Integer.MIN_VALUE` for one direction and may violate the expected sign
relation for other distances outside the `int` domain.

### Full-domain overflow

`Long.MIN_VALUE - Long.MAX_VALUE` overflows even before narrowing.
Subtraction is therefore not a valid implementation of total ordering over
`long` identifiers.

## Impact boundary

The internal `Index` maps observed in production source are keyed by `Long`:

```text
baseIndex
emptyIndex
currentBlock
```

They do not use `IndexOne` natural ordering. Block layout, disk format,
lookup order, split order, and persistence reconstruction are therefore not
driven by `IndexOne.compareTo()`.

The defect remains externally observable because `IndexOne` is public and
explicitly implements `Comparable<IndexOne>`.

## Regression gate

`IndexOneComparableSafetyRunner` covers:

- ordinary positive ordering;
- negative-to-zero ordering;
- `Long.MIN_VALUE` and `Long.MAX_VALUE`;
- a `2^32` distance that historically collapses to zero;
- an `Integer.MAX_VALUE + 1` boundary;
- equal IDs;
- antisymmetry of comparison signs.

The runner is intentionally expected to fail against the historical
implementation. It has been committed as a red regression gate; execution has
not been claimed in this document because the GitHub connector does not run the
Java build.

## Approved correction

The only approved production change is:

```java
@Override
public int compareTo(IndexOne indexOne) {
    return Long.compare(id, indexOne.getId());
}
```

This preserves:

- method signature;
- binary descriptor;
- equality result for equal IDs;
- ascending ID intent;
- storage representation;
- all internal `Long`-keyed index ordering.

It corrects only the invalid ordering outside the `int` difference domain.

## Classification

```text
I1: proven invariant/API defect
correction: approved
behavioral scope: public Comparable contract only
storage semantic impact: none established
format impact: none
required gate: compile and run IndexOneComparableSafetyRunner
```

## Atomic green commit requirements

The production correction must be committed separately from the red gate and
must include:

1. replacement of subtraction/narrowing by `Long.compare`;
2. successful compilation of `kanger-data-dumb` against `kanger`;
3. successful execution of `IndexOneComparableSafetyRunner`;
4. the ordinary active regression baseline where available;
5. no changes to I2 or I3 in the same commit.

I2 (`firstKey` empty behavior) and I3 (null iterator on empty index) remain
unresolved contract questions and must not be bundled with I1.
