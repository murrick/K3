## Shared factory lifecycle

Each `Mind` owns a concrete factory instance for both categories.

Child initialization follows the per-Mind overlay model established by J3:

```text
new child Mind
    -> create child factory
    -> transaction(parent factory)
    -> child Escalera overlays parent cache
    -> child storage connection remains null
    -> generation-local anchors and auxiliary state reset
```

Typed parent commit:

```text
parent factory commit(child factory)
    -> promote child cache chain
    -> rebind promoted units to parent Mind
    -> merge category-specific auxiliary state where present
```

Only a root factory in an open storage generation borrows the schema `IBase` from `User`. Child factories receive visibility through parent/cache layering and do not own storage close.

No-argument `mark / commit / release` methods belong to nested cache/composite checkpoints and must not be conflated with typed child commit.

## TVariableFactory contract

### Representation

`TVariableFactory` is the per-Mind registry and transaction overlay for logical `TVariable` units.

`createTVar(rule, name)` allocates a new variable identity and records:

```text
schema ID
owning Mind ID
variable index allocated through the term/dictionary subsystem
owning Rule
name Term
```

The class does not implement semantic-pair resurrection analogous to `TValueFactory.find`. Javadoc must therefore avoid implying that variables are deduplicated by name or Rule through a canonical lookup that does not exist.

### Transaction role

A child factory is a comparatively direct `Escalera` overlay:

```text
cache overlay
generation-local top anchor
root-only borrowed connection
```

Typed commit promotes child-created variables and rebinds their runtime owner to the parent `Mind`.

No additional checkpoint journal is currently owned by this class; no-argument mark/commit/release delegate to `Escalera`.

### Cross-factory cleanup

`pack()` physically removes TVariables marked deleted and removes the same variable keys from:

```text
mind.getTValues().getCurrent()
```

This is an explicit cross-factory lifecycle obligation. The transient current-binding projection must not retain a key for a physically removed logical variable.

The method is not general reachability collection for every undeleted variable.

### Persistence and concurrency

Root cache misses may hydrate through the borrowed `IBase`; root update persists cache changes. Child overlays do not own the connection.

`createTVar` is synchronized, but this local guard does not make variable objects, iterators, related factories, or the full transaction protocol independently thread-safe.

## TValueFactory contract

### Representation

`TValueFactory` owns several distinct state dimensions that must not be collapsed into one generic “current values” description:

```text
Escalera cache
    canonical TValue identities and transaction visibility

current: Map<TVariable, TValue>
    active runtime binding projection

parentIndex + localByVariable
    transaction-layered acceleration index by TVariable ID

indexInitialized
    readiness of the local acceleration layer

action
    factory mutation/effect signal

additionsStack + actionStack
    nested checkpoint rollback journal
```

The private names `top` and `current` remain intentionally distinct lifecycle axes:

```text
top      cache/overlay chain anchor
current  transient active binding projection
```

### Canonical identity and resurrection

The canonical semantic key is:

```text
(TVariable identity, ITerm value identity)
```

`add(tv, value)` calls `find(tv, value)` before allocating. `find` deliberately includes logically deleted candidates so that add can clear the deletion mark and reuse the same TValue identity.

```text
logical deletion
    reversible transaction state

pack removal
    physical canonical deletion boundary
```

Javadoc must describe this distinction explicitly and must not reinterpret the missing deleted filter as an accidental visibility bug.

### Current binding projection

`current` answers the active binding question for a `TVariable` through `get`, `set`, and `isEmpty`.

It is transient runtime state, cleared when a new factory transaction/generation is initialized. It is neither the canonical TValue registry nor the persistent record set, and typed child commit does not define it as a durable child-to-parent publication map.

Physical packing removes entries whose TValue no longer exists in the cache. TVariable packing separately removes bindings keyed by deleted variables.

### Layered variable index

The acceleration index stores TValue IDs only:

```text
parentIndex
    visible parent layers

localByVariable
    local TVariable ID -> ordered TValue IDs
```

Values remain owned and hydrated through `Escalera` / `IBase`.

Lazy root initialization reverses the newest-first Escalera iteration before indexing, preserving the historical oldest-first substitution order. Child collection traverses parent layers before local IDs. This ordering is observable and must not be described as an arbitrary set traversal.

Typed child commit snapshots and merges the child index into the parent layer.

### Checkpoint rollback

Nested Linker checkpoints are frequent. The factory journals deltas instead of copying the complete index:

```text
mark()
    push empty additions list
    push action state
    mark cache

add()
    index new TValue
    append it to the active additions delta

commit()
    commit cache
    fold child delta into enclosing delta
    discard saved action state

release()
    release cache
    unindex recorded additions in reverse order
    restore saved action state
```

This protocol preserves index/cache agreement and action rollback while keeping nested rollback proportional to newly added values.

### Packing and persistence

`pack()` physically removes:

- values still logically deleted;
- values whose underlying ITerm is no longer referenced by an active Rule.

Removal unindexes the TValue and later cleans stale `current` entries. The cache root becomes the new generation-local `top` anchor.

Only root factories borrow the schema `IBase`; child overlays remain memory-only transaction layers.

### Ordering and concurrency boundaries

`TValue.compareTo` defines full-range lexicographic ordering by:

```text
(tVarId, TValue id)
```

That unit-level ordering is separate from the factory's oldest-first per-variable substitution order. Javadoc must not conflate Comparable ordering, canonical identity, and iteration/publication order.

`indexLock` protects local acceleration metadata, and add is synchronized, but semantic objects are hydrated outside a claim of universal factory thread safety. Parent publication and composite transaction ordering remain `Mind` responsibilities.

## Pair comparison

| Dimension | `TVariableFactory` | `TValueFactory` |
| --- | --- | --- |
| Represented unit | Logical variable owned by Rule/Mind | Canonical variable/value association |
| Allocation | New identity through `createTVar` | Canonical lookup, allocate or resurrect |
| Child cache | Escalera overlay | Escalera overlay |
| Auxiliary visible state | No independent checkpoint metadata | Layered variable index, current binding, action |
| Typed commit | Promote/rebind units | Promote/rebind, merge index, propagate action |
| Checkpoint journal | Escalera only | Escalera plus additions/action delta stacks |
| Transient projection | None owned here | `current` active bindings |
| Pack cross-effect | Remove deleted variable from current bindings | Remove deleted/orphan values and stale bindings |
| Ordering concern | Variable index assigned at creation | Canonical identity, TValue Comparable, substitution order |

The pair is intentionally asymmetric. Documentation must not imply that TVariable and TValue are two interchangeable sides of one map.

## J4 acceptance criteria

J4 closes only when:

1. both class-level comments explain exact per-Mind ownership, child initialization, parent completion, and root-only storage attachment;
2. TVariable creation identity and Rule/name/index relationships are stated without inventing semantic deduplication;
3. the TVariable pack obligation toward `TValueFactory.current` is explicit;
4. TValue canonical identity and pre-pack resurrection are explicit;
5. `current`, canonical cache, layered index, action state, and checkpoint journals remain distinct;
6. parent/local index layering and oldest-first substitution ordering are documented;
7. typed commit and no-argument checkpoint commit are not conflated;
8. pack, persistence, cleanup, and concurrency claims remain evidence-bounded;
9. Java 8/21 rendered pages contain both introductions with resolved links;
10. canonical resurrection, ordering, action rollback, factory lifecycle, persistence, and the complete qualification contour remain green on one final HEAD;
11. paired review confirms no wording implies persistent current bindings, arbitrary substitution ordering, or universal factory semantics.
