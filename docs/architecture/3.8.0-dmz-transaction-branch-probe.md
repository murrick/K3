# DMZ candidate: first transaction branch probe

Status: executable characterization of existing Core capabilities. This is
not a replacement for trust and not a complete DMZ implementation.

Base: `develop/3.8.0`, `2422f7f6d9e1af7608203b1566df64b5f29fe344`.
Specification: section 20 of the live architecture specification 2.0.
Carrier: `experiment/3.8.0-dmz-transaction-probe`.

## Concrete question

Can existing transactions retain opposite external opinions, retract one
known ground support and its consequences only in an alternate branch, retain
independently supported results, and preserve the target Q?

The test uses ordinary compiler/linker/analyzer semantics throughout. No second
inference engine or production changes are introduced.

## Fixture and branch construction

Q owns these general productions:

```text
!@x a(x) -> male(x);
!@x b(x) -> ~male(x);
!@x a(x) -> shared(x);
!@x c(x) -> shared(x);
!@x male(x) -> positive(x);
!@x ~male(x) -> negative(x);
```

An ephemeral current transaction contains either `a(John)` or `b(John)`, plus
`a(Mary)`, `c(John)` and `stable(Tom)`. Trying the opposite support is rejected
with a collision witness and leaves current knowledge unchanged.

The alternate is a real child transaction over that live current transaction.
It masks the known first ground support using existing `queryDelete`, whose
production re-saturation removes unsupported consequences. It then accepts
the opposite support. Current retains the first opinion; alternate retains
the second. Neither is committed to Q.

This is a nested overlay alternative, not a sibling fork of the current state.
A separate case creates two live sibling ephemeral transactions over Q and
checks that opposite inputs and answers remain isolated. Operations are
interleaved sequentially; multi-thread execution is not tested here.

The probe recursively follows existing `ICause` links to confirm that the
generated conflict side exposes its known ground-support ancestry. The
collision witness itself still exposes diagnostic text, not a structured
rule-application conflict set.

## Qualified observations

- Both positive-first and negative-first cases succeed.
- Masking `a(John)` retracts its unsupported positive consequence; masking
  `b(John)` retracts its unsupported negative consequence.
- `shared(John)` survives through independent `c(John)` support.
- `positive(Mary)` survives: the general `a -> male` production is retained.
- Each resulting branch matches a freshly constructed transaction with the
  corresponding accepted inputs for the checked ground answers and unary
  enumeration Values.
- Original current knowledge is unchanged by alternative operations.
- Two sibling transactions retain opposite John opinions simultaneously.
- When Q itself owns `male(John)`, external `b(John)` is rejected atomically,
  while `b(Mary)` and the same general production remain applicable.
- Q's visible rules, root dictionary counts and user current-Mind slot remain
  unchanged. After disposal all branch reservations return to zero.

## Run and result

Executable: `org.kanger.DmzTransactionBranchProbeRunner`, qualification source
`kanger-qualification/src/org/kanger/DmzTransactionBranchProbeRunner.java`.

Compile the exact carrier Core, Command, Bootstrap and UDF sources plus the
runner for Java 8. Put `kanger/resources` and `kanger-udf/resources` on the
runtime classpath with the compiled classes. Invoke the runner with an optional
positive round count (default 3).

Observed clean-source run used ECJ with `-8`, Java 17, and three rounds:

```text
SYMMETRIC_BRANCH_PASS first=a witnesses=1
SYMMETRIC_BRANCH_PASS first=b witnesses=1
SIBLING_BRANCHES_PASS
Q_PRIORITY_PASS
```

The four lines repeat for each round; final result:

```text
DMZ_TRANSACTION_BRANCH_PROBE_PASS rounds=3 checks=523
```

The number is the runner's assertion count, not 523 independent tests.
Maven reactor, full regression corpus and historical `set_08_02` were not run
in this probe. No production code changed.

## Limits and next concrete step

The pair of conflicting supports is supplied explicitly by the fixture.
Deletion of one ground support is a bounded characterization technique, not
the proposed generic prohibition of a combination of rule applications.
The test does not provide automatic conflict attribution, generic symmetric
split scheduling, substitution-sensitive no-good sets, multi-source Context
attachment, branch cache/lifecycle wiring, or the final opinions API.

Next: preserve structured identities of conflicting supports before the
collision transaction is discarded; reconstruct both causal alternatives,
including substitution and source identity; represent a branch-local forbidden
combination. Only then select and qualify the production hook that can skip
that combination without deleting whole source assertions or general rules.
Full cross-context attachment remains a separate architectural question.

## Second slice: detached collision graphs

`CollisionProofCapture` is a package-private, opt-in experimental scope. The
Analyzer captures both existing cause graphs while colliding rules still
belong to the live transaction, before rejection rolls it back. Outside an
active scope the hook returns immediately. Existing collision witness text,
equality, storage and truth semantics are unchanged.

The result consists of immutable detached node/edge lists. Nodes retain
original source text, concrete domain rendering and generated status. Each
existing `ICause` pair has separate rule and donor references expressed as
graph-local indexes. Missing endpoints are `-1`, cycles are preserved without
infinite traversal, and no Mind/Rule/Term/Cause object is exported. These are
inspection graphs, not complete proof certificates or stable cross-context
application identities. Original text and domain rendering do not by
themselves constitute a no-good key.

`DmzCollisionProofCaptureRunner` verifies a two-step production chain in both
input orders, including contraposition, and inspects the captured graphs
after rejected compile rollback and complete branch disposal. It verifies
that the John conflict does not prevent the Mary substitution, immutable
graph lists, and nested capture restoration.

Clean ECJ compilation for Java 8 followed by Java 17 execution reports:

```text
DETACHED_CONFLICT_PASS reverse=false collisions=1 edges=3
DETACHED_CONFLICT_PASS reverse=true collisions=1 edges=3
DMZ_OPEN_REQUIREMENT alternative_supports_complete=false captured_a=false captured_c=true
DMZ_COLLISION_PROOF_CAPTURE_PASS checks=74
```

The prior transaction runner still reports 523 passing assertions in three
rounds with capture disabled. Full reactor qualification is not claimed.

### Blocking discovery: alternatives are not complete

For rules `a(x) -> male(x)` and `c(x) -> male(x)`, both ground supports
`a(John)` and `c(John)` are accepted. At a later conflict with `~male(John)`,
the existing stored cause graph exposes only the `c(John)` chain in this
fixture. Capturing that graph faithfully does not recover the missing
alternative. This is explicitly printed as an open DMZ requirement; it is
not counted as proof-completeness success.

Existing ordinary deletion can re-saturate surviving inputs, as the first
probe demonstrates. A generic DMZ split must also account for alternatives
that currently have no retained cause edge. Otherwise blocking the visible
support may miss or misclassify the remaining independent proof.

Next step is therefore to qualify complete operation-local support collection
or reconstruction, including grouping of multi-premise supports and query
taint, before implementing generic branch restrictions. Merely unioning
`ICause` pairs or removing a whole source rule is not accepted as a solution.


## Third slice: terminal support observation

`TerminalSupportCapture` is an opt-in, operation-local immutable journal.
The Linker observes complete terminal candidates before stored-result
suppression in its single-candidate path. Each event retains conclusion,
source rule text and a separate donor group. Outside a capture scope the
hook returns immediately; inference and stored-cause semantics are unchanged.
This hook does not cover all terminal paths and is not a proof certificate.
The scope must start before inference: it cannot recover derivations from
an already populated cache. Source text is diagnostic, not stable identity.

The qualification distinguishes two fixtures: independent `a -> male` and
`c -> male` proofs produce separate events even after canonical suppression;
`(a && c) -> male` produces one event containing both required donors in the
single-tuple fixture. Snapshots and donor groups are immutable; nested scopes
isolate events, restore the outer scope and reject out-of-order close.

Clean Java 8-target ECJ compilation and Java 17 execution report:

```text
TERMINAL_ALTERNATIVES_PASS events=8
TERMINAL_CONJUNCTION_PASS events=4
DMZ_OPEN_REQUIREMENT terminal_binding_certified=false mixed_donor_groups=true
DMZ_TERMINAL_SUPPORT_CAPTURE_PASS checks=28
```

The collision graph runner still passes 74 checks; the transaction probe
still passes 523 assertions over three rounds. Full reactor qualification
and a release workflow are not claimed.

### Blocking discovery: accumulated causes mix substitutions

With John and Mary both satisfying `(a(x) && c(x)) -> male(x)`, the raw
terminal cause group contains donors from the other tuple. This is explicitly
asserted as a characterization of the current implementation, not counted
as support-binding certification. The cause map accumulates across variable
rotations, so moving capture earlier than storage solves alternative loss
in the bounded fixture but does not solve binding attribution.

No branch restriction may use these raw groups. Filtering donors by names
in the conclusion would also be unsound: intermediate variables need not
appear in the conclusion. The next hook must retain the unification event,
its complete binding and the premise occurrence that consumed each donor,
then assemble AND supports separately from alternative proofs. Rollback,
query provenance, contraposition, cycles, source/version identity and all
terminal paths still require qualification before automatic symmetric splits.


## Fourth slice: premise-local partial bindings

The same opt-in journal now observes `markExcluded` immediately before a
new Cause is constructed. It copies the explicit substitution candidates
passed to that call, rather than reading the accumulated cause map or
assuming that current TVariable values describe the matched donor.

Each detached match contains a capture-local premise index, original rule
text, donor rendering, the native result flag and a list of partial bindings.
Each binding retains a capture-local variable index, diagnostic name and
rendering, and an immutable `SemanticTermSnapshot` of the ordinary value.
Premise and variable indexes distinguish runtime objects within the scope;
they are not durable source/version identities. The identity map holds
runtime objects only while the scope is open and is cleared on close.
Nonordinary substitutions are excluded from this observation surface.

The unary conjunction fixture keeps John and Mary bindings separate. A
second fixture uses `(a(x,y) && c(y)) -> male(x)` with `(John,One)` and
`(Mary,Two)`: the captured `c` matches preserve the hidden `y` binding even
though `y` does not appear in the conclusion. Both substitutions refer to
the same captured premise and variable, while retaining distinct values.
The snapshots are inspected after scope closure; native truth is checked.

Clean Java 8-target ECJ compilation followed by Java 17 execution reports:

```text
DMZ_PREMISE_BINDINGS_PASS matches=16
DMZ_HIDDEN_JOIN_BINDINGS_PASS matches=16
DMZ_TERMINAL_SUPPORT_CAPTURE_PASS checks=126
DMZ_COLLISION_PROOF_CAPTURE_PASS checks=74
DMZ_TRANSACTION_BRANCH_PROBE_PASS rounds=3 checks=523
```

This isolates bindings in the tested premise matches, but does not yet
assemble complete applications. The terminal cause groups remain mixed,
and the corresponding open-requirement check remains in the runner.
A partial match may be discovered before all premises hold; the native
result flag is preserved, not interpreted as a proof of the conclusion.
Zero-substitution matches, other Cause construction sites, functions,
C-variables and all alternate production paths are not certified here.

Next: connect compatible premise matches to a specific terminal application,
retain AND groups separately from OR alternatives, and fail closed for
unsupported paths. Only a complete, source-qualified support can justify
branch-local forbidden combinations and dependent consequence retraction.
