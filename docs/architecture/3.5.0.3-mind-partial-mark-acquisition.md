# 3.5.0.3 — Mind partial mark acquisition invariant

## Defect

`Mind.commit(child)` acquires factory checkpoints sequentially. If a later
`mark()` throws, the method has no acquisition ledger and no guaranteed unwind
for checkpoints that were already opened.

Example:

```text
functions.mark()   succeeds
fValues.mark()     succeeds
tVars.mark()       throws
```

The first two factories remain marked, later factories were never marked, and
the child transaction reservation is not consumed because
`finishTransactionLocked()` is reached only on the normal path.

## Required invariant

Checkpoint acquisition must be exception-atomic:

```text
for each factory:
    mark()
    record factory in acquisition ledger only after mark succeeds

on failure:
    release recorded factories in reverse acquisition order
    leave unacquired factories untouched
    consume child reservation exactly once
    preserve the original acquisition failure
```

Rollback failures during this unwind must not stop later releases. They are
attached to the acquisition failure through `Throwable.addSuppressed()`.

## Regression gate

`KangerMindPartialMarkAcquisitionSafetyRunner` injects a failure into the third
factory mark (`TVariableFactory`) after the first two marks have succeeded. It
requires:

- the injected failure to propagate;
- the child transaction reservation to be closed;
- all successfully acquired frames to be unwound;
- no checkpoint or auxiliary stack to remain open.

The current implementation violates these requirements because the composite
mark sequence is not protected by an acquisition ledger or a failure cleanup
path.
