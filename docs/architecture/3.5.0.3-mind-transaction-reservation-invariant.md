# KANGER 3.5.0.3 — Mind transaction reservation invariant

## Scope

This checkpoint resolves the semantic role of:

```text
Mind.transactionCounter
```

and records the focused regression gate:

```text
MindTransactionReservationSafetyRunner
```

No production behavior is changed.

## Reconstructed contract

`transactionCounter` is not:

- a transaction identifier;
- a global transaction sequence;
- the nesting depth of the current Mind;
- the number of all descendants below a root.

It is the number of unfinished direct child-Mind reservations owned by one parent Mind.

```text
new Mind(parent)          -> parent counter +1
parent.commit(child)      -> parent counter -1
parent.release(child)     -> parent counter -1
failed child construction -> parent counter -1
```

A grandchild increments its immediate parent's counter, not the root's counter.

## Publication barrier

For a root Mind (`next == null`), the transition to zero is a publication barrier:

```text
last direct child completes
        -> transactionCounter becomes 0
        -> pack()
        -> update()
```

As long as one direct child reservation remains open, root packing and persistence update must not run through this completion path.

The counter is therefore lifecycle state, not ordinary diagnostics.

## Synchronization invariant

Reservation creation and completion are serialized by the parent's `locker`:

```text
incTransactionCounter()
finishTransactionLocked()
abortTransactionStart()
commit(...)
release(...)
```

The underflow check occurs before decrement:

```java
if (transactionCounter <= 0) {
    throw new IllegalStateException(...);
}
```

A duplicate completion is rejected without making the counter negative.

## Regression gate

`MindTransactionReservationSafetyRunner` verifies:

1. a fresh root starts at zero;
2. one direct child increments only the root;
3. one grandchild increments only the child;
4. grandchild release restores only the child counter;
5. child release restores the root counter;
6. duplicate release is rejected;
7. underflow rejection leaves the counter at zero.

The existing `KangerMindSafetyRunner` separately stresses concurrent creation and release of 32 direct children over repeated rounds.
