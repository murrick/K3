# Stage3bh — provider-owned pending-child snapshot and audited inspection

Added package-private ContextPendingProductionSnapshotSession. This is a separate
read-only owning lease for an actual unfinished native child. The existing settled
root writer/snapshot lease is not weakened. Neither this class nor its detached
result reserves a transaction, writes, commits, releases or authorizes publication.
The default DB validation policy remains unchanged.

## Concrete reservation ownership

A root counter alone cannot distinguish a released old child from a replacement
child while the counter is again1. Mind now records each child's original
reservation parent and whether its parent reservation is still live. The read-only
requirePendingPhysicalChild check requires the actual direct physical-root child,
same user/original parent, a live reservation, exactly one root reservation and no
pending grandchildren. Current user Mind may be the parent or that child (explicit
user transaction). The original parent reference cannot be changed via setNext.

Live metadata is cleared at existing irreversible settlement boundaries BEFORE
root finalization, including ordinary success, settle-on-rejection, operational
failure, release/discard and constructor-start abort. A retained amendable user
transaction is not marked consumed merely because validation rejected it. Native
commit decisions, factory operations, reservation counts and settlement exception
outcomes are unchanged. The marker is runtime metadata, not persisted knowledge.

## Acquired state and rechecks

Under the actual DB monitor, the lease requires its owner thread, writable open
provider, exact current user/provider and a valid live child. It captures source
Context/revision, complete parent and proposed-child native rule inventories and
exact initialized/pinned ordinary foreign views. Distinct context identities are
required; TRUST flattening is unsupported. The row allowance covers proposed X
plus foreign inventories; the parent guard inventory is separately captured under
the same finite bound.

requireCurrent rechecks ownership/reservation, current user Mind, physical address,
revision, topology, both parent/child fingerprints and every initialized foreign
fingerprint. Every inspect starts and finally ends with these checks. Whole native
binding, synchronous flat family inspection and independent whole-family audit run
freshly against those acquired views. Results accept no caller's old certificate
or audit. Binding/event bounds remain per binding; inference work and final audit
work are separate existing phase budgets, not one aggregate CPU claim. No partial
supported family can bypass an unsupported binding, resource stop or failed audit.

## Controls

New disposable actual-provider controls cover both masked sibling orders with
barrier2/verified audit, no parent settlement, release/reopen purity, cross-thread
and closed leases, whole batch consistency, inference work and audit budget stops,
row limit, unsupported function binding, changed child, multiple reservations and
pending grandchild. A real native parent edit invalidates a captured lease. This
uses an actual effective edit, not mutation of an unpersisted loaded Rule copy.

An explicit user-level current child is supported. Topology and private connected
initialization changes invalidate old leases. Even a reconnection with equal
Context/pin/certificate/initialization metadata installs a different runtime object
and invalidates the captured lease; exact effective connection identity is checked. Foreign physical HEAD advancement
preserves the old immutable pin and its audited view. Another user/provider and a
settled root cannot claim pending-child ownership. Released old children cannot
impersonate replacement reservations.

A real durable commit followed by an injected flush exception still reports
COMMITTED/original cause. Its old lease is invalid, the old child remains consumed
when a replacement reservation opens, and committed knowledge is retained.
The existing real native commit hook probe now invokes this production owning
lease (temporarily restoring the actual DB while observing the interface hook),
then always stops before settlement as before. It does not enable a default guard.
