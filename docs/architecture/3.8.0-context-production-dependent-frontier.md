# Stage515: typed, alpha-equivalent, whole-Source frontier comparison

The dependent diagnostic now constructs detached representative frontiers and compares them without confusing repeated proof applications with new units. A representative is identified by its signed conclusion and exact whole Source set; the minimum available derivation depth is retained for that identity. Different Source alternatives, including strict supersets, remain separate. The complete proof recipe/ticket ledger is unchanged.

## Equality obligations

`ContextDependentFrontierInspection.sameConclusion` compares polarity, predicate, arity and ordered arguments. It uses a bijection between result-local free-variable IDs across the entire row, preserving repeated-variable correlations. It ignores allocation IDs and variable names. Thus p(x,y) and p(y,x) are alpha-equivalent, while p(x,x) and p(x,y) are not.

Ordinary values use `SemanticTermSnapshot.semanticallyEquals`, with exact logical type and actual semantic comparison after a hash prefilter. Rendering and hash identity alone never establish equality. Applications require the exact physical witness Source (context/revision/original row/local-X/view), existential declaration position and recursively equal ordered dependency arguments. Alpha renaming can rename free coordinates; it cannot reorder the relationship between output coordinates and witness arguments. Distinct witness identities are kept distinct for comparison; this does not assert that their values are unequal.

Comparison is iterative and bounded. Exhaustion throws instead of returning false equality or a stable verdict. Conclusion equality intentionally excludes proof support and depth; representative matching additionally requires exact whole-Source set equality and keeps minimum depth. A cheaper proof improves the representative and changes the frontier. A deeper duplicate does not. Neither Source-set minimization nor general subsumption is used.

## Exact next-input frontiers

Each checked round barrier retains its actual whole physical basis, cut memberships and detached rows for all proof tickets. `Discovery.frontier` contains representative common units and representative next-input pools for every exact local/independent/TRUST cut. A next-input pool includes newly exported common units plus the cut's own visible units; it does not include a sibling's foreign-only products. This describes what the next pass can consume, even though that pass has not yet qualified the new common units.

Snapshots pin complete physical context/revision/local-X/view fingerprints, including empty members, and exact cut scopes. Comparisons of different bases, revisions or memberships refuse. Empty product pools therefore cannot hide an empty TRUST member replacement or revision change. Snapshot order is not identity: freshly reconstructed arenas and reordered equivalent physical descriptors compare equal.

Representative lists and maps are immutable. The global representative-count bound applies across the common collection and all receiving pools; a single work budget covers normalization, matching, Source checks and graph traversal. `newOrImproved` and `removedOrWorsened` count representative changes across these collections, not globally distinct logical facts. Historical snapshot equality does not authenticate current DB state: the owning lease still supplies live topology and before/after currentness guards.

## A stable frontier is not admission

The original X(left&&right->p), A(left,p), B(right,~p) scenario gives a concrete counterexample to treating unchanged frontier as consistency. After B exports negative left, the detached next-input pools already contain it for A. On the next round the representative pools can remain equal while A newly qualifies that unit and refutes its original left. The required test proves both unchanged frontier and the newly observed sourced refutation.

Future iteration must check the receiving round's refutations before declaring a fixed-point outcome. Even that finite diagnostic fixed point will not imply full-language consistency, model existence or default-writer eligibility. This stage adds no iteration or admission verdict.
