# 3.5.0.8 — parser terminal-boundary correction

## Trigger

After an in-memory source was loaded and exercised successfully, `use <database>` attempted to recompile that source while switching to persistent storage. When the source ended with delimiters after its final semicolon, tokenization advanced to `line.length()` and then called `String.charAt(line.length())`.

Observed stack:

```text
StringIndexOutOfBoundsException
  at org.kanger.compiler.Parser.nextToken(Parser.java:234)
  at org.kanger.enums.Tools.extractLine(Tools.java:308)
  at org.kanger.Mind.compile(Mind.java:733)
  at org.kanger.Console.useDatabase(Console.java:723)
```

## Intended correction

- treat `tokenEnd >= line.length()` as exhaustion in `Tools.extractLine()`;
- return `null` from `Parser.nextToken()` after delimiter skipping reaches the terminal boundary;
- add a permanent qualification gate for exact-end and trailing-delimiter source buffers;
- preserve `develop/3.5.0.7` as the closed parent shelf.
