## Problem established by the audit

The GC sweep itself is correct. Canonical residue survives when an operation-local child `Mind` escapes an exceptional Core path and keeps the owning Mind's `transactionCounter` above zero.

After the compiler-local leak was closed, five independent Core query families produced the same RED result on malformed input:

```text
+ insert
! accept
- delete
? check
= function/UDF
```

Each returned from the failed operation with one hidden reservation still active. This establishes a missing ownership abstraction rather than five separate command bugs.

## Model

KANGER now distinguishes two lifecycle classes conceptually:

```text
U0 -> U1 -> ... -> Un       explicit user-visible transaction stack
                  \
                   T        operation-local technical transaction
```

A technical transaction:

- is owned by exactly one Core operation;
- is never published as a user-visible level;
- commits or rolls back into the current owning Mind;
- cannot survive the operation boundary;
- automatically rolls back when execution leaves the scope before explicit settlement.

Success:

```text
Un + T -> commit(T) -> Un'
```

Failure:

```text
Un + T -> rollback(T) -> Un
```

At operation return, `T` no longer exists in either case.

## Structural owner

`TechnicalMindTransaction` is a package-private Java 8-compatible `AutoCloseable` owner for one child `Mind`.

```text
begin(parent)
  -> child Mind

mind()
  -> operation-local child

commit()
  -> begin settlement
  -> parent.commit(child)

rollback()
  -> begin settlement
  -> parent.release(child)

close()
  -> rollback only when settlement has not started
```

The settlement flag is set before entering `Mind.commit` or `Mind.release`. Those methods may fail after consuming the parent reservation; retrying settlement from `close()` would therefore risk double-settlement and transaction-counter underflow.

Try-with-resources supplies the required failure composition: when operation execution throws and automatic rollback also throws, the original operation failure remains primary and rollback failure is suppressed.

## Migrated Core ownership sites

The structural scope replaces handwritten operation-local `new Mind(this)` ownership in:

- `compile(...)`;
- `compileLine(...)`;
- insert;
- accept;
- delete and its candidate-discovery child;
- check;
- false-check;
- true-check;
- function/UDF implementation;
- delete-result application.

The logical algorithms, factory commit/release semantics, user transaction stack and storage lifecycle are not redesigned by this artifact.

## Next transaction stage

This artifact establishes operation-local ownership only. The subsequent transaction-model stage must formalize command-boundary invariants for the explicit user stack and storage/source operations, including:

- explicit `transaction start/commit/rollback` as the only user-visible stack mutation;
- failed `get` leaving no technical layer and no semantic delta;
- successful `get` atomically appending into the current user level;
- `use` rebasing the storage base while preserving explicit `U1..Un` boundaries;
- command return proving agreement between user-visible transaction depth and internal lifecycle state.

No merge, release acceptance, publication, deployment or production cutover is authorized by this document.
