# Stage3ah: explicit live ground write bridge

DB.writeGroundProductionCandidate is a separate ground-only authoring API. Each
call reacquires an owning ContextProductionSnapshotSession, stages the actual
single assertion and runs fresh ground-family qualification. It accepts only
the assertion and bounds, never a historical Evaluation, Certificate or trial
Artifact. The old explicit writeProductionCandidate and ordinary default authoring
are unchanged.

## Qualification and native settlement boundary

Under the provider monitor, writeGroundCandidate checks current ownership and
source/view freshness, calls the stage3ag ground qualifier (which also checks
freshness in finally), and checks requireCurrent again immediately before any
physical operation. COLLISION and INCOMPLETE return declined results with the
same before/after RevisionRef and do not call source.query. Native binding,
ownership, stale inventory or topology failures propagate without any fallback.
A model, work, round or unsupported-scope stop cannot authorize publication.

Only GROUND_FIXED_POINT reaches settlement. The session marks itself closed
BEFORE calling the ordinary source.query with the exact staged assertion. Native
transaction machinery retains responsibility for parsing, local/pair checks,
commit/rejection, generated caches, durable publication and connection certificate
refresh. No default validation is bypassed, no query result becomes primary
knowledge, and no detached staged source ID is pretended to be a physical row ID.

GroundProductionWriteResult retains the actual staged trial and the real
physical before/after revision references. PUBLISHED means native settlement
returned true; NATIVE_REJECTED means its normal false/nontrue result. Exceptions
are not converted into safe rejection. In particular a post-settlement
TransactionSettlementException(COMMITTED) propagates unchanged, and the consumed
session cannot reopen or retry it. Even a native refusal consumes this attempted
publication authority conservatively. Prewrite declines leave a still-current
read/write session usable for another freshly qualified assertion.

The public facade requires an initialized writable provider. Closed or cross-
thread sessions, unrelated Minds, open child reservations, stale source rows,
changed initialized views/connections and immutable historical revisions cannot
use this bridge. No new acceptance scope is inferred from unsupported cases;
TRUST and universal clauses remain outside the new ground route.

## Disposable end-to-end evidence

Real A left,p and B right,~p reject candidate left&&right→p at common barrier2
before any write. Candidate left&&right→q publishes through the ordinary native
transaction, consumes its old lease and persists as its own primary rule across
close/reopen. Its foreign-dependent q output is not promoted to a primary fact.
Declined candidates leave revision, rows, logs, solutions and hypotheses intact.

The full composition candidate ~a||~b||~c with A d→a, B d→b, C d,c rejects at
barrier3. The proof contains exactly five original assertion sources including
the actual candidate; physical source state is unchanged. Model assignment and
common round limits cannot fall back. Tiny work allowance can fail while binding
the real foreign snapshot; that exception likewise reaches no native publication.

A successful historical diagnosis of delayed(1), followed by actual ~delayed(1)
in X, cannot approve a later write: the facade requalifies and refuses. Changed
initialization/topology invalidates held sessions. A standalone seed→ready rule
publishes and is observed by an ordinary native query. Immutable revisions and
pending/unowned contexts refuse before writing.

A test User subclass throws from flush AFTER super.flush has durably completed.
The bridge propagates COMMITTED with the exact injected cause and a consumed
reservation; physical revision advanced and committed(1) survives reopen. The
old session cannot retry, no again(1) row appears, and only one failing flush
attempt occurs. This uses the existing virtual User.flush seam; no production
fault-injection hook or altered transaction implementation was introduced.
All fixtures are disposable, not user project databases.
