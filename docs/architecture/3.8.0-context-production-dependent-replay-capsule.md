# Stage 507: pinned dependent proof replay capsule

The inactive dependent matching path can now write a bounded binary replay packet and reconstruct its checked materialization in a fresh JVM. The packet contains whole original assertions, saved inventory-local Source coordinates, the exact receiver and ordered producer/pivot recipe, and a canonical typed graph of the final materialization. It is not a native database record or an admission receipt.

## Durable representation and reconstruction

Version1 (`K3DP`, version integer1) records the context/revision/local-X coordinate, original frozen-view label, sorted original native row IDs and exact UTF-8 source text. These IDs identify saved occurrences; they are never used to look up newly compiled rows. Reopen builds an explicit bijection to fresh Sources. All original rows, including unused primary rows, are replayed and preflighted before a result can escape.

The canonical transcript binds each witness symbol to its whole-source ordinal and declaration position. Application arguments preserve exactly the preceding universal parameters. Variable sharing and shared applications use encounter-based graph references; arena UUIDs, native CVar indexes and ephemeral variable IDs are omitted. Typed value encoding writes type names and payloads independently of `Term.pack()`, whose ownership/deletion machinery requires a Mind. No application is flattened to a scalar CVar or rendered string. Different applications do not imply unequal model values.

Reopen checks a separately retained SHA256 pin before decoding, rebuilds every original in a fresh in-memory Mind, checks the complete rebuilt inventory, replays every match and composes all later substitutions. It then recomputes the whole typed transcript and compares it byte for byte, including receiver/residual, per-producer Sources and cumulative support/depth. Recorded graph bytes never become trusted bindings or facts. Tests intentionally consume17 original Rule IDs and variable indexes before compiling the writer view; fresh replay uses different IDs and still recovers the original Source correspondence.

A packet represents **one checked chain**, including a possible partial branch. It is not a saturation or all-alternative certificate. Separate Source alternatives, including supersets, remain separate packets. A closed branch is not promoted to an existing sealed conflict/admission receipt.

## Whole-view boundary and concrete counterexample

Version1 accepts an empty initialization and a primary-only frozen inventory. Generated/deleted rows, including compiler-created auxiliary rows for some multi-clause originals, cause an explicit whole-packet refusal. They are never dropped. Opaque initialization is neither ignored nor executed during restore.

An implementation review found a real gap in the draft: changing an unused original `!unrelated(99);` in a repinned test packet to `!~newa(1)&&~newb(2);` could retain the same primary-row count and proof transcript while the compiler added auxiliary/deleted rows. Checking only `frame.entries().size()` accepted the changed whole view. The final decoder also checks **all rebuilt rows and the primary inventory** against the primary-only packet manifest. The concrete regression now refuses. Pre-fix evidence: `/tmp/k3-stage507-whole-view-probe.log`. This was a draft capsule issue, not a newly claimed defect or fix in the default Core.

## Authority and limits

The external pin identifies historical packet bytes. It authenticates neither a physical provider nor the currentness of a live context, revision, TRUST cut or configuration. The saved Source view label remains a capture-time coordinate; replay does not reauthenticate that historical native-view fingerprint from a current provider. A new caller-supplied pin does not authorize publication. Provider leases and original/independent actual-final audits are still required for integration.

Input/output bytes, row/step counts, node counts and per-phase work are bounded; UTF-8 is strict, lengths are checked before decoder allocations, and trailing/unknown-version data refuses. These are not a preemptive compiler time/memory guarantee. Capture returns only after whole proof/currentness validation; reopen exposes only a complete, checked result. Failure closes the private frame. Closing or changing the reopened frame invalidates its verification authority; historical bytes remain data.

Disk-file round trips are tested across process exit boundaries. Atomic storage replacement, fsync/crash recovery and native DB schema migration are outside this component. Default Linker, native Terms, storage writer, query and mixed admission guards remain unchanged. The real-Core required gates remain open. The next integration work is live original/provider pins distinct from inference-local mutation, then real native materialization/publication and independent actual-final checks before activating mixed admission.
