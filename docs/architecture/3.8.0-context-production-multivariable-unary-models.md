## Why Cartesian evaluation is necessary

For `p(u)||q(v)`, take one named value n plus the ALL-other-admissible class O.
Let p(n)=true,p(O)=false,q(n)=false,q(O)=true. Both equal-value pairs satisfy the
clause, while (u=O,v=n) falsifies it. Treating all variables as one iteration value
would accept a false interpretation. The old implementation rejected this shape;
it did not execute that unsound shortcut. Expansion therefore requires independent
assignments, including outside/named and different-named combinations. Reusing the
same variable still means the same assignment.

The original auditor recursively traverses variable-ID assignments. The final auditor
independently uses an odometer with explicit variable-to-position lookup. Both charge
existing work budgets and retain zero-variable evaluation exactly once. Whole-shape,
original Source/binder correlation and all actual final carrier/Source alternatives
are still checked before any receipt. Candidate exhaustion/budget/unsupported shape
remains INCOMPLETE, never a no-model refutation or publication authority.

The chosen interpretation has a uniform unary truth value for each predicate on all
unnamed admissible elements. Because supported atoms are equality-free unary atoms,
any concrete assignment maps to one of the enumerated combinations of named values
and that class; distinct unnamed elements have the same chosen unary truths. Thus
the finite traversal checks this concrete interpretation over ALL admissible values.
It neither restricts the language's universal domain to the database nor claims every
possible model has uniform unnamed values. Model truth cells are not persisted facts.
