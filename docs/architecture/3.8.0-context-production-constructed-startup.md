# Constructed dependent startup

Diagnostic only. `ContextDependentConstructedStartupInspection` constructs separate
base and proposed all-value quotient interpretations from actual native views.
The request contains the actual append, a typed search palette and explicit bounds;
it contains no interpretation maps, runtime frame or supplied qualification receipt.
The append iteration configuration overrides the search template's iteration.

A fresh exact parent/child manifest and complete family source qualification precede
search. BASE_REFUTED and CANDIDATE_REFUTED retain actual source proofs and incoming
causality; a failed interpretation never constitutes a refutation. Construction runs
separately for base and proposed families, with per-family limits. Both searches
include native original/final and independent indexed truth checks.

Constructed proposed functions initially name actual child Sources. Only the fresh
manifest translates these keys to preserved PARENT original Sources; candidate and
foreign Sources remain exact. Binder ranks and complete choice tables are preserved.
A separate rebasing work bound and whole-family function count reject truncation or
aliasing. A fresh runtime-model inspection then repeats the actual append and all
native and indexed audits, translating original keys back to actual child Sources.
The final result advertises that final qualification, not the preliminary manifest.

Any limit, unsupported shape or unsuccessful bounded search returns INCOMPLETE with
no candidate, startup or preparation prefix. Attempt counts describe spent work only.
Currentness is checked before and after the whole operation; interruption propagates.
The provider session entrypoint is owner-guarded and read-only: neither success nor
failure replaces an existing live preparation, assigns a Cvar or writes a revision.

Successful preparation is historical configuration. Existing automatic iteration can
freshly requalify it; it is not write authority or proof of ordinary eligibility.
Receiving-round model construction is not integrated here: existing automatic round
plans still require receiving interpretations. No native RED gate, default hook,
Console command, query behavior, recovery format or semantic baseline changes.

Qualification evidence is recorded after the frozen source and shaded-JAR runs.
