## Architectural contract now explicit

The Linker class-level Javadoc records:

- one Linker instance is owned by one Mind and is not a canonical store or transaction owner;
- every `link()` resets query-local solve acceleration and statistics;
- active Rule-set construction differs between full and Rule-scoped saturation;
- each pass traverses the same Rule-set first by descending full-range Rule ID and then ascending;
- fixed-point continuation is the union of Rule, TValue, FValue, temporary-hypothesis, and hypothesis action signals;
- variable rotation uses transient TSolve compatibility filtering, with indexes as acceleration only;
- domain candidates use paired local TValue/FValue checkpoints;
- functions and system predicates publish through their owning Calculator/factories and solve stores;
- `linkDatabase()` classifies branches and produced Domains while `updateDatabase()` performs delayed Rule materialization;
- Linker has no direct persistence ownership;
- flood/error and cleanup boundaries are distinct;
- one Linker instance is not independently thread-safe and depends on Mind reservation/serialization;
- `isValidFor()` and `linkDatabase()` remain frozen semantic kernels pending independent equivalence proof.
