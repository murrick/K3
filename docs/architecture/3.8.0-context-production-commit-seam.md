# Stage3bf — ordinary-authoring pre-settlement seam reconciliation

## Observed actual hook

Mind.commit calls optional IRevisionPublication.validateCommit(actualChild) before
merging native child factories into the physical root. Existing DUMB2 validation
checks pairs/composition there. The default masked contract remains RED56/2 in a
fresh run: both sibling orders still accept the masked rule. This stage does not
enable a default guard or claim that defect fixed.

A new disposable runner intercepts that actual optional publication-interface call
with a forwarding proxy over the final DB implementation. All other methods
forward to the real provider; the real legacy validateCommit is invoked explicitly
and its acceptance/refusal recorded. Production DB/Mind behavior is unchanged.
Every observation ends with the same injected pre-settlement exception, including
CONSISTENT proposals, so nothing in this probe can publish a candidate. The real
provider is restored before testing a fresh owning lease and closing storage.

The hook sees the actual direct child of the current physical parent. Its complete
native inventory is bound without recompiling a submitted command as a replacement
for the proposed state. All actual initialized/pinned foreign views are acquired
from the provider topology with one total row allowance. Detached flat family
inspection then runs on those exact native-bound snapshots.

recertified with the existing family model checker; publication remains stopped.

## Integration requirements

Do not call the explicit writer from validateCommit: it compiles/stages a new
candidate and calls source.query to write, recursively entering native settlement.
Instead qualify the exact already-prepared whole child before the existing merge.
Do not treat it as a single candidate string: batch changes/deletions/explicit
transaction commits require complete effective-state qualification. Do not weaken
the explicit snapshot lease's settled-root requirement to reuse it mid-transaction.

A production handoff still needs an owning pending-child snapshot acquisition,
exact parent/child/topology/view rechecks and an independent whole-family verdict
audit applicable to that child. CandidateAudit's single-append staging/rebasing
contract cannot simply be asserted for arbitrary proposed edits. Complete verified
consistency may allow the original native commit to continue once; collision,
unsupported scope, exhausted resources or audit failure must not fall back to
legacy acceptance. Keep source evidence tied to the proposed view, not an already
published revision. Preserve native rollback/user-transaction reservation policy,
read-only/no-context behavior and truthful post-settlement failure outcomes.
