## 1. Code hygiene

Begin with an inventory of dead code, temporary workarounds, obsolete comments,
repeated initialization and misplaced diagnostics. Remove only demonstrably
unused code. Review responsibilities in Mind, Linker, Console and federation
support before extracting cohesive components. Consolidate scattered settings
and initialization where their ownership is clear.

Use small, independently reviewable changes and appropriate regression checks.
Preserve inference behavior, correlated bindings, secondary variable children,
resultative formal hypotheses and concrete negative-proof Values. Do not turn
structural cleanup into a change of logical semantics.

## 2. Long-session stability

The next functional qualification remains repeated connections, queries,
rollback, publication and historical fork in a sustained session. Code hygiene
must not displace or silently close this work.

Check that working productions and temporary objects do not accumulate across
repeated equivalent cycles, that rollback releases child state, and that pinned
revisions retain their truth and Values as CURRENT advances. Distinguish valid
retained revision state from unsupported computed-state retention; do not use
heap size alone as proof of a leak or successful reclamation.

This extends the John/Tom regression: the individual stale-production case is
fixed; repeated lifecycle transitions still need qualification. Record cycle
counts, semantic assertions, retained-state measurements and any limitations.
Broader pin/commit/fork/cycle stress and federation performance measurements
remain part of the follow-up qualification.

### Reclamation fix

Mind now asks its federation provider to collect computed connection state only
after the root's final child reservation settles. DB retains current connections
and the members of current cached communes, protects their shared runtime
identities, closes retired layers, and prunes obsolete commune states. While any
child reservation remains live, all earlier checkpoint layers remain available.
Cleanup also runs after read-only queries without collecting persistent records.

The regression probe now alternates independent/commune connections and nested
commit/rollback, rolls back the
outer private edits, and asserts zero retired layers and zero cached communes
after each disconnect/query settlement. ContextLongSessionTest runs 40 cycles
through Maven/Surefire; the standalone main remains available for longer runs.
This qualifies reclamation at root quiescence, not bounded retention during an
arbitrarily long open outer transaction. The broader publication/pin/fork work
above remains open.

### Sustained publication and historical fork qualification

ContextPinnedSessionProbe keeps a target writer and a pinned reader open in
parallel. Across 20 cycles, target N CURRENT advances from revision 2 to 22,
while X repeatedly publishes and keeps N@2. Quantified q(x) remains TRUE with
exactly x=John; facts introduced into newer N revisions remain unknown through

Every fifth cycle forks the original X revision after CURRENT has advanced.
Each fork has independent identity, the exact source origin and dependency pin,
retains the same quantified Values, and can publish independent changes without
mutating X or N. Reopening X preserves its pinned answers. The probe additionally
checks zero retired layers and exactly one live commune after each pinned query.
ContextLongSessionTest includes this scenario in Surefire.

This covers repeated publication, CURRENT advancement, pinned truth/Values,

### Repeated stack transitions and rejected publication

ContextStackSessionProbe passes three series of ten transitions each:

- Two private initialized connection layers are squashed into U1; both derived
  answers survive squash, then disappear on outer rollback without publication.
- Two native transaction levels repeatedly rebase between X and Y. Both edits
  survive the storage switch, each rollback removes only its own level, and the
  destination baseline and pinned derived answer remain available.
- Incompatible publication is rejected ten times with U2 still selected, both
  rollback boundaries intact and CURRENT/dependency pin unchanged. Rolling back

Each series checks zero retired connection layers and exactly one current
commune after root settlement. ContextLongSessionTest includes all three series.
This qualifies these rollback paths alongside the earlier publication/fork
scenario. Repin rejection stress, topology-only cycles without root settlement,
long-open outer transactions and federation performance remain open; this is not
a blanket claim that every lifetime path has been covered.

### Topology changes without a query

The topology-only reproducer failed before the next fix on its first
connect/reconnect/disconnect cycle: retired layers survived because no query or
transaction had triggered root settlement. DB now collects after successful
connect, disconnect and revision switch when the current Mind is U0 and the
existing publication-quiescence guard confirms there are no hidden children.
It deliberately does not collect intermediate candidate vectors.

ContextTopologySessionProbe covers 40 root cycles without queries, another 40
cycles while an outer rollback checkpoint is live, and a hidden child while U0
remains selected. It checks immediate root cleanup, no automatic publication,
preservation of both visible and hidden checkpoint runtimes, and cleanup after
rollback. The scenario is part of ContextLongSessionTest.
Topology-only successful connect/disconnect is now covered; rejected topology
operations, repeated repin and long-open transaction memory bounds still need
qualification. Prior references to topology-only cycles above describe the
earlier stage and are superseded by this measurement.

### Rejected joins and repins

ContextRejectedTopologyProbe reproduced another retention path: the first
rejected join of B into N's trust commune left a candidate in retiredLayers.
The connection itself remained absent, but the failed candidate's member layer
survived until another settlement or storage close. DB now also collects after
a rejected prepared connection at quiescent U0, retaining the original error
and attaching any cleanup error as suppressed. Live child reservations still
defer collection until root settlement.

Twenty rejected commune joins and twenty incompatible repins pass with source
CURRENT, dependency pin and working topology unchanged, zero retired candidate
layers and exactly one current commune. The private Mary initialization and
derived answer survive repin rejection. The probe is in ContextLongSessionTest.
Repin's qualification helper already closes rejected replacement layers; this
stage fixes join rejection and qualifies both paths.

The remaining long-session limits are long-open outer transaction memory
bounds, resource-failure injection and performance. These measurements close
the concrete successful/rejected lifecycle scenarios above, not every possible
failure mode. Global foreign-hypothesis acceptance and M5 remain subsequent work.
