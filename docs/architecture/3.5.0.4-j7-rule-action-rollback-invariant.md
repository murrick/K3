# KANGER 3.5.0.4 — J7 RuleFactory action rollback invariant

## Finding

The J7 evidence audit found a lifecycle asymmetry in `RuleFactory`.

`RuleFactory.mark()` opened coordinated checkpoints for:

```text
Escalera Rule cache
local domain-ID index
local term-ID index
RuleCandidateIndex journals
primary-promotion overlay
```

A speculative `Rule` added after the mark set `action=true`. `release()` correctly removed the Rule and restored all derived indexes and promotion state, but it did not restore the pre-mark `action` value.

The resulting state was internally inconsistent:

```text
canonical Rule no longer visible
candidate metadata no longer contains Rule ID
promotion overlay rolled back
RuleFactory action remains true
```

Because `Linker` consumes `RuleFactory.isAction()` as a continuation signal, the released mutation could request an additional semantic pass despite leaving no surviving Rule change.

## Red gate

The focused permanent runner is:

```text
kanger-console/src/org/kanger/KangerRuleActionRollbackSafetyRunner.java
```

The runner establishes a baseline Rule, clears `action`, opens a RuleFactory checkpoint, adds a distinct speculative Rule, and releases the checkpoint. It then verifies:

```text
cache size returned to baseline
speculative Rule ID is no longer findable
action returned to false
```

Gate and workflow commits:

```text
cb1a2ae5852b536adb0236e054b9eaa0cd0ef39b  Gate Rule action rollback
0183768940bbaad5f9ac4290179c84ba40a9a4f4  Run Rule action rollback invariant
```

On `0183768940bbaad5f9ac4290179c84ba40a9a4f4`, compilation and every earlier invariant gate succeeded. Only the new `Rule action rollback invariant` failed, proving that the defect was isolated to the missing action rollback.

## Correction

Production correction:

```text
5faf73392ec0538d053b790118b868a105da35fd
Restore Rule action on checkpoint release
```

The correction adds one `Stack<Boolean>` journal to `RuleFactory`:

```text
transaction / clear -> discard obsolete action frames
mark                -> save current action
commit              -> discard saved action, retain current state
release             -> restore saved action
```

The change consists of ten added lines in `RuleFactory.java` and no deletions.

It does not change:

```text
Rule identity or structural equality
Rule ID allocation
canonical cache ownership
candidate signatures or positional filtering
promotion visibility or materialization
child-to-parent typed commit
storage schema or serialization
public API
synchronization topology
```

## Governing invariant

> A released RuleFactory checkpoint must restore canonical Rule visibility, every derived ID index, promotion state, and the Linker continuation signal as one coherent pre-mark view.
