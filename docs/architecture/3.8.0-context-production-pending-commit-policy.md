# Pending native commit refusal policy (stage 3bi)

The package-private DUMB2 `validatePendingUniversalCommit` adapter acquires the
fresh provider-owned pending snapshot, runs synchronous universal family inspection
and independent audit, then releases the lease before the caller continues the
original native commit. It never invokes an explicit writer or publishes itself.
The default `validateCommit` route is deliberately unchanged at this checkpoint.

Only an audited complete CONSISTENT verdict returns normally. An audited complete
COLLISION throws `ContextProductionCommitException` with STORAGE_CONTEXT_CONFLICT,
the immutable full family audit (including Source alternatives and opposition
proofs), and legacy diagnostic statement pairs. Unsupported binding, lost lease,
inspection limits or incomplete audit throw STORAGE_CONTEXT_INCOMPLETE with no
invented collision witnesses. Binding/ownership refusal preserves its original
cause. Detached diagnostics do not authorize any later publication.

`ContextPendingCommitPolicyRunner` temporarily intercepts actual native
IData.validateCommit in isolated fixtures, calls the strict adapter, then the
unchanged DUMB2 validation and original settlement. The test proxy temporarily
restores the real provider identity while under its monitor; this is test routing,
not production integration. Controls cover both A/B orders of the masked rule
`left(x)&&right(x)->p(x)`, barrier2 collision, rounds/work/audit limits, unsupported
function binding, ordinary consistent publication and reopen purity. An explicit
user commit rejection retains its exact live child; deleting the offending rule
with the native rule-ID selector, adding an amendment and retrying commits once.
Successful qualification followed by injected post-durable flush failure retains
the native COMMITTED outcome, original cause and durable knowledge without retry.

## Concrete blockers to blanket installation

1. After rejecting an explicit user commit, `transaction rollback` calls the
   parent's `qualifyCurrentContext(false)` before releasing the retained child.
   That qualification uses a technical transaction. A blanket strict hook now sees
   two parent reservations and refuses with STORAGE_CONTEXT_INCOMPLETE: it cannot
   acquire the single owned authoring child required by the pending lease. The test
   proves the exact user child remains current/live, then restores original routing
   and the ordinary rollback succeeds. This is a routing/ownership distinction to
   handle before enabling the policy, not grounds to weaken the snapshot lease.
2. Context WA knows `@w seed(w,1)->q(w,1)`. X contains
   `$w seed(w,1)&&flag(w,1)` and `@w seed(w,1)->warm(w,1)`, with WA connected.
   For the proposal `@w q(w,1)->out(w,1)`, this flat unit-family guard returns
   INCOMPLETE on the prepared native child. After releasing that child, the existing
   owned witness production writer publishes the same proposal from the same
   source state after its own qualification. Installing the flat adapter on every
   commit would therefore reject a supported qualified witness publication.

Both counterexamples execute the actual native path. No fail-open fallback or
historical evidence token is added. Next integration work must identify technical
qualification commits and provide an owned handoff for existing qualified writers,
while preserving the independent audit and pre-settlement refusal boundary.
General native witness/residual/function coverage remains incomplete; this stage
makes no claim to repair the default authoring contract or settle question3.

refresh scope and provider sibling-aware lease; the same complete strict inspection
and audit still run. See 3.8.0-context-production-rollback-qualification.md.
The witness-writer blocker and the unchanged default policy remain.
