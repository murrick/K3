# KANGER 3.5.0.1 — Index internal audit

## Scope

This note records the complete internal dead-code review of:

```text
kanger-data-dumb/src/org/kanger/storage/Index.java
```

It supplements the main `3.5.0.1-dead-code-audit.md` register and does not authorize behavioral changes by itself.

## Live execution graph

The private traversal and block-management helpers are rooted in active API and iterator paths:

```text
getOne / set / remove
  -> getHead
  -> loadBlock
  -> flush
  -> saveCurrentBlock
  -> writeDumb

iterator / IndexIterator
  -> getNext / getPrevious
  -> getHead / getTail
  -> loadBlock
  -> getOne
```

`IndexOne` is the live physical record carrier. Its constructor, ID/data/offset accessors, deletion/base-code flags, `readFrom`, and `writeTo` participate directly in index hydration and persistence. `compareTo` is retained as the declared `Comparable<IndexOne>` contract. `toString` remains a compatibility/debug surface.

`IndexIterator` constructors and methods are live through both `iterator()` overloads. Empty `Iterator.remove()` implementations are legacy iterator semantics, not unreachable methods.

## Confirmed D2 additions

In addition to the previously registered historical fragments, `Index.java` contains two more commented former implementations:

1. the complete `getFreeBlock()` helper, which formerly consumed `emptyIndex` to reuse deleted blocks;
2. an abandoned conditional fallback inside `lastKey()` based on a former `IndexOne.getSize()` check.

These comments are not compiled and have no runtime, binary, persistence, reflection, or diagnostic effect.

**Classification:** D2 — safe source cleanup.

They should be added to manifest `3.5.0.1-A`, with the same invariant that no executable token changes.

## Dead-state candidate: `emptyIndex`

The private field:

```java
private NavigableMap<Long, IndexOne> emptyIndex =
        new ConcurrentSkipListMap<>();
```

is modified by live code but has no live read path in the audited class.

Current writes are:

- `open(...)` stores deleted physical block heads;
- `clear()` and `close()` clear the map;
- `saveCurrentBlock()` stores a block head when a block becomes empty;
- `remove(...)` stores a deleted head.

The only observed consumer is the fully commented former `getFreeBlock()` implementation. Consequently, the map currently records reusable physical blocks but the allocator always appends new blocks and never consults that record.

This makes the following executable statements potential dead state maintenance:

```text
field allocation of emptyIndex
emptyIndex.clear() lifecycle calls
emptyIndex.put(...) calls during open/save/remove
```

The writes do not participate in index lookup, traversal, persistence layout, flushing, recovery, or counters. Removing them should preserve current observable execution semantics while reducing memory and mutation overhead.

However, this candidate is not yet approved because the field is private and could still be named by reflection-based diagnostics or qualification code outside the class.

**Classification:** U/D1 — probable unreachable state, pending exact-name reflection and qualification-runner exclusion.
