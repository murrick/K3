# KANGER 3.7.0.1 — accepted `rule` command family

Status: ACCEPTED DESIGN DECISION / DOCUMENTATION ONLY

Reference runtime: `release/3.5.2` at `9c8b7dd2c9ef347cea6af6a6faef9cfa48030306`

## Canonical family

The canonical operator-facing `rule` family is:

```text
rule
rule all
rule produced
rule level <n>
rule show <id>
rule tree <id>
rule comment <id>
rule comment <id> <text...>
```

## Semantics

- bare `rule` is a read-only projection of the current rule context;
- `rule all` selects all rules;
- `rule produced` selects produced/generated rules;
- `rule level <n>` selects rules at a transaction/context level;
- `rule show <id>` displays one rule explicitly by runtime id;
- `rule tree <id>` displays provenance / derivation tree for one rule;
- `rule comment <id>` reads the current comment;
- `rule comment <id> <text...>` updates the comment.

## Grammar decision

For this family the second token may be a selector or an action word. This is intentionally simple and explicit:

```text
<group> [<selector-or-verb>] [<arguments...>]
```

The semantic hierarchy remains:

```text
WHERE -> WHAT EXACTLY / WHAT TO DO -> WITH WHAT
```

Do not add redundant forms such as:

```text
rule show all
rule show produced
rule show level 2
```

The shorter selector forms are preferred because they are unambiguous and match the command-dialogue character of KANGER.

## Explicit-id rule

Do not use `rule <number>` as the canonical form for one-rule display.

Canonical syntax is:

```text
rule show <id>
```

This avoids argument-shape inference in the dispatcher. A command word is resolved as a command word; the dispatcher does not need to guess whether token 2 is a keyword or a numeric id.

## Implementation principle

This family is intentionally compatible with a very simple Console dispatcher:

```text
switch(group)
  -> switch(selector-or-verb)
     -> parse only the arguments required by that branch
```

No heavy parser architecture is required. Prefer the simplest transparent implementation that satisfies the accepted command contract.
