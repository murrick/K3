# KANGER 3.7.0.1 — Console flash-back requirement

Status: ACCEPTED FOLLOW-UP TODO / DEFERRED / NO RUNTIME CHANGE IN 3.7.0.1

Reference runtime: `release/3.5.2` at `9c8b7dd2c9ef347cea6af6a6faef9cfa48030306`

## Decision

The current artifact is UI / command-model design work. Do not interrupt it by modifying the historical Java Console.

After the canonical KANGER command language and registry are closed, the Console must be revisited in a dedicated follow-up stage and brought onto the same command model.

This is a TODO for later implementation, not a defect that blocks the present UI baseline.

The historical one-letter Console dispatch is understood as a pragmatic debugging-era shortcut. It is not treated as an architectural problem in itself; it is simply not the common dispatcher model chosen for the converged interfaces.

## Required outcome

Console, Browser and future UI must eventually converge on one command dialogue and one family identity model:

```text
Core semantics
  -> Practicum-derived command taxonomy
  -> canonical command registry
  -> fixed four-character family IDs
  -> Console | Browser | future UI
```

Human-readable canonical command words remain the user-facing grammar. The four-character family ID is the common registry/dispatcher identity.

Representative IDs include:

```text
SOURCE        -> SOUR
STORAGE       -> STOR
TRANSACTION   -> TRAN
RULE          -> RULE
FUNCTION(S)   -> FUNC
BASE          -> BASE
VALUES        -> VALU
SOLUTION(S)   -> SOLU
WHEN          -> WHEN
XPLAIN        -> XPLA   # Console-local diagnostic family
```

## Concrete deferred migration targets

At minimum the later Console flash-back must normalize historical divergences including:

```text
append [n]               -> when accept <n>
list                     -> when
transaction create       -> transaction start
one-letter top dispatch  -> common four-character family-ID dispatcher
put <numeric-rule-id>    -> rule comment <id>
index / pack             -> canonical storage reindex family
missing source delete    -> canonical source delete lifecycle
historical options/log   -> accepted family-local presentation commands where applicable
```

Source lifecycle in the converged Console must include the accepted server-side base operations, including `delete`; Browser-only upload/download transport remains outside the Console command language.

Exact compatibility aliases, if any, are a later migration/usability decision. They must resolve one-to-one to the same canonical command family/action and must not preserve separate execution paths.

## Preservation constraint

The flash-back is a command-language and dispatcher convergence task, not a Console redesign.

Preserve useful historical interactive and debugging behavior where it remains compatible with the accepted model, including Console-local diagnostics such as `xplain`.

## Sequencing / TODO

Do not implement this migration during the current 3.7.0.1 UI design pass.

Required sequence:

```text
3.7.0.1  close UI/design baseline and canonical registry
    -> parser/dispatcher conformance specification
    -> implementation ownership
    -> dedicated Console flash-back/convergence artifact
    -> Browser/future-UI adoption through the same command model
```

The exact fourth-component artifact number is intentionally not assigned yet.

This document is the durable TODO marker so Console convergence is not lost while the current work stays focused on UI design.
