# KANGER 3.7.0.1 — Console flash-back requirement

Status: ACCEPTED FOLLOW-UP TODO / DEFERRED / NO RUNTIME CHANGE IN 3.7.0.1

Reference runtime: `release/3.5.2` at `9c8b7dd2c9ef347cea6af6a6faef9cfa48030306`

## Decision

The current artifact is UI / command-model design work. Do not interrupt it by modifying the historical Java Console.

After the canonical KANGER command language and registry are closed, the Console must be revisited in a dedicated follow-up stage and brought onto the same command model.

This is a TODO for later implementation, not a defect that blocks the present UI baseline.

The historical one-letter Console dispatch is understood as a pragmatic debugging-era shortcut. It is not treated as an architectural problem in itself; it is simply not the common parser model chosen for the converged interfaces.

## Required outcome

Console, Browser and future UI must eventually converge on one command dialogue and one abbreviation rule:

```text
Core semantics
  -> Practicum-derived command taxonomy
  -> canonical command registry
  -> minimum-unique-prefix parser
  -> Console | Browser | future UI
```

Canonical full words remain the documentation/help form. Interactive input may use the shortest unambiguous leading prefix in the relevant grammar position. There is no fixed three-character or four-character rule.

## Concrete deferred migration targets

At minimum the later Console flash-back must normalize historical divergences including:

```text
append [n]               -> when accept <n>
list                     -> when
transaction create       -> transaction start
one-letter top dispatch  -> common keyword/minimum-unique-prefix parser
put <numeric-rule-id>    -> rule comment <id>
index / pack             -> accepted storage reindex family
missing source delete    -> delete <source>
historical options/log   -> accepted family-local presentation commands where applicable
```

Canonical source vocabulary is closed as the top-level operations:

```text
get <source>
put <source>
delete <source>
```

Browser-only upload/download transport remains outside the Console command language.

## Console-local source-list convenience

Preserve terminal self-sufficiency by allowing these no-argument Console forms:

```text
get
put
delete
```

Each bare form is read-only and lists the available source names. It performs no source mutation and does not automatically choose an item.

After inspecting the list, the operator issues the explicit named source command.

This is a Console-local presentation convenience rather than an additional canonical source intent. Browser/UI does not need the same no-argument behavior because the source namespace is already visible/selectable there.

## Other Console-local behavior

Exact compatibility aliases, if any, are a later migration/usability decision. They must resolve one-to-one to the same canonical operation and must not preserve separate execution paths.

The flash-back is a command-language and dispatcher convergence task, not a Console redesign.

Preserve useful historical interactive and debugging behavior where it remains compatible with the accepted model, including Console-local diagnostics such as:

```text
xplain
xplain <file>
xplain mode on
xplain mode off
```

## Sequencing / TODO

Do not implement this migration during the current 3.7.0.1 UI design pass.

Required sequence:

```text
3.7.0.1  close UI/design baseline and canonical registry
    -> parser/dispatcher conformance specification
    -> implementation ownership
    -> dedicated Console flash-back/convergence artifact
    -> Browser/future-UI adoption through the same command model
```

The exact fourth-component artifact number is intentionally not assigned yet.

This document is the durable TODO marker so Console convergence is not lost while the current work stays focused on UI design.
