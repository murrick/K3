# KANGER 3.7.0.1 — Console flash-back requirement

Status: ACCEPTED FOLLOW-UP TODO / DEFERRED / NO RUNTIME CHANGE IN 3.7.0.1

Reference runtime: `release/3.5.2` at `9c8b7dd2c9ef347cea6af6a6faef9cfa48030306`

## Decision

The current artifact is UI / command-model design work. Do not interrupt it by modifying the historical Java Console.

After the canonical KANGER command language, parser conformance contract and shared command-processor ownership are closed, the Console must be revisited in a dedicated follow-up stage and brought onto the same command model.

This is a TODO for later implementation, not a defect that blocks the present UI baseline.

The historical one-letter Console dispatch is understood as a pragmatic debugging-era shortcut. It is not treated as an architectural problem in itself; it is simply not the common parser model chosen for converged interfaces.

## Shared processor target

Console must consume the accepted shared module:

```text
kanger-command/
    src/org/kanger/command/...
```

The Console must not retain an independent keyword table or forked parser after convergence.

Canonical flow:

```text
raw Console line
    -> Core-language bypass OR kanger-command
    -> canonical intent + arguments
    -> Console-local dispatcher/presentation
    -> existing runtime operation
```

`kanger-command` itself remains runtime-neutral and does not depend on Console or `IMind` execution semantics.

## Required outcome

Console, Browser/Server and future interfaces converge on one command dialogue and one abbreviation rule:

```text
Core semantics
  -> Practicum-derived command taxonomy
  -> canonical command registry
  -> kanger-command parser/registry
  -> Console | Server-backed Browser/UI | future clients
```

Canonical full words remain the documentation/help form. Interactive input may use the shortest unambiguous leading prefix in the relevant grammar position. There is no fixed three-character or four-character rule.

## Concrete deferred migration targets

At minimum the later Console flash-back must normalize historical divergences including:

```text
append [n]               -> when accept <n>
list                     -> when
transaction create       -> transaction start
one-letter top dispatch  -> shared keyword/minimum-unique-prefix parser
put <numeric-rule-id>    -> rule comment <id>
rule show <id>           -> rule <id>
index / pack             -> storage reindex <name>
missing source delete    -> accepted delete <source>
historical options/log   -> accepted family-local presentation commands where applicable
```

Browser-only upload/download transport remains outside Console command language.

Exact compatibility aliases, if any, are a later migration/usability decision. They must resolve one-to-one to the same canonical operation and must not preserve separate execution paths.

## Console-local preserved behavior

The flash-back is command-language and dispatcher convergence, not a Console redesign.

Preserve useful historical terminal/debugging behavior where compatible with the accepted model, including:

```text
xplain ...

get
put
delete
    -> read-only source listing convenience when no argument is supplied
```

These are Console adapter/presentation behaviors over the shared processor contract, not alternate Browser/UI grammar.

## Sequencing / TODO

Required sequence:

```text
3.7.0.1  close UI/design baseline
    -> transport/intent mapping
    -> dedicated command-processor implementation artifact
    -> Console flash-back/convergence artifact
    -> Browser/future-UI adoption through the same processor
```

The exact fourth-component artifact numbers are intentionally not assigned yet.

This document is the durable TODO marker so Console convergence is not lost while the current work stays focused on design.
