# KANGER 3.7.0.1 — Console flash-back requirement

Status: ACCEPTED FOLLOW-UP REQUIREMENT / NO RUNTIME CHANGE IN THIS COMMIT

Reference runtime: `release/3.5.2` at `9c8b7dd2c9ef347cea6af6a6faef9cfa48030306`

## Decision

After the canonical KANGER command language and registry are closed, the historical Java Console must be revisited in a dedicated follow-up stage and brought onto the same canonical command grammar.

This is not optional cleanup. It is required to prevent KANGER from retaining two user-facing command languages.

## Required outcome

Console, Browser and future UI must converge on one command dialogue:

```text
Core semantics
  -> Practicum-derived command taxonomy
  -> canonical parser / command registry
  -> Console | Browser | future UI
```

The Console must stop being an independent command-language authority.

## Concrete migration targets

At minimum the Console flash-back must remove or normalize historical divergences including:

```text
append [n]               -> when accept <n>
list                     -> when
transaction create       -> transaction start
first-letter dispatch    -> canonical keyword/prefix parser
put <numeric-rule-id>    -> rule comment <id>
index / pack             -> canonical storage reindex family
missing source delete    -> canonical source lifecycle
```

Exact compatibility aliases, if any, are a migration/usability decision. They must resolve one-to-one to the canonical command ID and must not preserve a separate execution path.

## Preservation constraint

The flash-back is a command-language and dispatcher convergence task, not a Console redesign. Preserve useful historical interactive behavior where it remains compatible with the canonical model.

## Sequencing

Do not implement this migration before the command vocabulary, selector grammar, canonical registry, parser conformance cases and parser/dispatcher ownership are accepted.

Recommended sequence:

```text
3.7.0.1  close design baseline and canonical registry
    -> parser conformance specification
    -> parser/dispatcher ownership
    -> implementation stage
    -> Console flash-back/convergence stage
    -> Browser/future-UI adoption through the same command model
```

The exact fourth-component artifact number for the Console flash-back is intentionally not assigned yet; it must follow the repository lifecycle and the accepted decomposition of the implementation work.
