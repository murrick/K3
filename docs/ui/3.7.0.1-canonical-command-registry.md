# KANGER 3.7.0.1 — Canonical command registry

Status: **ACCEPTED DESIGN BASELINE / DOCUMENTATION ONLY**

Reference runtime: accepted `release/3.5.2`.

This registry consolidates the accepted 3.7.0.1 command-language decisions. It changes no runtime behavior.

## 1. Parsing boundary

KANGER logical expressions remain Core language and are not ordinary command words:

```text
! ? + - =
```

The command dialogue is case-insensitive in keyword positions and uses minimum unique leading prefixes in the relevant grammar position.

Resolution rule:

1. exact full keyword wins;
2. otherwise a unique leading prefix resolves the keyword/family stem;
3. ambiguity is rejected;
4. argument spelling must not be used to guess between unrelated command identities.

Arguments preserve their content/case and are validated by the relevant semantic/namespace layer. Accepted lexical and quoting details are recorded in `3.7.0.1-command-lexical-decisions.md`.

Aliases are not part of this canonical registry or prefix calculation. Any later compatibility alias must normalize one-to-one to a canonical intent before execution.

## 2. Singular/plural family rule

`function/functions`, `solution/solutions`, and `base predicate/predicates` are not independent dispatcher namespaces.

They are grammatical forms inside one semantic family/selector stem:

```text
FUNCTION family
    functions
    function <id>
    function source <id>

SOLUTION family
    solutions
    solution <id>
    solution tree <id>

BASE / PREDICATE selector
    base predicates
    base predicate <id|name>
```

Prefix resolution therefore targets the semantic family/selector stem first. The grammar production then determines the canonical singular/plural echo.

This preserves short deterministic prefixes without treating English number inflection as separate command ownership.

## 5. Source operations

Source lifecycle intentionally remains self-identifying top-level verbs rather than an artificial `source` namespace.

Canonical Browser/UI executable forms are:

| Intent ID | Canonical syntax | Class | Mutation | Destructive |
|---|---|---|---:|---:|
| `SOURCE_GET` | `get <source>` | USER_MUTATION | yes | no |
| `SOURCE_PUT` | `put <source>` | USER_MUTATION | yes | no |
| `SOURCE_DELETE` | `delete <source>` | USER_MUTATION | yes | yes |

The source argument is explicit in Browser/UI command execution. The visible/selectable Source menu supplies the presentation assistance needed to compose that argument.

The deferred Java Console may additionally accept bare:

```text
get
put
delete
```

as a read-only terminal convenience that lists available source names and performs no mutation. These bare forms are Console-local presentation behavior, not additional canonical source intents and not part of Browser/UI grammar.

Browser/UI transport actions are outside this registry:

```text
Source menu
    Get
    Put
    Delete
    Upload
    Download
```

`upload` and `download` are Browser transport actions, not KANGER commands and not participants in prefix resolution.

## 10. Lexical contract

The accepted lexical model is intentionally small:

```text
keyword/argument tokens separated by whitespace
+ double-quoted argument when one argument contains whitespace
+ minimum-unique-prefix resolution only in keyword positions
+ free-text remainder for rule comment bodies
```

Keywords are case-insensitive; argument content is preserved. Once the grammar expects an argument, a word that happens to equal a command keyword is still data.

Quoted arguments use double quotes. Inside them only `\"` and `\\` are special. No single-quote or shell-style escape syntax is introduced.

`rule comment <id>` is the read form; `rule comment <id> <text...>` sets the comment, and `rule comment <id> ""` sets an explicitly empty comment.

Source/storage names are namespace objects, not filesystem-path expressions. Legality/canonicalization is validated below the lexer.

## 11. Console-local diagnostic outside UI registry

`xplain` remains Console-local and is not part of the Browser/UI canonical command surface:

```text
xplain
xplain <file>
xplain mode on
xplain mode off
```

Its later Console implementation follows the same minimum-prefix principle where applicable, but it does not affect the UI prefix table.
