## Corrections

### EDITOR-COMPILE-EOF-02 — residual Browser view boundary closed

The Server/compiler boundary introduced in 3.7.0.7 remains unchanged: compiler
compatibility may normalize a copy, while the source-document contract remains
exact.

The residual failure was one layer later. After Compile, the Browser returned
to Console and a subsequent Editor open fetched the Server representation
again. That view transition could therefore replace the exact author buffer
with a reconstructed/normalized representation even though compilation itself
had preserved the intended source semantics.

The 3.7.0.8 Browser convergence layer now keeps the exact CodeMirror author
buffer as the reusable Editor document across pure Editor/Console view
navigation. It binds that buffer to the authoritative Server workspace source
projection and invalidates reuse when the projection changes.

Thus the intended contract is now:

```text
exact author buffer
      |
      +--> Compile payload / exact source-document identity
      |
      +--> Console view
      |
      `--> Editor view reuses the same exact buffer

Server workspace/source transition (get / erase / other mutation)
      |
      `--> invalidate reusable local Editor view
          and use the ordinary authoritative Server source load
```

No compiler normalization is performed by this Browser layer and no KANGER
command is parsed or executed by it.

The focused VPS qualification pins the original failure exactly: a 26-byte
source with no final CR/LF must still save as exactly 26 byte-identical bytes
after Compile and a Console query.

### SPLITTER-GEOMETRY-07 — residual competing path retired

3.7.0.7 introduced `--kanger-left` as the intended grid-width authority, but
the historical splitter node still retained an old inline handler and the late
3.7.0.7 anonymous drag listener. Legacy `placeElements()` could also continue
to write inline left/right geometry.

3.7.0.8 makes ownership explicit:

```text
left splitter pointer
        |
        v
--kanger-left
        |
        v
CSS grid geometry
```

The live splitter node is replaced by a clone, atomically discarding both the
historical inline handler and the prior anonymous listener. The new capture
handler suppresses the legacy mousemove path, keeps historical `sizeX` inert,
and persists only `sx`.

A narrow MutationObserver removes any later legacy inline `width`/`left`
geometry from the left/right containers, so old layout code can no longer
become a second width authority after initialization.

The Browser artifact inventory remains the same qualified 22 files; the final
convergence code is contained in existing `bottom-layout.js` rather than adding
an unqualified 23rd Browser file.

## Small Browser usability corrections

### Help exposes the `rules` collection alias

`rules` already executed with canonical `rule all` semantics in 3.7.0.7. It is
now also discoverable in registry-derived Help.

The registry model now explicitly permits multiple documented syntax
Definitions for one semantic intent. The first definition remains the
canonical formatter representative, therefore:

```text
input alias:       rules
semantic intent:   RULE_ALL
canonical format:  rule all
```

No command grammar fork is introduced.

### One clear-input control

The command input now receives one local presentation-only clear control at its
right edge: a circular button containing a centered multiplication/cross glyph
`×`.

Clicking it clears only the current input, leaves focus in the input and does
not execute, submit, store or otherwise mutate a KANGER command.

### Return from Editor goes to latest dialogue activity

When Console is reopened from Editor, `query-history` is positioned at its
current `scrollHeight`. The operator therefore returns to the most recent
activity instead of the startup/top-of-history position.

### Obsolete confirmation e-mail menu action removed

`Resend confirmation e-mail` is no longer meaningful in either supported
registration/authentication mode. The authenticated user menu therefore no
longer exposes that action, unconditionally. `Personal data`, `Change login &
password`, and `Quit` remain.

This correction intentionally removes only the dead Browser affordance. The
legacy resend backend path is outside this narrow UI correction artifact and is
not used by the supported UI.
