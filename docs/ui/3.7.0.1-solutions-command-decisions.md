# KANGER 3.7.0.1 — `solutions` command decisions

Status: **ACCEPTED DESIGN DECISION / DOCUMENTATION ONLY**

Reference runtime: accepted `release/3.5.2`.

No runtime behavior is changed by this document.

## 1. Semantic object

`Solutions` is the set of proof-producing statements produced by the last informational query.

Unlike `Values`, each Solution is a concrete logical object (`IRule`) with its own runtime identity and provenance.

Therefore a Solution may be addressed by its semantic/runtime ID.

## 2. Accepted canonical syntax

```text
solutions
solution <id>
solution tree <id>
```

Semantics:

```text
solutions
```

shows the current Solutions set for the last informational query.

```text
solution <id>
```

shows the concrete solution whose logical/runtime ID is `<id>` from the current Solutions set.

```text
solution tree <id>
```

shows the inference/provenance tree of that concrete solution.

## 3. Deliberately rejected syntax

The canonical language does not include:

```text
solutions tree
solutions tree <id>
solution show <id>
solutions all
```

Rationale:

- `solutions` already means the complete current set;
- `solution <id>` is already an unambiguous singular object address, so `show` is redundant;
- provenance is useful when attached to a specific addressed solution;
- a bulk "all trees" mode adds output volume without expressing a distinct enough operator intention.

## 4. Identity invariant

`solution <id>` addresses the ID of the underlying logical statement, not a presentation row number or ordinal position in the Solutions list.

This differs fundamentally from `Values`, whose rows are a rowset projection and are not exposed as semantic identities.

## 5. `tree` family semantics

The accepted command language now uses `tree` only for a concrete addressed logical object:

```text
rule tree <rule-id>
base tree <statement-id>
solution tree <solution-id>
```

The exact meaning of the tree follows the semantic family:

- `rule tree` — compiled/structural tree of a rule;
- `base tree` — inference tree of a derived statement in the base;
- `solution tree` — inference/provenance tree of a solution produced by the current query.

The common command-language principle is that `tree` is not a bulk display mode.

## 6. Design principle

Apply Occam's razor to the command dialogue:

- plural form addresses the current collection;
- singular form addresses one semantically identifiable object;
- avoid redundant `show`/`all` words when the grammatical form is already unambiguous;
- expose provenance only where it carries concrete semantic value.
