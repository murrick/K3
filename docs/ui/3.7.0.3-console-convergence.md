## 1. Purpose

The accepted 3.7.0.1 design requires typed and composed commands to share one command-language authority. 3.7.0.2 established that authority in `kanger-command` and connected Server raw dialogue to it.

3.7.0.3 applies the same model to the historical Java Console:

```text
operator line
    |
    +-- Core prefix ! ? + - =
    |       -> existing Mind/Core execution
    |
    +-- ordinary command
            -> CommandParser
            -> CommandInvocation
            -> canonical Console runtime adapter
            -> existing Mind/storage/source operations
```

The active Java Console entry point no longer uses first-character dispatch as the authority for raw operator commands.

## 2. Active Console boundary

`kanger-console/src/org/kanger/CanonicalConsole.java` owns the interactive session.

It uses:

```text
CommandParser
CommandFormatter
CommandHelpRenderer
CommandInvocation
SortKey
```

from the shared `kanger-command` source root.

`kanger-console/src/org/kanger/Kanger.java` now starts:

```text
CanonicalConsole.session(mind, shutdownHook)
```

instead of the historical `Console.session(...)` path.

The historical `Console.java` is retained in this artifact as rendering/lifecycle helper code and behavioral evidence. Its raw first-character session loop is no longer the default executable Console path. Removal or mechanical delegation of that dormant compatibility entry is source-hygiene work, not a second grammar authority for the active Console.

## 3. Canonical command execution

The Console adapter consumes normalized `CommandInvocation` values and maps them to existing Core/runtime behavior.

Implemented families:

```text
rule
function/functions
base
values
solution/solutions
when
transaction
get / put / delete
storage
erase
help
quit
```

Important semantic bindings preserve the accepted command model:

- `solution <id>` and `solution tree <id>` address actual runtime `IRule.id`, never display row position;
- `when` displays optimized hypotheses using zero-based indexes;
- `when accept <index>` addresses that same zero-based row and delegates to existing `Mind.queryAccept(...)` semantics;
- `base tree <statement-id>` selects Base statements only;
- `values order ...` sorts a copied projection and does not mutate configured/default Values order;
- `help` is generated from the shared `CommandRegistry` through `CommandHelpRenderer`;
- minimum-prefix and ambiguity behavior therefore comes from the same parser used by Server dialogue.

## 4. Core language remains separate

Lines beginning with the historical Core operators:

```text
! ? + - =
```

bypass ordinary command dispatch.

The Console preserves the existing Core execution path, transaction overlay behavior, query-local log/result publication and comment attachment semantics. The shared command processor is not a replacement for the KANGER Core parser.

## 5. Console-local forms

The following remain intentionally outside the canonical intent registry:

```text
get
put
delete
```

with no argument are read-only source-name listings in Java Console only.

Also Console-local:

```text
xplain
xplain <file>
xplain mode on
xplain mode off
z
```

`z` repeats the last Core query.

These forms do not add canonical intent IDs and do not affect minimum-prefix calculation for the shared command language.

## 6. Source and storage adapters

Source file commands operate inside the user's source directory. `CanonicalConsole` resolves source targets canonically and rejects targets whose resolved parent is not the source root.

Storage execution preserves the already-qualified historical Console lifecycle model:

```text
storage use <name>
    -> open/create persistent baseline
    -> if an offline workspace exists, insert it as a level-1 overlay

transaction commit
    -> commit overlay into persistent root

storage close
    -> existing close/checkpoint lifecycle
```

Storage lifecycle logic is not reimplemented in the command parser. Existing `Mind`/`User` lifecycle and DUMB persistence operations remain authoritative.

The historical local Console logical-name mapping (`a.b` -> hierarchical storage path) is preserved in this artifact. Server filesystem-name policy remains independently enforced by `ApiInputPolicy`; changing the local storage naming contract is outside this convergence slice.

## 9. Compatibility boundary

3.7.0.3 does not rewrite Browser transport or UI.

It also does not remove the historical `Console.java` implementation wholesale. That file still provides rendering/helpers used by the canonical adapter and retains dormant compatibility code. What is closed here is the active Java Console operator boundary:

```text
raw ordinary command
    -> shared kanger-command parser
    -> exactly one canonical intent
    -> Console runtime adapter
```

No active default Console command path derives ordinary command meaning from the historical first character of raw user input.
