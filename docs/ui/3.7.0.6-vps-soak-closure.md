## Findings carried into 3.7.0.7

### COMMAND-GRAMMAR-01 — missing plural RULE collection alias

Observed:

```text
rules
[application:command_parse_error] Unknown command rules
```

Required canonical symmetry:

```text
rule <id> / rules
function <id> / functions
solution <id> / solutions
```

Target semantics:

```text
rules == rule all
```

`rule` itself remains the current-rule-context command.

### HELP-COMPOSE-UX-02 — parameter metavariables copied literally

Help correctly displays complete syntax, but clicking a parameterized syntax such as:

```text
rule <id>
```

currently composes the literal metavariable. Required compose behavior is the fixed executable prefix with the caret at the first user argument:

```text
rule 
rule tree 
base predicate 
storage drop 
when accept 
```

Finished no-argument commands continue to compose without a trailing space.

### SOLUTIONS-TREE-UX-03 — action decoration mismatch

Current visible action:

```text
○ tree
```

Required visible action:

```text
○
```

The tooltip/action meaning may still be `tree`; only the visible row control should match the icon-only presentation of adjacent semantic controls.

### EDITOR-COMPILE-EOF-02 — compile normalization mutates authoritative editor bytes

A source without final EOL was 26 bytes before Compile and 27 bytes after Compile/reopen.

The final statement correctly participates in compilation and inference, so EOF normalization solves the compiler-boundary problem. The defect is that the normalized LF leaks back into authoritative/current source state.

Required boundary:

- preserve exact editor/source bytes as authoritative source;
- give the compiler a normalized copy when needed;
- do not repair this after the fact by stripping bytes during reopen.

### DESTRUCTIVE-CONFIRM-UI-04 — Browser destructive confirmation unusable

Confirmed affected Browser paths:

```text
erase
delete <source>
storage drop <name>
```

The Server correctly requests confirmation. Java Console confirmation works. Browser receives the confirmation request but the current confirmation path cannot be accepted in the deployed Browser environment and resolves locally as `Cancelled`.

Required result: a Browser-owned usable confirmation UI that resubmits the exact same raw canonical line with only `confirmed=true`; Browser must not acquire destructive-command semantics.

### PUT-OVERWRITE-CONFIRM-05 — existing source overwrite is unguarded

Required semantics:

```text
put <new-source>      -> immediate save
put <existing-source> -> explicit confirmation
```

Observed existing-source overwrite saves immediately without a server confirmation request.

The confirmation requirement belongs to the canonical Server operation, not Browser command recognition.

### TRANSACTION-PROJECTION-06 — upper transaction indicator remains stale

Canonical transaction commands update Server state correctly, but the upper Browser transaction indicator changes only after a full refresh.

Confirmed cause in the 3.7.0.6 Browser boundary: canonical transaction presentation supplies a truthy presentation argument to the legacy response path, while `showTransactionLevel(data)` is only called inside the no-presentation branch.

Required result: transaction state projection updates for canonical transaction responses without changing command execution authority.

### SPLITTER-GEOMETRY-07 — conflicting left-column geometry owners

Observed narrow-layout behavior:

```text
drag left -> follows pointer -> threshold -> snaps/jumps right
```

Confirmed cause:

- legacy splitter writes/persists `sx` and tries to set the left container width;
- the presentation CSS grid independently owns the same geometry through `--kanger-left` and `width:auto !important`.

Required result: one authoritative geometry owner. Prefer integrating the existing splitter with the CSS-grid custom property rather than maintaining competing width models.

## Semantic clarification discovered during the soak

An exact duplicate rule is **not** a collision. Canonical semantic duplicates are deduplicated/reused. A rejected-`get` collision fixture must therefore contain a real contradiction, e.g. positive versus negative form of the same statement.

## 3.7.0.7 scope

`ui/3.7.0.7-soak-corrections` starts exactly from the deployed 3.7.0.6 canonical product head and is intentionally limited to the eight findings above plus regression tests and qualification documentation.

No new feature scope is admitted into this artifact. The previously recorded future source-management work — Browser `.k` delete/drop, upload/download, and upload collision validation analogous to `get` — remains a later UI-stage requirement and is not part of 3.7.0.7.

After correction, the next VPS qualification should be a targeted third soak over the eight findings, the blocked destructive cleanup case, and a minimal source/Core/server health smoke.
