# KANGER 3.7.0.1 — `base` command decisions

Status: **ACCEPTED DESIGN DECISION / DOCUMENTATION ONLY**

Reference runtime: accepted `release/3.5.2`.

No runtime behavior is changed by this document.

## 1. Semantic object

`base` is the operator-facing projection of the current semantic statement/domain base. It is distinct from physical persistent `storage`.

The accepted authorial distinction is:

- `base` addresses semantic knowledge already represented in the current KANGER context;
- `storage` addresses physical durable database lifecycle.

## 2. Accepted canonical syntax

```text
base
base predicates
base predicate <id|name>
base tree <statement-id>
```

## 3. `base`

```text
base
```

shows the current unambiguous domains/statements represented in the semantic base.

It is a read-only projection.

## 4. `base predicates`

```text
base predicates
```

shows the predicates known in the current semantic context, independently of whether they currently have unambiguous domains.

## 5. `base predicate <id|name>`

```text
base predicate <id>
base predicate <name>
```

shows the unambiguous domains/statements associated with the selected predicate.

Predicate references may be numeric IDs or predicate names. Predicate-name lexical syntax already excludes a leading digit, so the two reference forms are intrinsically distinguishable without an additional selector or heuristic.

## 6. `base tree <statement-id>`

```text
base tree <statement-id>
```

shows the inference/provenance tree of one concrete derived statement in the base: how that statement was obtained.

This is intentionally different from:

```text
rule tree <rule-id>
```

which addresses the compiled/structural representation associated with a rule.

The common `tree` word is attached to one concrete addressable logical object; it is not a bulk rendering mode.

## 7. Rejected historical/generalized forms

The canonical grammar does not retain:

```text
base <predicate-name>
base <predicate-id>
base tree
base tree <predicate-name>
base tree predicate <id>
```

The accepted grammar makes predicate selection explicit and reserves `base tree` for provenance of one statement.

## 8. Family completeness

For 3.7.0.1 the `base` family is complete at this level:

```text
base
base predicates
base predicate <id|name>
base tree <statement-id>
```
