# KANGER 3.7.0.1 — Console-local `xplain` decisions

Status: **ACCEPTED DESIGN DECISION / DOCUMENTATION ONLY**

Reference runtime: accepted `release/3.5.2`.

No runtime behavior is changed by this document.

## 1. Classification

`xplain` is not part of the canonical semantic command taxonomy of KANGER.

It is a Console-local diagnostic utility for inspection and offline analysis of the explanation/analyzer log.

The Browser/UI does not need an `xplain` command because the inference/runtime log is already presented continuously in the dedicated lower LOG / RESULTS panel.

## 2. Accepted Console syntax

```text
xplain
xplain <file>
xplain mode on
xplain mode off
```

Semantics:

```text
xplain
```

shows the currently accumulated explanation/analyzer log in the Console.

```text
xplain <file>
```

writes the currently accumulated explanation/analyzer log to `<file>` for offline inspection.

```text
xplain mode on
xplain mode off
```

turn continuous runtime display of the explanation/analyzer log on or off for the Console session.

## 3. Why `mode` is explicit

Bare `xplain on` / `xplain off` is deliberately not canonical.

The second positional argument without a selector is reserved for the common and concise file-write form:

```text
xplain analyzer.log
```

Therefore `mode` carries real disambiguating meaning:

```text
xplain mode on
xplain mode off
```

## 4. Removed historical option indirection

The historical Console exposed runtime log visibility through a general workspace option such as:

```text
options log yes|no
```

The accepted model moves that concern under the diagnostic family itself:

```text
xplain mode on|off
```

This is a Console presentation/debug concern, not a logical `Mind` option and not query semantics.

## 5. Browser/UI boundary

No Browser/UI command equivalent is required:

```text
Console
    xplain
    xplain <file>
    xplain mode on|off

Browser/UI
    LOG / RESULTS panel
```

The lower UI panel is the normal interactive projection of the same diagnostic information. Any future UI export/download affordance, if desired, is a UI transport action and must not force `xplain` into the canonical semantic command registry.

## 6. Design principle

Keep diagnostics where they belong:

- semantic commands address KANGER concepts and operator actions;
- `xplain` is a Console diagnostic utility;
- presentation toggles must not become Core logical state;
- UI visibility of the runtime log does not require a command-language duplicate.
