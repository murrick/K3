# KANGER 3.7.0.1 — accepted `function` command family

Status: ACCEPTED DESIGN DECISION / DOCUMENTATION ONLY

Reference runtime: `release/3.5.2` at `9c8b7dd2c9ef347cea6af6a6faef9cfa48030306`

## Canonical family

The canonical operator-facing function family is intentionally minimal:

```text
functions
function <id>
function source <id>
```

## Semantics

- `functions` — show the list of defined user functions;
- `function <id>` — show one function by runtime id;
- `function source <id>` — show the source of one function by runtime id.

`functions` and `function ...` belong to the same command family and dispatcher. The singular/plural form follows operator context: plural for the collection projection, singular for one selected object or one object's source. This preserves the established human-facing Console convention without introducing separate semantic command identities.

## Explicit omissions

The following forms are intentionally not part of the canonical grammar:

```text
function
function show <id>
function source
function all
```

Rationale:

- the collection form is explicitly `functions`, preserving the natural list/object distinction;
- `show` adds no useful information because a bare numeric argument in this tiny command family has only one meaning;
- bulk source display is unnecessary operator surface and would encourage large, noisy output;
- `all` is redundant because `functions` already means the complete collection projection.

## Grammar note

This family is a deliberate exception to the more explicit `rule show <id>` form.

`rule` has several peer selectors/actions in the same grammar position (`all`, `produced`, `level`, `show`, `tree`, `comment`), therefore explicit `show` improves determinism and readability there.

The function family has only one reserved selector after singular `function`: `source`. The remaining second-token form is unambiguously the function id:

```text
functions
function [<id> | source <id>]
```

The dispatcher can therefore stay simple and deterministic without introducing an otherwise redundant `show` keyword.

## Implementation principle

Prefer the smallest operator syntax that is still unambiguous. Do not introduce symmetry words merely to make unrelated command families look structurally identical.

Singular/plural spelling may express collection-vs-object context while still resolving to one command family and one implementation path.
