## 1. Purpose

The accepted command architecture requires one grammar authority for operator language regardless of client surface.

Before this artifact the historical Browser still interpreted raw input itself and selected legacy `command` or `query` transports. 3.7.0.4 removes that authority from the active Browser execution boundary:

```text
operator input
    -> exact raw line
    -> Browser context=dialogue
    -> qualified Browser operation/error/containment boundaries
    -> Server CanonicalCommandIngressReactor
    -> shared kanger-command CommandParser
    -> canonical intent or Core-language path
```

The Browser is now an editor and transport client. It does not determine command meaning.

## 2. Browser authority chain

The convergence deliberately preserves the already-qualified Browser security and state boundaries:

```text
trusted rendering
    -> operation generation / snapshot barrier
    -> workspace projection
    -> error boundary
    -> raw dialogue adapter
    -> opaque child transport
    -> parent containment broker
    -> Server
```

The parent remains the sole owner of the bearer token and network access. The console iframe remains an opaque sandbox with exactly:

```html
sandbox="allow-scripts"
```

`allow-same-origin` remains forbidden. Direct child networking remains disabled.

## 3. One raw operator transport

`html/dialogue.js` installs the active Browser operator boundary after the existing Browser error boundary has been established.

It replaces the historical global operator entry points with one implementation:

```javascript
window.command = dispatch;
window.query = dispatch;
```

Every initialized-editor operator line is sent as:

```text
context = dialogue
parameters.token = child session sentinel
parameters.line = exact raw operator text
```

The adapter intentionally contains no command tokenization, keyword normalization, abbreviation resolution or intent switch.

In particular, it does not use a command-language `split`, `toLowerCase`, or `switch` table. Mixed case, quoted arguments, spacing and ambiguous prefixes are transported unchanged for the shared Server parser to decide.

Core language and ordinary commands therefore enter the Browser transport identically. A line such as:

```text
?father(John,Tom);
```

and an ordinary command such as:

```text
r a
```

use the same raw Browser envelope. Their semantic separation happens only after `CommandParser` runs on the Server.

## 4. Operation serialization without client parsing

The Browser operation protocol treats every `context=dialogue` request conservatively as one serialized operation.

This is intentional. The Browser does not inspect the raw line to decide whether an intent is read-only or mutating. Doing so would reintroduce a second command parser or a shadow command taxonomy in JavaScript.

The existing generation/snapshot model therefore remains authoritative:

```text
one raw dialogue operation in flight
    -> generation transition
    -> stale response rejection
    -> six-part semantic snapshot staging
    -> coherent snapshot commit
```

The stronger operation qualification drives an actual raw dialogue packet through this barrier and verifies stale-snapshot rejection and coherent publication.

## 5. Parent containment and bearer injection

`html/containment.js` now admits the `dialogue` request context.

The security model is otherwise unchanged:

1. the opaque child sends a serializable packet without possessing the real bearer;
2. the parent broker validates the child source/origin/session generation;
3. the child-supplied token field is removed;
4. the currently authoritative parent bearer is inserted;
5. the normalized packet is sent to the Server;
6. the response returns through the same generation-bound bridge.

The Browser dialogue adapter therefore cannot bypass the parent session authority simply because the operator transport changed shape.

## 6. Typed `quit` and session ownership

Canonical typed `quit` creates a special lifecycle boundary: the Server invalidates the authenticated user session, while the Browser parent still owns the corresponding bearer record.

The Browser does not solve this by parsing the word `quit`.

Instead, after a successful canonical `QUIT`, `CanonicalCommandIngressReactor` adds transport-level response metadata:

```json
{
  "session": {
    "schema": 1,
    "state": "closed"
  }
}
```

The parent containment broker reacts to that structured Server result. It first delivers the operation result to the child, then clears only the matching parent session generation and reloads the owner shell.

Thus session cleanup is driven by authoritative execution outcome, not command spelling.

The pre-existing parent-owned logout button/session message path remains valid independently of typed command dialogue.

## 7. Historical empty-history bootstrap

The historical Browser welcome path invokes three generic command calls before CodeMirror creates `window.editor`:

```text
help
use
get
```

Only `help` remains canonical Browser dialogue. Historical bare `use` and `get` were presentation-era list requests and must not become compatibility aliases in the canonical command language.

To avoid editing the large historical page in this convergence slice, `dialogue.js` isolates this startup sequence structurally:

- the first pre-editor generic call is transported normally (`help`);
- the next two pre-editor generic calls are completed locally as no-op bootstrap calls;
- their command text is never read, translated or mapped;
- after the editor exists, every operator call is transported raw.

This bridge is migration glue for the old welcome chain, not a second grammar and not accepted command vocabulary.

## 11. Compatibility boundary

3.7.0.4 closes the **active raw Browser operator grammar boundary**, not every historical Browser implementation detail.

The large historical `console.html` command parser remains physically present as dormant source. After `dialogue.js` installs, its global `command`/`query` operator entry points are replaced by the raw dialogue adapter. Removing the dormant parser is separate source-hygiene work.

Legacy structured JSON requests also remain in Browser rendering/workspace helpers for panel refreshes, history, login/session probes and other already-qualified transport duties. These requests do not interpret raw operator command language and therefore are not a competing grammar authority.

The historical visual layout, panels and menu structure are also intentionally unchanged in this artifact.

## 12. Resulting command architecture

After 3.7.0.4 the active operator-language topology is:

```text
Java Console ---------+
                      |
Browser raw dialogue -+--> shared kanger-command --> canonical intent
                      |             |
Server raw clients ---+             +--> Core ! ? + - = path
```

The Browser can now be redesigned without inventing another command processor. Click-to-compose UI can insert ordinary canonical command text into the editor, and execution can use exactly the same raw dialogue transport as typed input.
