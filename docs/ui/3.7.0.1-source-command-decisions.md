# KANGER 3.7.0.1 — Source command and UI transport decisions

Status: **ACCEPTED DESIGN DECISION / DOCUMENTATION ONLY**

Reference runtime: accepted `release/3.5.2`.

No runtime behavior is changed by this document.

## 1. Scope

This decision closes the source-file command surface for the 3.7.0.1 UI / command-language baseline.

The word `source` is **not** introduced as a canonical command namespace merely for structural symmetry. Historical KANGER interaction already has clear source operations, and they remain self-identifying top-level commands.

## 2. Accepted command-language surface

The complete canonical source command-language surface is:

```text
get
put
delete
```

With source arguments where required by the concrete operation:

```text
get <source>
put <source>
delete <source>
```

No canonical `source get`, `source put`, or `source delete` wrapper is required.

The general `WHERE -> WHAT TO DO -> WITH WHAT` design principle remains valid where a real semantic family is needed to disambiguate or express ownership. It must not be applied mechanically when the operation word is already unambiguous.

## 3. UI Source menu

The Browser/UI exposes one minimal menu named `Source`:

```text
Source
    Get
    Put
    Delete
    Upload
    Download
```

The menu label is a presentation grouping, not a command-language namespace.

## 4. Command operations versus Browser transport

The boundary is explicit:

```text
COMMAND LANGUAGE
    get
    put
    delete

UI MENU "Source"
    get
    put
    delete
    upload
    download
```

`get`, `put`, and `delete` are KANGER source lifecycle operations over the user's server-side source repository/workspace contract.

`upload` and `download` are Browser/UI transport actions between the user's local computer and the server-side user source directory.

Therefore:

- `upload` is not a KANGER command;
- `download` is not a KANGER command;
- neither belongs in Console command grammar;
- neither participates in the canonical command prefix table;
- their UI placement under the same `Source` menu is intentional and does not imply shared command semantics.

## 5. Console follow-up

Historical Console already has `get` and `put`; `delete` is absent there.

The later Console flash-back/convergence TODO must add the accepted `delete` source operation and bring Console parsing onto the common canonical keyword / minimum-unique-prefix model.

This is deferred implementation work and must not interrupt the current 3.7.0.1 UI design pass.

## 6. Historical `put` overload

Historical Console `put <numeric-rule-id>` comment editing is not retained as source semantics.

Rule comments already have the accepted explicit family:

```text
rule comment <id>
```

Therefore `put` remains unambiguously a source operation independent of whether the source name looks numeric.

## 7. Completeness statement

For 3.7.0.1, the source functionality is considered complete at this level:

```text
COMMAND LANGUAGE
    get
    put
    delete

UI MENU "Source"
    get
    put
    delete
    upload
    download
```

No additional source commands or Browser transport verbs are required by the accepted baseline.
