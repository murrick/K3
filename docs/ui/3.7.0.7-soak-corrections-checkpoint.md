## Corrections

### COMMAND-GRAMMAR-01 — fixed

The RULE family now has the plural collection spelling:

```text
rules
```

with canonical semantics:

```text
rules == rule all
```

`rule` remains current rule context. `rules <arg>` is rejected as misuse of the collection form. Unique-prefix resolution remains registry-owned.

Regression coverage includes parse intent and canonical formatting.

### HELP-COMPOSE-UX-02 — fixed

Help still displays complete registry-derived syntax, but parameterized rows compose only the fixed executable prefix up to the first metavariable, e.g.:

```text
rule <id>                 -> rule 
rule tree <id>            -> rule tree 
base predicate <id|name>  -> base predicate 
storage drop <name>       -> storage drop 
when accept <index>        -> when accept 
```

Finished commands remain unchanged and clicking Help never executes the command.

Browser still does not parse or normalize operator command language; compose is presentation derived from Server-supplied syntax metadata.

### SOLUTIONS-TREE-UX-03 — fixed

The visible Solution tree action is now icon-only:

```text
○
```

The semantic label remains available through title/ARIA metadata and compose behavior remains `solution tree <id>`.

### EDITOR-COMPILE-EOF-02 — fixed at the source/compiler boundary

The Browser no longer appends a synthetic EOL to the source payload.

A new Server-owned exact source-document snapshot separates document identity from `Mind.getSourceCode()`, which is a semantic reconstruction and is not byte-preserving.

Boundary now is:

```text
Browser editor bytes
        |
        v
exact Server source document
        |
        +---- source response / workspace bytes / put repository bytes
        |
        v
compiler-only copy
        |
        +---- append one terminal EOL only when compiler compatibility needs it
```

The compiler-normalized copy is never republished as the source document.

Exact source-document state is invalidated after direct Core mutation, erase or session closure and then falls back to semantic reconstruction until another source document is successfully compiled/loaded.

Integration regression proves all of the following with a source whose last statement has no final EOL:

- Compile succeeds;
- final statement participates in inference;
- Server `source` response equals the original string exactly;
- projected UTF-8 byte count equals the original bytes;
- `put` writes byte-identical repository contents.

### DESTRUCTIVE-CONFIRM-UI-04 — fixed

The Browser no longer depends on `window.confirm`, which is not a usable authority in the deployed opaque sandbox.

When and only when Server returns canonical `confirmation_required`, Browser renders its own DOM confirmation overlay. Accept resubmits the exact original raw canonical line with only:

```text
confirmed=true
```

Cancel performs no Server mutation and records `Cancelled` locally.

The Browser still does not decide which commands are destructive.

### PUT-OVERWRITE-CONFIRM-05 — fixed

The Server overwrite guard now checks the canonical `.k` repository identity even when the operator supplies a logical source name without the extension.

Required semantics are preserved:

```text
put <new>       -> immediate
put <existing>  -> confirmation_required
```

A real temporary-user regression test proves that an existing `victim.k` is detected by `put victim` and cannot reach runtime before explicit confirmation.

### TRANSACTION-PROJECTION-06 — fixed

Canonical Browser dialogue now refreshes `showTransactionLevel(data)` independently of whether a canonical presentation fragment was supplied to legacy logging.

Server transaction execution is unchanged; only the stale upper projection boundary is repaired.

### SPLITTER-GEOMETRY-07 — fixed

The late Browser correction adapter captures the legacy left splitter before its old inline handler and makes the CSS grid custom property the single runtime geometry authority:

```text
--kanger-left
```

The existing `sx` cookie remains persistence storage, but no competing inline left-container width is applied during drag.
