## Why 3.7.0.6 exists

The first live VPS development soak of 3.7.0.5 exposed integration defects that the component and browser qualification suites had not reproduced. The defects crossed parser, command ingress, Browser presentation/projection, editor transport, and destructive-operation UX boundaries.

## Architectural decisions fixed by this artifact

### One canonical command surface

Java Console and Browser use the same canonical command parser/processor. Browser UI is an additional visual projection and compose surface, not a reduced alternate language.

The Browser must therefore accept and present the canonical command families, including:

```text
rules
functions
base
values
solutions
when
transaction
```

where the semantic panels remain additional visualizations of the same authoritative state.

### Parser owns syntax before semantic interpretation

A doubled Core statement operator such as:

```text
!!a(x);
```

is invalid syntax and must be rejected at the shared parser boundary before Core semantic interpretation. It must never be reinterpreted as a negative statement/rule form (for example `!~a(x)`) and must never introduce `?a(x)` into inference state.

### Destructive confirmation policy

Explicit confirmation is required for operations that destroy or overwrite persistent/external user state:

```text
erase
delete <source>
storage drop <name>
put <source>       only when the source already exists and will be overwritten
```

The following intentional context/storage-control operations remain immediate and must **not** ask for confirmation:

```text
transaction rollback
storage reindex
```

Bare `delete` is not destructive. It is a read-only list form used to select a source for deletion.

### Browser projections must follow authoritative state

A failed/rejected operation must not leave stale semantic rows in active Browser projections. In particular, a rejected `get` may report its error, but statements from the rejected source must not remain in the Statements/Base panel.

Panel visibility after coherent snapshot publication is derived from committed semantic projection state, not from the incidental JSON shape of the command response.

### Editor EOF is data, not a missing line

Compile transport must preserve the final source line even when the editor buffer does not end in CR/LF. Transport normalization may add an EOL to the transmitted copy but must not mutate the editor buffer.

## Soak findings addressed

1. `values` / `solutions` result panes disappeared immediately after a query in Browser while Console remained correct.
2. `!!eating(Cat, Mouse);` was accepted and semantically reinterpreted instead of rejected as malformed syntax.
3. Browser editor compile dropped the last line when the source did not end with CR/LF.
4. Rejected `get` left ghost statements in the left semantic panel although the authoritative Mind was clean.
5. Browser `erase` executed without an explicit confirmation step.
6. HELP command syntax was passive text instead of a compose affordance.
7. Browser command presentation diverged from Console for `rules`, `functions`, `base`, `values`, `solutions`, `when`, and `transaction`.
8. Bare `delete` lacked a safe list/select flow; named delete needed confirmation.
9. Solution `tree` action lacked the presentation marker used by peer actions.
10. Right-side row actions drifted/wrapped when panels became narrow.
11. The input prompt colon was vertically misaligned.
12. Console/Browser confirmation policy required convergence, while `transaction rollback` and `storage reindex` remain intentionally immediate.

## Implementation summary

The correction artifact changes only the necessary parser, command, Console, Server ingress/runtime, Browser dialogue/editor/presentation boundaries and adds regression coverage around those boundaries.

Key properties:

- shared parser rejects doubled Core statement prefixes before execution;
- server response carries canonical command intent/presentation metadata;
- Browser renders server-supplied command results instead of maintaining a second parser/dispatcher;
- HELP is registry-derived and Browser syntax rows compose into the input without auto-execution;
- named destructive requests use a server-guided confirmation contract;
- bare `delete` is a read-only source listing;
- coherent semantic projection controls result/solution/hypothesis visibility;
- inactive/deleted statement residue is pruned from active Browser Base projection;
- compile transport normalizes EOF without modifying editor contents;
- narrow-row action geometry is stable and input prompt alignment is corrected.
