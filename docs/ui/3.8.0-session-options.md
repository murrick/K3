# Session options

The current command surface restores `options` (`opt` is its unambiguous prefix).
This supersedes the earlier decision to retire the options family.

```
options
options help
options debug [yes|no]
options values [yes|no]
options log [yes|no]
options timezone [<zoneId>]
options optimize [yes|no]
options <optimization> [yes|no]
```

Without a value, a setting reports its current state. `options` shows all settings.
`options optimize no` selects the reference paths for all eight qualified
accelerations; `yes` enables all eight. A later individual switch overrides that
setting only, and the aggregate reports `mixed` when the settings differ.

| Optimization | Acceleration |
| --- | --- |
| versionedSolveSync | Reuse unchanged solve synchronization |
| residentBaseComparison | Compare resident arguments without repeated lookup |
| singleTValueLookup | Resolve a variable's current value with one lookup |
| resolvedCauseWeights | Reuse resolved argument IDs for cause weights |
| compactCauseWeights | Use compact primitive IDs for cause weights |
| candidateMembershipFilter | Filter rule candidates by argument membership |
| compactFindSnapshots | Use compact candidate snapshots |
| preserveTValueIndex | Retain an unchanged TValue index across release |

Changes apply immediately within the current User session, including child
transactions and subsequent storage switches. They do not alter other sessions
or the JVM properties. Existing `kanger.experiment.*` properties supply defaults
until an option is explicitly changed. Verification and profiling properties
remain developer instrumentation, outside the optimization group.

`options timezone Europe/Moscow` changes the session time zone. The historical
standalone `timezone` spelling remains accepted for compatibility and formats
canonically as `options timezone`.

`status` remains a separate read-only command. Memory and object status are
available through its existing projections.
