# TValue observer: стоимость отключённого подключения и диагностики

**Отключённое подключение имеет измеримую цену в ограниченном setter-тесте.** На опубликованном observer patch парная медиана добавочного времени составила 24,7 нс при 32 resident-значениях и 31,9 нс при 128. Allocation в чистом и отключённом режимах по медиане счётчика равен нулю. Следующий эксперимент — быстрый обход bridge при отсутствии observer, с сохранением проверок владения и отказов.

Это измерение точного patch `51b28d5de50822f47aca376664375efda380b7c3`, на native-базе `5d5f6aff271f1abf371fbde55d637744c53f0bc3`. Runtime, диагностические классы, production/defaults и Maven source roots не изменены. Ускорение вывода здесь не измеряется.

## Что измерено

Три режима запускаются в отдельных JVM: clean native; тот же generated hooked runtime без attachment; hooked runtime с `QualifiedJournalConsumer`. Все используют один standalone diagnostic jar; неактивное присутствие jar не подключает callbacks.

Два размера — 32 и 128 значений, по одному значению на переменную; изменяются первые восемь. Две term-идентичности различны. До измерения независимый native-контроль проверяет изменение payload и восстановление, canonical references и порядок. После каждого блока native-перечисление сверяется с обоими полными resident-представлениями и проверяется чистота читателей.

| Нагрузка | Измеренная работа | Проверка вне таймера |
| --- | --- | --- |
| `setter` | 8192 вызова `setValue` на блок, чередование payload; volatile sink читает фактическое значение каждого setter | Для attached — новая сессия и baseline до таймера, observe/finish после; полный контроль, callback count и идентичность повторных трасс |
| `export` | 16 циклов на блок; цикл выполняет 16 setter-вызовов. В attached внутрь таймера входят open, baseline, оба наблюдения изменений и восстановлений, полный finish и release владельца | Native-контроль итогового состояния, сравнение представительной трассы, проверка отсутствия attachment |

Таким образом, `export` в attached измеряет весь диагностический сервис; чистый/отключённый режимы выполняют ту же native-работу. Время полного сервиса включает обязательные проверки обоих журналов, свежий полный oracle и создание immutable trace. Внутренние фазовые таймеры журналов выключены во всех запусках.

Каждая JVM прогревает 16 блоков и измеряет 32 блока каждой нагрузки. Allocation измеряется поддерживаемым `ThreadMXBean` для текущего потока. Создание CSV-строк и запись файлов выполняются вне таймеров. Volatile sink предотвращает исчезновение всей работы, но также входит в цену setter-теста; полученные отношения относятся к этому конкретному микросценарию.

## Результаты

Числа ниже — медианы шести JVM-медиан при флагах `on`. Отношения и добавочное время вычислены сначала внутри каждой пары повторения. Все шесть перестановок порядка трёх режимов использованы по одному разу для каждого размера. Полные диапазоны и первая/вторая половина каждой JVM записаны в [per-JVM-medians.csv](tvalue-observer-cost/per-JVM-medians.csv) и [aggregated-medians.csv](tvalue-observer-cost/aggregated-medians.csv).

| Значений | Чистый setter, нс | Hooks без observer, нс | Attached setter, нс | Парное добавочное время отключённых hooks, нс | Парное отношение disabled/clean |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 32 | 20,24 | 48,30 | 1647,69 | 24,68 | 2,23 |
| 128 | 12,88 | 45,27 | 1748,35 | 31,88 | 3,60 |

Attached callback выделяет примерно 1739/1763 байта на setter для размеров 32/128. Оба журнала записывают каждое metadata-событие: этот поток событий и сопутствующие структуры входят в allocation. Чистый и отключённый режимы имеют нулевые медианы allocation в обоих сценариях. Это показание счётчика для данной JVM/JIT, а не универсальная гарантия отсутствия выделений при любых условиях.

| Значений | Native-цикл, мкс | Цикл с отключёнными hooks, мкс | Полный checked export, мс | Allocation checked export, байт |
| ---: | ---: | ---: | ---: | ---: |
| 32 | 0,261 | 0,560 | 0,870 | 783944 |
| 128 | 0,213 | 0,522 | 2,505 | 2671760 |

Полный checked export ожидаемо дороже одних native-записей: он выполняет дополнительные полные чтения, проверки и сериализацию. Эти отношения не являются замером end-to-end inference overhead.

Среда: OpenJDK 17.0.20, ECJ 3.33, Linux x86_64, Xeon Platinum 8573C, общий контейнер без CPU pinning и гарантии эксклюзивного хоста. Между JVM есть разброс: парное отношение disabled/clean для setter менялось от 1,60 до 5,47 при 32 значениях и от 2,53 до 6,79 при 128. Результат описывает локальный эксперимент; статистическая значимость и переносимость на другую среду не заявлены.

## Проверки и воспроизведение

Финальная серия — 48 JVM: 36 основных timing-запусков и 12 запусков с `off`/`verify` для проверки семантической устойчивости. Последние дают только по одному повторению на ячейку и не включены в итоговые timing-медианы. Всего 3072 измеренных блока. Два пилота исключены из финальной серии: первый выявил удержание строк событий в длинной сессии; второй проверил ограниченную сессию на блок.

Native-контроли совпадают побайтно между режимами, повторениями и флагами. Все 32 представительные checked traces повторно проиграны; проверены baseline/delta/full authority, 8192 setter-callbacks и 16 term-переходов на export-трассу. Attached setter-трасса фиксирует чередование payload каждого события, даже когда к моменту наблюдения итоговое состояние восстановлено. Журналы сохраняют свои полные проверки в каждом finish.

Build/analyze сверяют source/class/jar hashes всего предыдущего observer patch и нового драйвера. Native production sources, runtime bridge и диагностические реализации остаются неизменными. [summary.json](tvalue-observer-cost/summary.json), [build-validation.json](tvalue-observer-cost/build-validation.json), [environment.json](tvalue-observer-cost/environment.json) и [manifest.json](tvalue-observer-cost/manifest.json) фиксируют исходники, команды и доказательства.

Из корня репозитория, с prerequisite checkout/tooling из диагностического README:

```bash
# Требуется только если предыдущие observer build outputs ещё не созданы.
python kanger-qualification/diagnostics/build_observer.py
python docs/tvalue-observer-cost/build.py
python docs/tvalue-observer-cost/run.py
python docs/tvalue-observer-cost/analyze.py
python docs/tvalue-observer-cost/manifest.py
```

Новый драйвер находится в `kanger-qualification/diagnostics/test`; он компилируется отдельным cost build. Старые evidence и normal Maven test source set не меняются.

## Следующий шаг и границы

Для следующей экспериментальной ветки предлагается проверить быстрый disabled-path: явная проверка отсутствующего attachment до создания callback lambda и входа в synchronized dispatch. Для безопасной видимости attachment потребуется сохранить согласованный контракт публикации/снятия подключения, например через volatile-ссылку. Причинный вклад monitor, lambda и дополнительных getter-вызовов пока не разделён измерением; сейчас это инженерная гипотеза по коду и общему результату.

Новый patch должен повторить NO_INSTRUMENTATION, exclusive owner, foreign-thread taint, observer failure и native parity, затем пройти тот же cost-тест рядом с текущим bridge. Парный полный oracle остаётся включённым. Production-интеграция, полная SMART persistence, весь inference corpus, concurrent native sessions и исправление recycled ID после root clear по-прежнему не квалифицированы.
