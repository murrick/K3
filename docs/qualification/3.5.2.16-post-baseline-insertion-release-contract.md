## Accepted lifecycle contract

The supported storage-baseline insertion remains:

```text
offline workspace L0
        -> use database
workspace overlay L1
persistent database L0
```

The workspace is recompiled in the database context so canonical identities, generated consequences and contradiction checks are rebuilt against the persistent baseline. It remains provisional until explicit commit; rollback leaves the database unchanged.

Opening a database while an ordinary L1+ transaction stack is active is deliberately rejected with `ACTIVE_TRANSACTION / TRANSACTION_RESOLUTION_REQUIRED`. Generalized multi-level rebase is not part of 3.5.2.

Storage lifecycle quiescence requires both visible transaction level zero and no pending root child reservations. This applies to `use`, `checkpoint` and `close`.
