## Confirmed lifecycle behavior

The VPS soak confirms the integrated `3.5.2` contract in real deployment conditions:

- nested transactions resolve without DUMB topology corruption;
- explicit close/reopen preserves durable state exactly once;
- offline L0 workspace insertion over a DB baseline produces provisional L1;
- rollback discards the inserted workspace and commit persists it once;
- opening a database under an ordinary L1+ transaction stack is rejected before storage acquisition and leaves the stack unchanged;
- clean restart preserves committed state;
- SIGKILL recovery preserves committed L0 while uncommitted child state does not survive;
- source lifecycle remains coherent;
- `get <source>` over an open database correctly creates provisional L1;
- failed storage switch, reindex and dropping a different database preserve confirmed active storage identity;
- Browser reload preserves a live server-side session;
- transport loss is distinguished from session invalidity and the same live session resumes after transport recovery;
- Browser containment keeps the bearer parent-owned and the child sandbox remains `allow-scripts` without `allow-same-origin`;
- ordinary semantic/runtime execution remains functional after the lifecycle work.
