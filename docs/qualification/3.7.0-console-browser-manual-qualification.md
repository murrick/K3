# KANGER 3.7.0 — Console / Browser Manual Qualification

## Purpose

This document is the permanent manual qualification runbook for semantic behavior shared by the standalone Java Console and the Browser UI.

The runbook is intentionally client-paired: one semantic vector is executed through both clients wherever the vector is applicable. The purpose is to detect semantic divergence, lost diagnostics, and Browser presentation loss without treating harmless formatting differences as defects.

This document is a test plan. A blank result cell is **not** evidence of PASS.

## Result vocabulary

Use only:

- `PASS` — required semantics are preserved.
- `DEFECT` — required semantics are violated.
- `NA` — vector is not applicable to that client/lane.
- `BLOCKED` — vector could not be executed; record the reason.

Always distinguish:

1. **machine/semantic contract** — state, typed error/recovery data, operation outcome, tree nodes, transaction/storage behavior;
2. **presentation** — human-readable rendering, indentation, wording, labels;
3. **transport** — HTTP status/envelope when Browser Network evidence is relevant.

Exact human-readable wording is not a machine contract unless a separate contract explicitly says so.

```text

```

After drop, inspect the physical DB storage area appropriate to the client/runtime.

Required:

- storage artifacts are gone;
- empty physical parents corresponding to `zz/error` are pruned;
- user DB root remains present.

### Part B — sibling preservation

Create both logical storages:

```text
storage use zz.error.smoke
```

Drop only `zz.error.smoke`.

Required:

- `zz.error.keep` remains intact and usable;
- shared physical parent directories remain while needed by the sibling.

Then drop `zz.error.keep`.

- now-empty nested physical parents are pruned;

## Closure criteria

This manual qualification is complete only when:

1. every applicable vector has an explicit `PASS`, `DEFECT`, or `BLOCKED` result;
2. all cleanup steps are recorded;
3. Console and Browser divergences are classified as semantic, presentation-only, or transport-only;

5. exact executable/deployed provenance is recorded.

Completion of this runbook does **not** authorize or imply merge, release, tag, deploy, production cutover, or release acceptance. Those remain separate explicit decisions.
