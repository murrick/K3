## Closed architectural gap

The explicit storage lifecycle is no longer a server-owned specialization.

- `IUser` exposes the normative `use`, `checkpoint` and `close` operations;
- ordinary Core `User` owns every lifecycle precondition and physical transition;
- server sessions instantiate ordinary `User`;
- `ExplicitLifecycleUser` was removed;
- server-only `StorageCheckpoint` was removed;
- `ExplicitStorageLifecycleReactor` only protects earliest protocol ordering and translates typed Core exceptions.

Transaction lifecycle and physical storage lifecycle are independent state machines:

```text
commit never closes storage
use requires CLOSED
close requires transaction level 0
checkpoint requires OPEN at transaction level 0
```

## Durable checkpoint

`User.checkpoint(IMind)` is a public Core operation. It intentionally commits an empty child into the root to reuse the existing qualified publication sequence:

```text
pack → update → flush
```

It does not compact or close physical storage, detach storage-bound context, or clear runtime state.

Level-zero `close` performs this checkpoint first and then follows the normal physical close/compaction and cleanup path.

## Typed lifecycle protocol

Core reasons are represented by `StorageLifecycleException` and `StorageLifecycleErrorCode`:

```text
STORAGE_ALREADY_OPEN
  required_action = EXPLICIT_CLOSE_REQUIRED

ACTIVE_TRANSACTION
  required_action = TRANSACTION_RESOLUTION_REQUIRED

NO_STORAGE_OPEN
```

The server and Console publish typed lifecycle failures without parsing exception text.

Transaction responses are stable:

```text
Transaction committed
Transaction rejected
Transaction rolled back
Storage checkpoint completed
```

Analyzer output is optional `details` and cannot replace the transaction result.

## Console lifecycle binding

The Core contract is now bound explicitly into the interactive Console:

- level-zero `transaction commit` checkpoints an open storage and keeps it open;
- level-zero `transaction commit` with no open storage is an idempotent Console no-op;
- low-level `IUser.checkpoint` remains strict and returns `NO_STORAGE_OPEN` when called without storage;
- repeated `use` exposes `STORAGE_ALREADY_OPEN / EXPLICIT_CLOSE_REQUIRED`;
- `close` during an active transaction exposes `ACTIVE_TRANSACTION / TRANSACTION_RESOLUTION_REQUIRED`;
- the former Console force-close path is removed;
- database brief output separates root logical state from the chain-shared runtime canonical cache;
- predicate listings use Mind-aware semantic rendering rather than `Object.toString()`;
- unsupported DUMB aggregate counters are reported as `N/A`, never false zero values.
