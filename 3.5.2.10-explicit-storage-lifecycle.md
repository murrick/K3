## Normative invariant

> Transaction lifecycle and physical storage lifecycle do not perform implicit transitions into one another.

Allowed transitions:

```text
CLOSED
    -- use -->
OPEN, level 0

OPEN, level N
    -- commit / rollback -->
OPEN, level N-1

OPEN, level 0
    -- commit -->
OPEN, level 0 + durable checkpoint

OPEN, level 0
    -- close -->
CLOSED
```

Forbidden transitions:

```text
commit → implicit close
OPEN → use the same database
OPEN → use another database
OPEN, level > 0 → close
```

## Fix A — commit never closes storage

- `commit` at level greater than one transfers the child delta to its parent and decrements the level.
- `commit` at level one transfers the child delta to root, reaches level zero, performs the existing durable root checkpoint and leaves storage open.
- `commit` at level zero performs a repeatable durable checkpoint and leaves storage plus runtime context open.
- `commit` does not compact the integrity manifest, close Index/Data, clear storage context or invoke close.

## Fix B — use requires CLOSED

`use` rejects immediately whenever any database is already open, including the requested database itself. Rejection occurs before target canonicalization/open, integrity validation, protective probe transaction or active-context mutation.

The rejected operation preserves:

- active storage identity;
- active `Mind` identity;
- transaction level;
- source/runtime context;
- target storage bytes and metadata.

An explicit successful `close` is required before any later `use`.

## Fix C — close requires level zero

`close` rejects every active transaction level greater than zero. Rejection does not flush, checkpoint, compact, commit, roll back, clear context or close physical storage. The active transaction remains queryable and must be explicitly committed or rolled back.

At level zero, close performs the durable root checkpoint, closes physical storage through its normal compaction/close path, clears storage-bound runtime context and publishes no active storage.

## Regression matrix

### Commit

- root commit does not close storage;
- root commit performs a durable checkpoint;
- repeated root commit is safe;
- query and mutation remain available after root commit;
- level one to zero commit leaves storage open;
- nested commit reaches root without an implicit close.

### Use

- same-storage use while open is rejected;
- different-storage use while open is rejected;
- rejection does not open or validate the target;
- active storage, `Mind`, transaction level and source context are unchanged.

### Close

- level one close is rejected;
- level two-or-greater close is rejected;
- transient rules remain queryable after rejection;
- storage files and active context remain unchanged;
- commit/rollback remain available after rejection.

### Persistence

- commit → explicit close → reopen;
- rollback → explicit close → reopen;
- close → use same database;
- close → use another database;
- nested commit → explicit close → reopen;
- repeated close/reopen cycles;
- reopen integrity validation passes and committed rules remain available.
